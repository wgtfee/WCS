# 多协议工业通信架构

## 概述

本架构为 WCS 系统提供统一的 PLC/设备通信抽象层，支持以下工业协议，每种协议均使用行业标准开源库实现：

| 协议 | 用途 | 底层库 |
|------|------|--------|
| **Modbus TCP** | 通用 PLC、传感器、仪表 | [NModbus](https://www.nuget.org/packages/NModbus/) |
| **OPC UA** | 高端 PLC、跨平台数据交换 | [OPC Foundation 官方库](https://www.nuget.org/packages/OPCFoundation.NetStandard.Opc.Ua.Client/) |
| **EtherNet/IP** | Allen-Bradley / Rockwell PLC | Socket (生产环境推荐 [libplctag](https://www.nuget.org/packages/libplctag/)) |
| **MQTT** | 物联网设备、消息推送 | [MQTTnet](https://www.nuget.org/packages/MQTTnet/) |
| **S7 (Snap7)** | Siemens S7-300/400/1200/1500 | Snap7（标准 S7 协议，DB块+字节偏移） |
| **S7 (CommPlus)** | Siemens S7-1500 系列 | S7CommPlusDriver（扩展符号标签协议） |

## 架构设计

```

├── Abstractions/                    ← 统一接口 + 枚举 + 状态模型
│   ├── IPlcConnection.cs           ← 核心接口
│   ├── PlcProtocolType.cs          ← 协议枚举
│   └── PlcConnectionStatus.cs      ← 连接状态
├── PlcConnectionBase.cs             ← 抽象基类（状态管理 / 日志 / 计数器）
├── PlcConnectionFactory.cs          ← 工厂：根据配置创建对应协议实例
├── PlcRegistrationExtensions.cs     ← DI 注册扩展
│
├── Modbus/
│   └── ModbusConnection.cs          ← NModbus TCP
├── OpcUa/
│   └── OpcUaConnection.cs           ← OPC Foundation 客户端
├── Eip/
│   └── EipConnection.cs             ← TCP Socket（可用 libplctag 替代）
├── Mqtt/
│   └── MqttConnection.cs            ← MQTTnet 发布/订阅
└── S7/
    ├── S7Connection.cs              ← 模拟实现（向后兼容）
    ├── Snap7/                       ← Snap7 协议（标准 S7）
    │   └── Snap7PlcClient.cs        ←   标签式客户端（实现 IPlcClient）
    ├── S7CommPlus/                  ← S7 CommPlus 协议（符号标签）
    │   └── S7CommPlusPlcClient.cs   ←   标签式客户端（实现 IPlcClient，占位）

    └── S7PollingService.cs          ←   S7 轮询服务
```

### 核心接口 `IPlcConnection`

所有协议实现同一接口，可无缝替换：

```csharp
public interface IPlcConnection : IDisposable
{
    string Name { get; }                          // 连接名称
    PlcProtocolType ProtocolType { get; }         // 协议类型
    bool IsConnected { get; }                     // 是否已连接

    Task<bool> ConnectAsync(CancellationToken ct = default);
    Task<bool> DisconnectAsync(CancellationToken ct = default);
    Task<byte[]?> ReadAsync(string address, ushort length, CancellationToken ct = default);
    Task<bool> WriteAsync(string address, byte[] data, CancellationToken ct = default);
    PlcConnectionStatus GetStatus();
}
```

### 抽象基类 `PlcConnectionBase`

所有协议实现继承此类，自动获得：

- 连接状态机管理（`Connected` / `Failed` / `Disconnected`）
- 读写计数器 + 心跳时间戳
- 失败计数 + 错误日志
- 线程安全的状态快照

## 各协议使用说明

### 1. Modbus TCP（NModbus）

**配置**：
```csharp
var config = new ModbusConnectionConfig
{
    Name = "生产线PLC1",
    Host = "192.168.1.100",
    Port = 502,
    UnitId = 1,        // 从站地址
    TimeoutMs = 5000,
};
```

**地址格式**：
| 类型 | 格式 | 示例 |
|------|------|------|
| 保持寄存器 | `HR:{起始地址}` | `HR:0` 读取保持寄存器 0 |
| 输入寄存器 | `IR:{起始地址}` | `IR:0` 读取输入寄存器 0 |
| 线圈 | `COIL:{起始地址}` | `COIL:0` 写入线圈 0 |

**使用示例**：
```csharp
var conn = new ModbusConnection(config, logger);
await conn.ConnectAsync();

// 读取 10 个保持寄存器 (地址 HR:0)
var data = await conn.ReadAsync("HR:0", 10);
// 返回 byte[20] (10个ushort × 2字节，大端序)

// 写入 4 个保持寄存器 (地址 HR:100)
var writeData = new byte[] { 0x00, 0x64, 0x00, 0xC8 };
await conn.WriteAsync("HR:100", writeData);

await conn.DisconnectAsync();
```

### 2. OPC UA（OPC Foundation）

**配置**：
```csharp
var config = new OpcUaConnectionConfig
{
    Name = "OPCUAServer1",
    EndpointUrl = "opc.tcp://192.168.1.200:4840",
    UseSecurity = false,       // 测试环境可关闭安全
    TimeoutMs = 10000,
};
```

**地址格式**：使用 OPC UA 节点 ID 字符串，如 `ns=2;s=MyVariable`

**使用示例**：
```csharp
var conn = new OpcUaConnection(config, logger);
await conn.ConnectAsync();

// 读取节点值
var value = await conn.ReadAsync("ns=2;s=Temperature", 4);
// 返回 byte[]，自动将 int/float/bool 转为字节

// 写入节点值（默认按 int 写入）
await conn.WriteAsync("ns=2;s=SetSpeed", BitConverter.GetBytes(1500));

// 断开连接
await conn.DisconnectAsync();
```

> **注意**：OPC UA 支持更丰富的数据类型，`ReadAsync` 自动将 int/uint/short/
> float/double/bool/string 转为 `byte[]`，若需精确类型控制可直接访问 `Session` 属性。

### 3. EtherNet/IP（TCP Socket）

**配置**：
```csharp
var config = new EipConnectionConfig
{
    Name = "AB_PLC",
    Host = "192.168.1.50",
    Port = 44818,
    TimeoutMs = 5000,
};
```

> **生产建议**：当前实现基于 TCP Socket 进行基础 CIP 通信。
> 生产环境推荐使用 [libplctag](https://www.nuget.org/packages/libplctag/) 替代，
> 它原生支持 Allen-Bradley ControlLogix / CompactLogix 等主流 PLC 的标签读写。
>
> ```csharp
> // libplctag 示例（需安装原生运行时）
> using var tag = new Tag
> {
>     Name = "MyTag",
>     Gateway = "192.168.1.50",
>     Path = "1,0",
>     PlcType = PlcType.ControlLogix,
>     Protocol = Protocol.EIP,
>     Timeout = TimeSpan.FromSeconds(5),
> };
> ```

**使用示例**：
```csharp
var conn = new EipConnection(config, logger);
await conn.ConnectAsync();

// 读取标签数据
var data = await conn.ReadAsync("MyTag", 10);

await conn.DisconnectAsync();
```

### 4. MQTT（MQTTnet）

**配置**：
```csharp
var config = new MqttConnectionConfig
{
    Name = "MQTTBroker",
    Host = "mqtt.example.com",
    Port = 1883,
    Username = "wcs",
    Password = "wcs123",
    ClientId = $"WcsCore_{Guid.NewGuid():N}",  // 自动生成唯一客户端ID
    TimeoutMs = 5000,
};
```

**特点**：
- MQTT 是发布/订阅模型，`ReadAsync` 不支持直接读取
- 通过 `SubscribeAsync` + `OnMessageReceived` 事件接收消息
- 通过 `WriteAsync` 按主题发布消息

**使用示例**：
```csharp
var conn = new MqttConnection(config, logger);
await conn.ConnectAsync();

// 订阅主题
conn.OnMessageReceived += (topic, payload) =>
{
    Console.WriteLine($"收到 {topic}: {Encoding.UTF8.GetString(payload)}");
    return Task.CompletedTask;
};
await conn.SubscribeAsync("wcs/commands/#");

// 发布消息
await conn.WriteAsync("wcs/status",
    Encoding.UTF8.GetBytes("{\"status\":\"running\"}"));

// 断开连接
await conn.DisconnectAsync();
```

> **自动重连**：MQTT 连接意外断开时会自动等待 3 秒后重连。

### 5. 工厂模式创建连接

```csharp
[ApiController]
[Route("api/plc")]
public class PlcController : ControllerBase
{
    private readonly PlcConnectionFactory _factory;

    public PlcController(PlcConnectionFactory factory)
    {
        _factory = factory;
    }

    [HttpPost("connect")]
    public async Task<IActionResult> Connect([FromBody] ProtocolConnectionConfig config)
    {
        var conn = _factory.Create(config);
        var ok = await conn.ConnectAsync();
        return Ok(new { ok, status = conn.GetStatus() });
    }
}
```

## 扩展：添加新协议

1. 在 `PlcProtocolType` 枚举中添加新类型
2. 创建 `YourProtocol/YourProtocolConnection.cs` 继承 `PlcConnectionBase`
3. 在 `PlcConnectionFactory.Create()` 中添加创建分支
4. 在 `PlcRegistrationExtensions` 中注册到 DI
5. 在 `_routeMap` 的对应 `ProtocolConnectionConfig` 中添加配置

无需修改现有代码即可扩展新协议。

## 统一标签式读写系统（Label/Tag）

在 `IPlcConnection`（按地址读写字节）之上，新增了统一标签式读写抽象层，将 PLC 变量以**标签名**的形式暴露给业务代码。

### 架构

```
业务代码（使用 [PlcStruct] / [PlcTag] 特性）
         │
         ▼
  PlcTagSerializer          ← 协议无关：通过特性自动读写对象
         │                    [PlcStruct("DB1")] + [PlcTag("DB1.X")]
         ▼
  IPlcClient                ← 接口层：TagName → Value
    │            │
    ▼            ▼
Snap7PlcClient  S7CommPlusPlcClient   ← 两种 S7 协议实现
(标准 S7 协议)  (扩展 Plus 符号协议)
    │            │
    ▼            ▼
 ReadPool/     S7CommPlusDriver
 WritePool     客户端连接
(已有生产代码)  (待集成)
```

### 组件总览

| 组件 | 位置 | 说明 |
|------|------|------|
| `IPlcClient` | `Abstractions/` | 标签式读写接口（`ReadAsync`/`WriteAsync`/`ReadBatchAsync`/`WriteBatchAsync`） |
| `PlcTagRegistry` | `Label/` | 标签名→(DB,偏移,类型) 映射注册表 |
| `PlcTagSerializer` | `Label/` | 基于 `[PlcStruct]`/`[PlcTag]` 特性驱动，自动读写对象 |
| `Snap7PlcClient` | `S7/Snap7/` | Snap7 实现：通过 `ReadPool`/`WritePool` 通信，需预先注册偏移 |
| `S7CommPlusPlcClient` | `S7/S7CommPlus/` | S7CommPlus 实现：符号标签访问（占位，待集成） |

### 特性系统


### S7 协议选择

根据项目需要，通过 DI 注册选择具体协议：

```csharp
// Program.cs

// 1. 注册核心服务（协议无关）
services.AddWcsPlcCore();

// 2. 二选一：
//    方式 A：使用 Snap7（兼容 S7-300/400/1200/1500，需配偏移）
services.AddS7Snap7();

//    方式 B：使用 S7CommPlus（仅 S7-1500，符号标签，待集成）
// services.AddS7CommPlus();
```

两种 S7 协议的对比如下：

| 维度 | Snap7（标准） | S7CommPlus（扩展） |
|------|-------------|-------------------|
| 适用 PLC | S7-300/400/1200/1500 | S7-1500 系列 |
| 地址模型 | DB 块 + 字节/位偏移 | 符号地址（Area+SubArea+LIDs） |
| 标签映射 | 需预注册 `(DB,offset,type)` | 通过 Explore 协议自动解析 |
| 通信协议 | 标准 S7 ISO over TCP | S7-1500 Communication Plus |
| 加密 | 无 | 支持 TLS |
| 标签批量优化 | 手动（同 DB 块合并） | 原生 MultiVariables 请求 |

三个新的 PollingService 都加了可选的 SignalSnapshotCenter + EventDetector 注入，在 Program.cs 里用 sp.GetService<T>() 获取（存在就用，不存在就跳过）。

每次轮询读取后执行的链路：

快照更新 — 存到 SignalSnapshotCenter 的 Current/Previous（为 EventDetector 提供变化对比依据）
EventDetector — 边沿检测 → 通过 IEventBus 发业务事件
注意：EventDetector 内部依赖 FieldMetadataCache 用 FieldInfo 做字段比对。标签类用的是属性而非字段，如果 FieldMetadataCache 后续不扩展支持属性，EventDetector 对标签类的边沿检测会静默跳过（不报错）

写入器使用方式

var writer = new TagWriter(plcClient, db, logger);

// 自动识别特性，走对应的协议写入
await writer.WriteAsync(new TagControlCommand
{
    StartStation1 = true,
    SpeedSetpoint1 = 500
}, deviceId: "CV01", taskId: "TASK001");

// 也支持 Modbus 和 OPC UA 的模型
await writer.WriteAsync(new ModbusControlCommand { Start = true });
await writer.WriteAsync(new OpcUaControlCommand { Start = true});


现在完整的写入链路是这样的：


业务代码（TaskExecutionWorker / API / 其他）
  │
  ├─ Snap7（原有）
  │   └─ CommandCenter.SendStructuredCommandAsync(deviceId, type, cmd)
  │        └─ PlcWriter.WriteStructAsync(cmd)→ Serialize() → WritePool
  │
  └─ 标签协议（新）
      └─ CommandCenter.SendTagCommandAsync(deviceId, type, cmd)
           └─ TagWriter.WriteAsync(cmd)
                └─ ITagSerializer.WriteAsync(obj)
                     ├─ Snap7TagSerializer → PlcWriter（兼容原有）
                     ├─ PlcTagSerializer   → S7CommPlusPlcClient
                     ├─ ModbusTagSerializer → ModbusPlcClient
                     └─ OpcUaTagSerializer  → OpcUaPlcClient
用法：


// Snap7 命令（struct）
await cmdCenter.SendStructuredCommandAsync("CV01", "Start", new ConveyorControlCommand {
    StartStation1 = true
});

// 标签命令（class），自动识别协议
await cmdCenter.SendTagCommandAsync("CV01", "Start", new TagControlCommand {
    StartStation1 = true
});
SendTagCommandAsync 内部走 TagWriter → ITagSerializer，至于到底用哪个序列化器，取决于你在构造函数里传入了哪个 ITagSerializer：


// Program.cs 注册时指定协议
var tagWriter = new TagWriter(new PlcTagSerializer(s7plusClient), db, logger);
services.AddSingleton(tagWriter);


现在多个协议可以同时用了。CommandCenter 不再依赖单个 TagWriter，而是接收所有 ITagSerializer，根据命令的特性自动路由。


// 注册时：把所有序列化器都注册进去
services.AddSingleton<ITagSerializer>(sp => new PlcTagSerializer(sp.GetRequiredService<S7CommPlusPlcClient>()));
services.AddSingleton<ITagSerializer>(sp => new ModbusTagSerializer(sp.GetRequiredService<ModbusPlcClient>()));
services.AddSingleton<ITagSerializer>(sp => new OpcUaTagSerializer(sp.GetRequiredService<OpcUaPlcClient>()));
services.AddSingleton<ITagSerializer>(sp => new Snap7TagSerializer(sp.GetRequiredService<PlcWriter>()));

// CommandCenter 自动根据命令的特性路由：
await cmdCenter.SendTagCommandAsync("CV01", "Start", new TagControlCommand { ... });
//   ↑ 发现 [PlcStruct] → 用 PlcTagSerializer

await cmdCenter.SendTagCommandAsync("CV01", "Start", new ModbusControlCommand { ... });
//   ↑ 发现 [PlcModbusBlock] → 用 ModbusTagSerializer

await cmdCenter.SendTagCommandAsync("CV01", "Start", new OpcUaControlCommand { ... });
//   ↑ 发现 [PlcOpcUaBlock] → 用 OpcUaTagSerializer

await cmdCenter.SendTagCommandAsync("CV01", "Start", new ConveyorControlCommand { ... });
//   ↑ 发现 [PlcBlock] → 用 Snap7TagSerializer（走原有 PlcWriter）
所有协议统一走 SendTagCommandAsync，业务代码不需要关心底层用的是什么协议。


SendTagCommandAsync 不是自动触发的，它是 CommandCenter 上的一个方法，业务代码主动调用才会执行。

调用时机取决于谁调它：


何时触发？                谁调？              写入什么？
──────────              ──────              ─────────
任务流程需要发命令       TaskExecutionWorker   发输送启动命令给 PLC
操作员点击"启动"        API Controller        发手动控制命令
上位系统下发指令         MQTT/OPC UA 监听    转发到对应协议写入
PLC 状态变化后回写     EventDetector 业务事件  写确认/应答
当前的链路：


TaskExecutionWorker 执行任务逻辑
  → 判断需要给 PLC 发命令
  → new TagControlCommand { StartStation1 = true }
  → cmdCenter.SendTagCommandAsync("CV01", "StartConveyor", cmd)
       → 自动路由到 PlcTagSerializer → S7CommPlusPlcClient → PLC
不像轮询（TagPollingService 是 timer 自动跑的），写入永远是被业务逻辑触发的。如果你想让 EventDetector 检测到某些状态后自动写入，那也是业务代码在 EventHandler 里调 SendTagCommandAsync，不是自动的。
