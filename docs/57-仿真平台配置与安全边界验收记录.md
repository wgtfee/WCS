## 2. 配置结构

### 2.1 Simulation

```json
{
  "Simulator": {
    "Enabled": true,
    "TransportTps": 2
  },
  "SimulationGovernance": {
    "Enabled": true,
    "ScenarioDirectory": "data/simulation-scenarios",
    "MaximumScenarioBytes": 1048576,
    "MaximumEvidenceRecords": 10000,
    "AllowedEnvironments": [
      "Simulation",
      "SimulationLoadTest"
    ]
  }
}
```

### 2.2 SimulationLoadTest

与 Simulation 使用相同治理边界，但允许更大的 Evidence 上限，并提高模拟任务吞吐。该环境仍不允许真实 PLC 写入。

### 2.3 Production

```json
{
  "Simulator": {
    "Enabled": false
  }
}
```

`SimulationGovernanceOptions.Enabled` 的代码默认值为 false。Production 不配置允许环境；即使通过外部配置误开启，Production 仍被 `SimulationBoundaryGuard` 和 `SimulatorBackgroundService` 双重拒绝。

## 3. 参数说明

| 参数 | 默认值 | 约束 |
|---|---:|---|
| `SimulationGovernance.Enabled` | false | 必须显式开启 |
| `ScenarioDirectory` | `data/simulation-scenarios` | 不存放真实生产数据 |
| `MaximumScenarioBytes` | 1,048,576 | 1 byte～16 MB |
| `MaximumEvidenceRecords` | 10,000 | 1～1,000,000 |
| `AllowedEnvironments` | Simulation、SimulationLoadTest | 禁止 Production，必须唯一 |
| `Simulator.Enabled` | false | 与 Governance 双开关 |
| `Simulator.TransportTps` | 2 | S0 不用于容量结论 |

## 6. Evidence 验收

- [x] Evidence Records 数量有界；
- [x] Sequence 唯一；
- [x] 输入顺序不影响最终排序；
- [x] 相同规范化内容产生相同 EvidenceHash；
- [x] 结束时间早于开始时间拒绝；
- [x] Evidence 不写生产 SQL；
- [x] Evidence 不触发任何控制命令。

## 7. 控制隔离

S0 Governance 和 Controller 明确禁止：

```text
PLC Write
Device Stop
Task Cancel
Route Change
Reservation Release
Vehicle Selection
Dispatch
```

S0 Controller 的 `validate/register` 只在进程内 Registry 保存版本 Hash。Host 重启后 Registry 清空；持久化场景仓库属于 S1 后续范围，届时仍必须保持不可变版本和审计。

## 10. 回退

```text
SimulationGovernance__Enabled=false
Simulator__Enabled=false
```

关闭 Simulation Host 后，确认：

- 仿真 API 不可见；
- 模拟 PLC 服务停止；
- 无后台仿真线程；
- 无真实控制写入；
- 原 WCS 生产配置和数据库不受影响。
