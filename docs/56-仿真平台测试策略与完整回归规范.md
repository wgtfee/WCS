# 仿真平台测试策略与完整回归规范

## 1. 范围

本文定义 WCS Simulation & Verification v1.0 从 S0 到 S10 的统一测试规则。任何仿真阶段不得只验证新增代码，必须证明既有调度、PLC、Telemetry、异常、健康、维修和 Forecast 没有回归。

## 2. 统一交付循环

```text
功能开发
→ 阶段契约测试
→ 阶段专项 E2E
→ 当前完整历史回归
→ 文档与证据回填
→ 文档提交形成新 exact Head
→ 新 Head 再跑同等完整回归
→ Ready
→ Squash Merge
```

旧 Head 的成功不能替代 latest exact Head。

## 3. S0 专项工作流

### 3.1 WCS Simulation Governance Compile

验证：

- 删除 bin/obj 后 Restore；
- `Wcs.Simulator.Tests` Release 编译；
- Host 依赖图编译；
- 全部 Simulation Governance 测试；
- TRX、Restore、Build 和 Test 日志形成 Artifact。

### 3.2 WCS Simulation Governance Boundary

验证：

- Production `Simulator.Enabled=false`；
- Simulation 与 SimulationLoadTest 双开关开启；
- Simulation 配置保持 Anomaly、ML、Forecast 关闭；
- Approved Environment 精确为 Simulation 与 SimulationLoadTest；
- Production 启动保护存在；
- API 非批准环境返回 404；
- API 状态明确 `controlWritesAllowed=false`；
- Governance 代码不依赖 PLC、任务、交通和调度控制命名空间；
- Governance 与 Controller 不包含写 PLC、取消任务、释放路权或派单操作。

## 4. S0 契约测试

`SimulationGovernanceTests`：

1. 相同 Seed 产生相同 100 项随机序列；
2. 不同 Seed 不产生相同首值；
3. Production 永久拒绝；
4. Simulator 与 Governance 双开关缺一不可；
5. 只允许批准环境；
6. AllowedEnvironments 包含 Production 时配置拒绝；
7. 合法 Package 幂等注册；
8. 同一 Version 变更内容拒绝；
9. 路径穿越拒绝；
10. 内容 Hash 不匹配拒绝；
11. Evidence 输入顺序变化后 Hash 仍一致；
12. Evidence Sequence 重复拒绝。

`SimulationGovernanceControllerTests`：

1. Production 双开关开启仍返回 404；
2. Development 双开关开启仍返回 404；
3. 任一开关关闭返回 404；
4. Simulation 双开关开启返回 200；
5. API 注册合法版本成功；
6. API 修改同一版本内容返回 400。

## 7. 失败处理规则

- 编译失败：读取精确文件、行号和项目依赖；
- 契约失败：修复实现，不修改断言来迁就错误行为；
- 性能失败：先判断 Runner 波动，再用 Artifact 和重复运行确认；
- 长稳失败：必须检查 RSS、GC、线程、句柄、队列和守恒量；
- 外部服务失败：区分测试脚本错误与业务错误；
- 不得删除、跳过、`continue-on-error` 或放宽关键门槛；
- 修复提交产生新 Head 后，旧 Head 结果全部失效。

## 8. Evidence 最低内容

每条阶段专项至少保存：

- Workflow 名称；
- Run Number 和 Run ID；
- exact Head；
- 测试环境；
- Restore/Build/Test 日志；
- TRX 或结构化结果；
- Artifact 名称；
- Artifact Digest；
- 精确通过/失败数量；
- 容量和性能数据；
- 安全写入计数；
- 已知限制。

## 9. 现场边界

仓库级与仿真级测试不能证明：

- 真实机械运动和制动安全；
- PLC 安全程序和硬件联锁；
- 工业网络干扰；
- 真实故障概率或 RUL 准确率；
- 现场权限和审计体系；
- HIL、试运行和正式投产。

上述内容必须在 S9 或项目级验收中独立签署。
