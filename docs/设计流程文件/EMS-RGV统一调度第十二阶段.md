# EMS/RGV 统一调度第十二阶段：离线仿真、策略优化与最终上线验收

## 1. 阶段定位

第十二阶段是 EMS/RGV 统一调度计划中的最后一个研发阶段。

本阶段不再扩展现场控制指令，而是建立生产策略正式启用前的证据链：

```text
当前状态 / 历史队列 / 人工场景
             │
             ▼
       离散事件仿真
             │
     ┌───────┼────────┐
     ▼       ▼        ▼
 历史回放  策略 A/B  故障注入
     │       │        │
     └───────┼────────┘
             ▼
     批量优化与拥堵预测
             │
             ▼
       容量压力基线
             │
             ▼
       最终验收报告
             │
             ▼
      现场人工验收与签署
```

第十二阶段坚持以下边界：

- 仿真不调用真实派单接口；
- 仿真不创建执行任务；
- 仿真不申请、释放或修改生产路权；
- 仿真不读写 PLC 点位；
- 故障注入仅作用于场景副本；
- 推荐策略和参数不会自动应用；
- 生产整定变更仍必须走 `ChangeConfiguration` 双人审批；
- 离线验收通过不能代替现场急停、断线、心跳冻结和实车恢复演练。

## 2. 仿真场景

`TransportSimulationScenario` 明确包含：

- 场景号、名称、描述和来源；
- 仿真基础时间；
- 仿真窗口；
- 确定性随机种子；
- 任务到达序列；
- 车辆列表；
- 站点及容量；
- 交通资源标识；
- 故障窗口。

场景来源：

```text
Manual
CurrentSnapshot
HistoricalReplay
CapacityStress
```

### 2.1 当前状态场景

从以下只读快照生成：

- 当前生产等待队列；
- 当前车辆类型、在线状态和电量；
- 当前站点定义和容量；
- 当前单轨区段与交通资源映射。

生成场景不会执行调度周期，也不会修改队列状态。

### 2.2 历史回放场景

从 `ProductionQueue` Journal 读取指定时间窗口中的任务：

1. 按 RequestId 去重；
2. 保留每个任务最新记录；
3. 使用原始入队时间形成到达偏移；
4. 使用原始优先级、交期和目标站点；
5. 使用配置的默认行驶和作业时间补全现场尚未记录的时间字段。

历史回放最多读取 50,000 条任务记录，防止离线现场内存失控。

## 3. 确定性离散事件引擎

相同的：

- ScenarioId；
- 场景内容；
- Policy；
- Seed；

必须产生相同的：

- 任务派单顺序；
- 车辆分配；
- 等待时间；
- 完成时间；
- 故障命中结果；
- 聚合指标；
- 拥堵预测。

命令失败概率通过以下固定输入计算：

```text
SHA256(seed + taskId + faultId)
```

因此不同策略的 A/B 对比共享同一故障样本，不会因为任务执行顺序变化而改变故障随机结果。

## 4. 仿真策略

支持：

```text
BaselineDynamicPriority
AgingFirst
DeadlineFirst
CongestionAware
BalancedBatch
```

策略参数包括：

- 每分钟老化加分；
- 交期紧迫加分；
- 恢复任务加分；
- 站点排队惩罚；
- 最大批量数量；
- 最低派单电量；
- 是否偏好相同目的地批量。

动态有效优先级由以下因素构成：

```text
基础优先级
+ 生产订单优先级
+ 等待老化
+ 交期紧迫
+ 故障恢复加分
- 站点拥堵惩罚
+ 策略附加项
```

## 5. 故障注入

支持：

```text
VehicleOffline
HeartbeatTimeout
StationBlocked
TrafficResourceBlocked
DriverLatency
CommandFailure
```

每个故障包含：

- 故障号；
- 目标车辆、任务、站点、交通资源或 `*`；
- 开始偏移；
- 结束偏移；
- 附加延迟；
- 命令失败概率。

故障注入只修改仿真中的车辆可用时间、站点窗口、资源窗口或任务结果，不访问生产驱动。

## 6. 策略 A/B 对比

同一场景可同时比较 2 到 10 个策略。

排序顺序：

1. 目标得分降序；
2. 吞吐量降序；
3. P95 等待时间升序。

目标得分综合：

- 吞吐量；
- 平均等待；
- P95 等待；
- 交期违约率；
- 失败任务；
- 最大队列长度。

对比报告包含：

- 每个策略对应的 RunId；
- 完整指标；
- 排名；
- 推荐 PolicyId；
- 相对基准的吞吐和等待变化。

推荐结果仅用于评审，不会修改 `TransportProductionTuningOptions`。

## 7. 批量优化

批量优化会使用当前生产整定参数生成五组候选：

- 当前动态优先级；
- 老化优先；
- 交期优先；
- 拥堵感知；
- 同目的地批量均衡。

输出：

- 推荐策略；
- 推荐任务顺序；
- 目标得分；
- 解释信息。

批量优化不保存生产参数，也不重新排列真实队列。

## 8. 未来拥堵预测

仿真按固定时间桶生成：

- 等待队列长度；
- 活动任务数量；
- 车队利用率；
- 拥堵等级。

拥堵等级：

```text
Clear
Light
Moderate
Heavy
```

该预测来自确定性场景，不等同于在线控制指令。生产调度仍以实时站点状态、路权和 PLC 反馈为准。

## 9. 容量压力基线

容量测试输入：

- 仿真时长；
- 车辆数量集合；
- 每小时任务率集合；
- 重复次数；
- 车辆类型；
- 策略；
- Seed。

每个车辆数和任务率组合输出：

- 平均完成任务数；
- 平均吞吐；
- 平均 P95 等待；
- 平均交期违约率；
- 平均车队利用率；
- 是否可持续。

可持续门槛默认：

```text
P95 等待 <= 120 秒
交期违约率 <= 5%
失败任务数 = 0
```

最终给出：

- 最大可持续任务率；
- 达到该任务率所需最少车辆数；
- 容量结论。

压力仿真只在显式 API 请求时运行，不设后台定时任务，避免占用生产 Host CPU。

## 10. 最终验收报告

验收门槛可显式配置：

- 最低吞吐；
- 最大 P95 等待；
- 最大交期违约率；
- 最大失败率；
- 最大车队利用率；
- 最大队列长度。

结果：

```text
Passed
Conditional
Failed
```

判定规则：

- 全部通过：Passed；
- 不超过 2 项未达门槛：Conditional；
- 3 项及以上未达门槛：Failed。

即使结果为 Passed，仍必须完成人工检查：

- PLC 程序、点位表和 WCS 映射版本核对；
- 急停、断线、心跳冻结和恢复实车演练；
- 单轨、路口、站点和闭塞范围核对；
- 蓝绿切换、Drain、回退和数据库恢复演练；
- 权限、审批、审计和备份流程验证；
- 设备、工艺、生产和信息化负责人联合签署。

新增类别：


- 验收报告。

## 14. 完成条件

第十二阶段通过以下条件后，十二个研发阶段全部结束：

1. Core 全部自动化测试通过；
2. Host Release 构建通过；
3. Desktop Release 构建通过；
4. 相同输入仿真结果可重复；
5. 仿真前后生产车辆、站点、队列、路权和 PLC 状态不变；
6. 历史回放、A/B、故障注入、容量基线和验收报告可持久化；
7. 最终报告明确保留现场人工验收项；
8. `main` 保持不变，直到用户明确批准合并。
