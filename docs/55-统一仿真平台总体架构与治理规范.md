# 统一仿真平台总体架构与治理规范

## 1. 文档定位

本文定义 WCS Simulation & Verification v1.0 的 S0 基线。S0 不新增控制算法，也不把现有 `Wcs.Simulator` 重写为另一套模拟器；它在已有设备模拟、PLC 模拟、任务生成和运输仿真能力上增加统一版本治理、环境隔离、确定性随机源与证据契约。

统一调度第一至第十二阶段和 AnomalyEngine v1～v3.9 已结束。S0 是独立验证线，不得称为调度“第十三阶段”。

## 2. S0 目标

- 复用现有 `Wcs.Simulator`；
- 场景必须有 ScenarioId、Version、Seed、ContentSha256、Source 和审批信息；
- 同一 ScenarioId + Version 不得对应不同内容或 ManifestHash；
- 所有随机行为使用显式固定 Seed；
- Evidence 记录有界、顺序确定并生成 EvidenceHash；
- Simulation API 只在批准环境且双开关开启时可见；
- Production 永久拒绝 Simulation；
- 仿真治理代码不得依赖 PLC 写入、任务取消、交通解锁或派单控制；
- 仓库和 Production 默认不启用仿真。

## 3. 现有能力复用

仓库已存在：

```text
Wcs.Simulator
├── ScenarioRunner
├── SimulatorOrchestrator
├── VirtualPlant
├── TransportGenerator
├── ChaosMonkey
├── SignalReplayPlayer
├── PlcSimulator
├── PlcSimulatorEngine
└── DeviceSimulator
```

S0 新增：

```text
Wcs.Simulator/Governance
├── SimulationGovernanceOptions
├── SimulationScenarioManifest
├── SimulationScenarioValidator
├── SimulationScenarioRegistry
├── SimulationBoundaryGuard
├── DeterministicSimulationRandom
└── SimulationEvidenceEnvelope
```

后续 S1～S8 必须基于这些治理契约扩展，不得在各模块自行定义版本、随机数或 Evidence 格式。

## 4. 环境与开关

仿真治理需要同时满足：

```text
Simulator.Enabled=true
AND
SimulationGovernance.Enabled=true
AND
Environment ∈ AllowedEnvironments
AND
Environment != Production
```

默认批准环境：

```text
Simulation
SimulationLoadTest
```

任何条件不满足时，`/api/simulation/governance/**` 返回 404，不暴露功能存在性。

若 `Simulator.Enabled=true` 且 Host 环境为 Production，`SimulatorBackgroundService` 失败关闭，不启动模拟 PLC。这样可以避免“配置人员以为正在模拟，实际连接真实 PLC”的危险歧义。

## 5. 场景 Manifest

必填字段：

- SchemaVersion；
- ScenarioId；
- Version；
- Seed；
- ScenarioFile；
- ContentSha256；
- CreatedAtUtc；
- Source；
- ApprovedBy；
- ApprovedAtUtc。

约束：

- 当前只接受 SchemaVersion=1；
- ScenarioId 和 Version 只允许字母、数字、点、下划线和短横线；
- Seed 必须显式填写且非零；
- ScenarioFile 必须是相对路径；
- 禁止绝对路径、`.` 和 `..`；
- 内容不能为空；
- 默认最大 1 MB，硬上限 16 MB；
- ContentSha256 必须与内容一致；
- 审批时间不能早于创建时间。

## 6. 不可变版本

Registry 使用 `ScenarioId|Version` 作为唯一身份。

允许：

- 同一个 Package 重复注册；
- 相同 Version、相同 ContentSha256、相同 ManifestHash 的幂等请求。

拒绝：

- 相同 Version 替换内容；
- 相同 Version 修改 Seed；
- 相同 Version 修改来源或审批；
- 相同 Version 修改场景文件；
- Hash 不一致。

场景需要修改时必须发布新 Version。

## 7. 确定性随机源

S0 提供运行时无关的 `DeterministicSimulationRandom`。后续故障概率、延迟、车辆行为、信号抖动和合成数据均必须使用该随机源或等价的受治理实现。

禁止：

- 直接使用当前时间作为 Seed；
- 未记录 Seed；
- 每个模块自行创建 `Random.Shared`；
- 重放时更换随机算法却沿用旧版本。

相同场景版本、Seed 和输入必须得到相同随机序列。

## 8. Evidence

`SimulationEvidenceEnvelope` 保存：

- ScenarioId；
- ScenarioVersion；
- ScenarioManifestHash；
- Seed；
- StartedAtUtc；
- FinishedAtUtc；
- 按 Sequence 排序的 Evidence Records；
- EvidenceHash。

规则：

- Sequence 唯一；
- 默认最多 10,000 条；
- 记录超限必须拒绝，不得无限增长；
- 相同输入即使传入记录顺序不同，也必须生成相同 EvidenceHash；
- Evidence 只证明软件仿真行为，不替代 HIL 和现场验收。

## 9. API

```text
GET  /api/simulation/governance/status
GET  /api/simulation/governance/scenarios
POST /api/simulation/governance/scenarios/validate
```

S0 的 POST 只进行内存校验和不可变版本登记，不运行场景、不写生产 SQL、不写 PLC、不改变任务或调度状态。

## 10. 安全边界

- 不写真实 PLC；
- 不停止设备；
- 不取消生产任务；
- 不释放真实路权；
- 不改变路线、区段占用、车辆选择或派单；
- 不启用 AnomalyDetection、MachineLearning、PluggableRuntime 或 AssetFailureForecast；
- 不提交真实点位、拓扑、场景、密钥或现场数据；
- Production 不能加入 AllowedEnvironments；
- 页面阶段 S10 只能调用治理 API，不得绕过治理契约。

## 11. 回退

第一优先级：

```text
SimulationGovernance__Enabled=false
Simulator__Enabled=false
```

随后停止 Simulation 环境 Host。回退不影响真实 PLC、调度、异常检测、健康、维修和 Forecast 的既有配置与数据。

## 12. 后续阶段依赖

```text
S0 治理与边界
  ↓
S1 场景引擎与虚拟时钟
  ↓
S2 虚拟 PLC
  ↓
S3 虚拟 RGV 与区段
  ↓
S4 调度、交通与死锁
  ↓
S5 MES、SQL 与网络故障
  ↓
S6 异常、健康与 RUL 合成数据
  ↓
S7 全系统集成与恢复
  ↓
S8 容量、长稳与 HIL 准备
  ↓
S10 统一页面完善
```

S9 保留给真实 HIL/现场试运行，不能由仓库代码自动宣称完成。
