# EMS/RGV 统一调度软件需求规格说明书

## 1. 引言

### 1.1 目的

本文定义 WCS Runtime Engine 中 EMS 空中台车和 RGV 地面车辆统一调度子系统的业务需求、功能需求、非功能需求、外部接口、约束条件和验收标准。

### 1.2 范围

系统负责从 MES/WMS/WCS 上层业务接收运输请求，完成车辆选择、路径计算、资源预留、执行编排、PLC 命令下发、交通控制、状态恢复、生产监控、备份恢复和离线策略仿真。

系统不负责：

- PLC 内部运动控制、伺服闭环和安全回路；
- 厂商控制器内部路径跟随算法；
- 生产工艺配方计算；
- 未经过点位配置的自由 PLC 地址读写；
- 由 AI 自动生成或直接执行控制指令。

## 2. 角色

| 角色 | 职责 |
|---|---|
| 上层业务系统 | 创建、取消和查询运输任务 |
| 调度管理员 | 配置车辆、资源、站点、单轨和生产策略 |
| 设备工程师 | 配置 PLC 点位、联调驱动和验证回执 |
| 生产操作员 | 查看队列、车辆、任务、报警和运行状态 |
| 运维工程师 | 监控健康、备份、恢复、日志和性能 |
| 审批人 | 审批危险操作和配置变更 |
| 测试/实施人员 | 执行仿真、容量、故障和现场验收 |

## 3. 功能需求

### FR-001 统一车辆管理

系统应统一管理 EMS 和 RGV 车辆，并至少保存车辆编号、类型、运行状态、可信节点、在线状态、电量、能力、活动任务数、版本和更新时间。

系统必须拒绝旧版本车辆状态覆盖新版本状态。

### FR-002 运输任务接收

系统应接收包含以下信息的运输请求：

- `RequestId`
- 起点节点
- 目标节点
- 允许车辆类型
- 所需能力
- 任务优先级
- 生产订单优先级
- 交期
- 目标站点
- 是否故障恢复任务

### FR-003 请求幂等

相同 `RequestId` 重复请求必须返回同一业务结果，不得重复选择车辆、重复预留路权或重复创建 PLC 任务。

### FR-004 车辆选择

系统应过滤离线、故障、维护、低电量、能力不匹配或状态不可用车辆，并根据空驶距离、任务负载、电量、动态优先级和策略进行排序。

### FR-005 路径计算

系统应基于统一拓扑计算车辆到取货点和取货点到目标点的路径，支持故障节点/边绕行、能力限制和拥堵权重。

### FR-006 路权预留

系统应在命令下发前完成必要路段和交通资源的原子预留。任一资源冲突时，本次预留不得部分成功。

物理占用已经确认时，不得通过软件超时或死锁解除提前释放。

### FR-007 执行状态机

系统应支持创建、开始、装载确认、移动、卸载确认、暂停、恢复、故障、取消和完成。

### FR-008 PLC 命令下发

系统应通过适配层向 EMS/RGV PLC 或控制器下发统一命令，并使用任务号、命令序号和回执序号进行相关性校验。

### FR-009 PLC 回执和心跳

系统应读取心跳、在线状态、可信节点、运行状态、当前命令、确认序号、命令接收和命令完成信号。

通信中断时不得根据时间推算并覆盖真实位置。

### FR-010 交通控制

系统应支持：

- 闭塞区段互斥；
- 路口冲突资源；
- 滚动路权窗口；
- 单轨方向许可；
- 同向编队；
- 相向会车等待；
- 死锁检测；
- 优先级让行；
- 物理占用保护。

### FR-011 生产任务竞争

系统应维护生产等待队列，根据任务基础优先级、生产优先级、等待老化、交期紧迫、恢复任务和站点拥堵计算有效优先级。

### FR-012 站点拥堵控制

系统应根据站点容量、占用和排队上限决定任务是否可进入调度。

### FR-013 充电和能耗

系统应支持最低派单电量、充电站容量、充电排队和低电量车辆排除。

### FR-014 故障车辆接管

取货前故障可在安全条件满足时重分配；已装载、正在装卸或物理占用未清除时必须转人工恢复。

### FR-015 持久化

系统应持久化车辆、执行任务、路权、命令、配置、点位映射、治理记录、联调记录和关键 Journal。

### FR-016 启动恢复

系统启动时应加载状态并与 PLC 当前状态执行三方对账。无法确认的任务不得自动续跑。

### FR-017 配置治理

危险操作和配置变更应支持权限校验、申请、独立审批、目标绑定、一次性执行和审计。

### FR-018 现场联调

系统应支持 JSON、CSV、XLSX 点位导入，模板生成，点位校验，单点读取、受控写入、在线探测、通信 Trace、故障码和恢复冲突处置。

### FR-019 可观测性

系统应提供 TraceId、操作耗时、排队时间、PLC 响应时间、失败数量、健康评分、一致性报告和 Prometheus 指标。

### FR-020 备份恢复

系统应生成包含配置、点位、运行快照、Journal 和基线的离线逻辑备份，并使用 SHA-256 校验。恢复准备不得直接恢复活动任务和 PLC 命令。

### FR-021 离线仿真

系统应支持当前快照、历史回放和人工场景的确定性仿真、故障注入、策略 A/B、批量优化、拥堵预测和容量基线。

### FR-022 Desktop

系统应提供车辆调度、交通控制、生产队列、配置审计、驱动诊断、现场联调、可观测性、韧性和仿真只读/受控操作页面。

## 4. 非功能需求

### NFR-001 安全确定性

控制层不得依赖生成式 AI。相同输入和状态应产生可解释、可复现的调度结果。

### NFR-002 可用性

单次监控、日志、备份或仿真失败不得终止 PLC 轮询和核心调度服务。

### NFR-003 性能

- PLC 轮询间隔应可配置，典型值 100ms；
- 命令泵典型周期 100ms；
- 生产派单周期典型值 1 秒；
- 日常 API 不应执行无界历史加载或无界仿真；
- 仿真必须受任务数、车辆数、时间桶和总估算量限制。

### NFR-004 可恢复性

重启后不得重复下发运动命令。任何数据库、内存和 PLC 不一致必须被识别并进入安全处置。

### NFR-005 可审计性

危险操作、配置变更、审批、回滚、备份、演练和验收必须记录执行人、时间、目标、原因和结果。

### NFR-006 离线部署

生产现场不得依赖互联网、云对象存储或在线模型服务。

### NFR-007 可扩展性

后续 AGV、堆垛机、电梯或其他运输设备应通过新的车辆类型、Driver、AdmissionPolicy 和资源模型扩展，而不是复制调度内核。

### NFR-008 兼容性

目标运行时为 .NET 8；Host、Core、Infrastructure 和 Desktop 应在 Windows CI Release 模式构建通过。

## 5. 外部接口需求

### 5.1 MES/WMS

推荐通过 HTTP API 提交运输请求和查询状态。上层系统负责提供唯一 `RequestId`。

### 5.2 PLC/控制器

通过配置化驱动和点位映射连接，禁止在业务代码中硬编码现场 DB 地址。

### 5.3 SQL Server

用于运行状态、配置、治理、点位、联调和 Journal 持久化。

### 5.4 Prometheus/OTLP

Prometheus 通过 `/metrics` 抓取；OTLP 可按配置发送到本地 Collector。

## 6. 约束

1. 双实例同时向同一车辆控制器写命令必须禁止，除非完成单活选主和 Fence Token。
2. PLC 无位置反馈时，WCS 只能维护可信节点和已确认物理占用。
3. `Stop` 可按审批执行安全补偿；运动类命令默认不得盲目重试。
4. 现场参数、点位、拓扑和故障码必须由项目实施附件确定。
5. 仿真推荐不得自动应用到生产参数。

## 7. 验收标准

软件研发验收至少包括：

- Core 全部自动化测试通过；
- Host Release 构建通过；
- Desktop Release 构建通过；
- 十二阶段文档和正式交付文档齐全；
- 无新增未说明数据库迁移；
- `main` 未经批准不合并。

现场投产验收还必须包括：

- PLC 点位和程序版本核对；
- 空载、带载、会车、追车、单轨和闭塞测试；
- 急停、断线、心跳冻结、重启和数据库恢复演练；
- 权限、审批、审计、备份和回退验证；
- 设备、生产、工艺、信息化和项目负责人联合签署。
