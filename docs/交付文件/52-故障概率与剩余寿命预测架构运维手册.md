# 故障概率与剩余寿命预测架构运维手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 能力版本 | AnomalyEngine v3.9 |
| 代码分支 | `feature/failure-probability-rul-v3-9` |
| 运行方式 | .NET 8、Microsoft ONNX Runtime CPU、本地模型、SQL Server |
| 输入 | v3.4 资产健康历史，不直接读取或写入 PLC |
| 输出 | 24/72/168 小时故障概率与 RUL 下限/中位/上限 |
| 默认状态 | `AssetFailureForecast.Enabled=false` |
| 安全定位 | 诊断与维修计划辅助，不是安全联锁、停机命令或实际寿命保证 |

## 2. 目标与非目标

v3.9 在 v3.4 健康历史与 v3.8 本地 ONNX 治理基础上，为具备真实退化和失效数据的资产提供版本化、可审计、可回退的故障概率与剩余寿命区间。

系统明确拒绝以下做法：

- 根据当前健康分做线性外推并伪造 RUL；
- 无真实失效样本、无删失样本或无验证指标仍输出小时数；
- 下载远程模型或调用云端预测；
- 自动训练、自动审批、自动激活或自动替换模型；
- 将概率或 RUL 直接用于 PLC 写入、设备停机、任务取消或调度修改；
- 将仓库级 CI 模型结果当作现场准确率承诺。

## 3. 总体架构

```text
AssetHealthScoreHistory（Memory / SQL Server）
                    ↓
AssetFailureForecastFeatureBuilder
  ├─ 历史点数门槛
  ├─ 历史跨度门槛
  └─ 固定 14 维特征
                    ↓
AssetFailureForecastService
  ├─ 本地 active.json
  ├─ Manifest / SHA / 审批 / 训练证据校验
  └─ OnnxAssetFailureForecastRuntime（CPU）
                    ↓
24h / 72h / 168h Failure Probability
RUL Lower / Median / Upper
                    ↓
Wcs_AssetFailureForecast
                    ↓
人工 Outcome Journal
  ├─ ObservedFailure
  ├─ PreventiveMaintenance
  ├─ CensoredNoFailure
  └─ InvalidPrediction
                    ↓
Brier / RUL MAE / Interval Coverage
```

预测模块只消费健康历史与本地模型，不订阅控制命令，不发布设备或调度操作。

## 4. 数据充分性门槛

默认要求：

- 至少 48 个已保留健康点；
- 历史跨度至少 24 小时；
- 单次最多读取 2,000 个点；
- 单轮最多评估 1,000 个资产。

未满足时返回 `InsufficientData`，不得生成概率、RUL 或 SQL Forecast 行。

## 5. 固定特征契约

v3.9 固定 14 维、区分大小写且顺序不可变：

```text
health.latest
health.mean
health.minimum
health.maximum
health.stddev
health.slopePerHour
health.delta
fusionRisk.mean
fusionRisk.maximum
grade.changeCount
grade.degradedOrWorseRatio
grade.criticalRatio
history.sampleCount
history.spanHours
```

Manifest 的 `FeatureNames` 必须与该顺序逐项一致；均值、标准差和 ONNX 输入第二维必须等于 14。特征定义变化必须建立新 SchemaVersion 与新模型版本，不能覆盖旧 Manifest。

## 6. 模型 Manifest

`AssetFailureForecastModelManifest` 必须包含：

- SchemaVersion、Version、AdapterId；
- 相对路径 ArtifactFile 与 ArtifactSha256；
- CreatedUtc、Source、ApprovedBy、ApprovedAtUtc；
- TrainingDatasetVersion；
- TrainingAssetCount；
- FailureEventCount；
- CensoredRecordCount；
- ValidationAuc；
- ValidationBrierScore；
- ValidationRulMaeHours；
- ValidationIntervalCoverage；
- FeatureNames、Means、StandardDeviations；
- InputName、OutputName、InputShape、OutputShape；
- MaximumRulHours。

仓库默认治理门槛：

| 指标 | 默认门槛 |
|---|---:|
| TrainingAssetCount | ≥ 30 |
| FailureEventCount | ≥ 10 |
| CensoredRecordCount | ≥ 1 |
| ValidationAuc | ≥ 0.65 |
| ValidationBrierScore | ≤ 0.30 |
| ValidationIntervalCoverage | ≥ 0.70 |

这些是最低软件门槛，不是现场投产标准。现场应按资产类型、风险等级、样本偏差和业务成本建立更严格标准。

## 7. 本地模型目录

```text
<ModelDirectory>/
├── active.json
├── manifest-<Version>.json
└── <ArtifactFile>.onnx
```

约束：

1. 模型只能从配置的本地目录加载；
2. `ArtifactFile` 必须是相对路径；
3. 禁止绝对路径和 `..`；
4. 默认单文件上限 256 MB；
5. 加载前验证 SHA-256；
6. `active.json` 原子替换；
7. 模型目录使用受控 ACL、备份、发布签名和容量监控；
8. 仓库不得提交真实模型、训练数据、许可证、密钥或站点信息。

## 8. ONNX 输入输出

运行时固定为 CPU、顺序执行、单 InterOp/单 IntraOp 线程，输入输出均为 float32。

```text
Input : [1|-1, 14]
Output: [1|-1, 6]
```

六个输出顺序：

```text
0: FailureProbability24Hours
1: FailureProbability72Hours
2: FailureProbability168Hours
3: RulLowerHours
4: RulMedianHours
5: RulUpperHours
```

运行时强制：

- 概率均在 `[0,1]`；
- `P24 <= P72 <= P168`；
- RUL 有限、非负且不超过 MaximumRulHours；
- `Lower <= Median <= Upper`。

任何一项不满足，整次预测失败且不写 Forecast。

## 9. SQL 对象

```text
Wcs_AssetFailureForecastModelVersion
Wcs_AssetFailureForecast
Wcs_AssetFailureForecastOutcomeJournal
```

### 9.1 模型版本

同一 `Version` 不能对应不同 `ManifestHash`。Manifest JSON、SHA、数据集版本、样本统计、验证指标和审批信息保留审计。

### 9.2 Forecast

`ForecastId` 由 AssetId、ModelVersion、历史窗口起止时间确定。相同资产、模型和窗口重复评估不重复插入。

Forecast 保留模型版本、ManifestHash、窗口、样本数、历史跨度、三段概率、RUL 区间、当前健康分、等级和解释。

### 9.3 Outcome Journal

Outcome 只追加，不覆盖原 Forecast：

- `ObservedFailure`：观察到真实故障；
- `PreventiveMaintenance`：预测窗口内进行了预防性维修；
- `CensoredNoFailure`：观察期结束但未故障；
- `InvalidPrediction`：经人工确认预测不适用。

必须记录 ObservedAtUtc、RecordedBy 和 Note。重复 OutcomeId 幂等。

## 10. 评估指标

基于人工 Outcome 计算：

- 24 小时 Brier Score；
- 真实故障的 RUL 中位数绝对误差；
- 真实故障落入 Lower～Upper 区间的覆盖率。

无 Outcome 时指标返回空，不伪造零误差或满覆盖。

## 11. 状态与失败隔离

状态：

- `Disabled`；
- `ModelUnavailable`；
- `InsufficientData`；
- `Ready`；
- `Failed`。

活动模型缺失、Hash 错误、训练证据不足、张量不匹配或推理异常只更新 Forecast 状态和失败指标，不使 Host 启动失败，也不进入 PLC、任务、命令、路权或调度线程。

`/api/anomaly/forecast/load/**` 只在 `ForecastLoadTest` 环境存在，生产返回 404。

## 14. 上线顺序

1. 保持 Forecast 关闭；
2. 验证 v3.4 SQL 健康历史完整性和时间语义；
3. 冻结数据集与 14 维 FeatureSchema；
4. 对故障、删失和维修记录做资产级拆分，防止数据泄漏；
5. 离线训练并独立回测；
6. 核验 AUC、Brier、RUL MAE、区间覆盖、分资产类型结果和许可证；
7. 生成 SHA 与 Manifest；
8. 可靠性、设备、工艺、安全和数据负责人审批；
9. 发布到本地受控目录；
10. 先用人工手工评估和小范围资产观察；
11. 检查 Outcome 指标和漂移；
12. 项目级签署后再考虑周期评估。

## 15. 回退

```text
AssetFailureForecast__Enabled=false
```

关闭后停止新预测和周期评估，保留模型、Forecast、Outcome 和指标审计，不影响健康评分、异常治理、PLC、任务或调度。

## 16. 运维检查

- [ ] 仓库与 Production 默认关闭；
- [ ] 无真实模型、数据、URL、密钥或许可证提交到仓库；
- [ ] 模型 SHA、ManifestHash、审批与数据集版本一致；
- [ ] 训练资产、故障与删失样本满足项目标准；
- [ ] FeatureSchema 和张量维度精确一致；
- [ ] 概率单调且 RUL 区间有序；
- [ ] 数据不足时不生成预测；
- [ ] Outcome 由有权限人员记录；
- [ ] Brier、RUL MAE 和区间覆盖持续监控；
- [ ] Host 重启恢复活动版本和历史 Forecast；
- [ ] 坏模型时 Host 健康且 Forecast 拒载；
- [ ] 无 PLC 写入、停机、任务取消或调度修改。
