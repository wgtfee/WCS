# AnomalyEngine v3.5～v3.9 总体演进路线

## 1. 文档定位

本文件定义 WCS Runtime Engine 在 AnomalyEngine v3.4 之后的独立异常诊断演进路线。

必须区分两条研发主线：

```text
EMS/RGV 统一调度主线：第一阶段～第十二阶段，软件研发已经结束
AnomalyEngine 诊断扩展线：v1～v3.9，继续以只读诊断能力演进
```

统一调度后续不再使用“第十三阶段”扩展。现场工作应以点位包、拓扑包、参数包、联调缺陷单、验收报告和生产发布单推进。

AnomalyEngine v3.x 不得绕过既有状态机、路权、PLC 联锁、AlarmCenter 和审批体系。

## 3. 总体数据流

```text
规则 / 统计 / ML / 同群 / 周期异常
                ↓
          v3.3 Evidence Fusion
                ↓
      v3.4 Health Score + Trend
                ↓
      v3.5 Governed Health Event
                ↓
     MES 通知 / 人工确认 / 抑制 / 恢复
                ↓
     v3.6 Root Cause Graph Analysis
                ↓
      v3.7 Maintenance Feedback Loop
                ↓
       v3.8 Pluggable Model Runtime
                ↓
      v3.9 Failure Probability and RUL
```

其中 v3.5～v3.9 均属于诊断与辅助决策层。任何自动停机、自动修改调度、自动释放路权或自动下发维修动作，都必须进入独立安全项目，不属于本路线默认交付。

## 4. v3.5：健康事件治理与 MES 联动

### 4.1 目标

把持续异常的健康评分转换为可确认、可恢复、可抑制、可审计、可重试推送的正式健康事件。

### 4.2 核心能力

- 按最低健康等级和连续评估次数创建事件；
- 使用连续恢复次数避免分数抖动造成反复恢复；
- 同一资产只保留一个活动健康事件生命周期；
- 保存 Raised、Observed、GradeChanged、Acknowledged、Suppressed、Unsuppressed、Recovered 转换；
- 确认操作保存操作者、时间和备注；
- 抑制操作保存操作者、原因和有效期；
- SQL Journal 采用 MessageId 和 EventId + Version 双重幂等；
- MES Outbox 支持超时、指数退避、最大次数和 DeadLetter；
- HTTP 使用 `Idempotency-Key`，MES 返回 2xx 或 409 时视为幂等成功；
- Host 重启后恢复活动事件和待发送消息；
- MES、SQL 或网络故障不阻塞 PLC、任务和调度。

### 4.3 明确边界

- 不自动停止设备；
- 不自动取消任务；
- 不改变车辆选择、路径或路权；
- 不替代 AlarmCenter；
- 不把 MES 响应当作 PLC 联锁依据；
- 不在仓库提交 MES 密钥。

### 4.4 完成门槛

- Core 生命周期单元测试通过；
- SQL Journal 精确版本和幂等测试通过；
- Host 重启后活动事件和 Outbox 可恢复；
- MES 成功、冲突、超时、5xx、断线和恢复测试通过；
- DeadLetter 可人工重试；
- 完整 Windows、异常、Fusion、Health、Soak 回归通过；
- 生产配置默认 `Enabled=false`、`MesPushEnabled=false`；
- 架构、配置、API、测试、运维和验收文档齐全。

## 5. v3.6：根因关联与异常传播分析

### 5.1 目标

将同一时间窗口内的设备、部件、信号、任务、站点和路段异常建立依赖关系，输出根因候选和传播路径，而不是向人员展示大量孤立告警。

### 5.2 计划能力

- 定义资产、部件、信号、任务和拓扑依赖图；
- 支持 DependsOn、Feeds、Controls、LocatedAt、Carries 等关系；
- 按时间邻近、拓扑邻近和因果方向关联 Evidence；
- 区分 RootCause、Intermediate 和 Symptom；
- 输出根因候选、置信度、支持证据和传播链；
- 支持人工确认、否决和补充根因关系；
- 对依赖图版本、来源和审批进行审计；
- 保持分析只读，不反向控制设备。

### 5.3 前置条件

- v3.5 已提供稳定健康事件生命周期；
- 现场提供设备、部件、工位和上下游关系；
- 依赖关系经过设备和工艺人员确认。

### 5.4 完成门槛

- 根因图无环或对允许环路有明确处理；
- 时间窗口和传播深度有界；
- 大规模资产图内存和查询受限；
- 人工标注与推断结果可追溯；
- 根因结果不得自动停机。

## 6. v3.7：维修决策支持与反馈闭环

### 6.1 目标

把健康事件和根因候选转换为可执行的检查建议，并利用 MES/维修人员反馈评估误报、命中率和维修效果。

### 6.2 计划能力

- 根因到检查项、部件、工具、备件和安全注意事项的规则映射；
- 生成“建议检查”，不直接生成控制命令；
- 支持 Accepted、Rejected、FalsePositive、Repaired、NoFaultFound 等反馈；
- 保存维修前后健康分、根因和事件变化；
- 统计建议采纳率、真实故障命中率、误报率和平均关闭时间；
- 将人工确认结果形成训练标签，但不自动污染活动模型；
- 与 MES 工单号、处理人和完成时间关联；
- 支持配置版本、审批和回退。

### 6.3 前置条件

- v3.5 事件和 MES 联动稳定；
- v3.6 根因结果达到可解释门槛；
- 现场提供标准维修作业和部件字典。

### 6.4 完成门槛

- 建议来源和规则版本可解释；
- 维修反馈不可覆盖原始诊断证据；
- 训练标签需人工审批；
- 无现场规则时不生成伪建议；
- 不自动申请停机或绕过生产审批。

## 7. v3.8：可插拔模型与 ONNX 运行时

### 7.1 目标

在保留纯 .NET Isolation Forest 的同时建立统一模型适配边界，使本地 ONNX 模型能够复用现有 Profile、治理、Shadow、Canary、回滚和 Evidence Fusion。

### 7.2 计划能力

- 定义 `IAnomalyModelAdapter`；
- 统一特征契约、输入维度、标准化和输出解释；
- 提供 Isolation Forest Adapter；
- 提供本地 ONNX Runtime Adapter；
- 模型加载前校验文件摘要、输入输出名称和维度；
- 继续使用冻结数据集、审批、Shadow、Canary 和原子激活；
- 模型输出只能生成 Evidence，不得直接写 PLC；
- 推理超时、异常和内存占用有界；
- 无 GPU、无外网环境可运行。

### 7.3 前置条件

- 存在经过现场验收的 ONNX 模型；
- 特征和标签定义稳定；
- 模型许可证和来源明确。

### 7.4 完成门槛

- 相同模型、相同输入结果可重复；
- 模型切换不影响活动生命周期一致性；
- Shadow 与 Active 输出守恒；
- 10 万窗口推理、回滚和内存测试通过；
- 模型失败自动降级，不阻塞控制链路。

## 8. v3.9：故障概率与剩余寿命预测

### 8.1 目标

在具备长期退化数据、真实故障和维修记录后，输出部件未来故障概率、剩余寿命区间和建议维护时间窗口。

### 8.2 计划能力

- 退化趋势特征和部件级健康轨迹；
- 指定时间窗内故障概率；
- Remaining Useful Life 点估计和置信区间；
- 按产品、负载、工况和维护状态分层；
- 离线回测、时间切分和数据泄漏检查；
- 预测校准、覆盖率、提前量和误报评估；
- 维修后重置或迁移退化状态；
- 输出建议维护窗口，不自动下发停机。

### 8.3 数据前置条件

至少需要：

- 足够长的连续历史；
- 明确故障发生时间；
- 部件更换和维修时间；
- 工况、产品和负载上下文；
- 可确认的正常和异常标签；
- 足够数量的真实失效样本。

数据不足时必须保持关闭，不得为了版本完整而输出虚假 RUL。

### 8.4 完成门槛

- 使用时间外测试集；
- 提前量、召回率、误报率和置信区间覆盖率达到现场门槛；
- 不同设备族和工况不得混用单一模型；
- 预测结果必须附带模型版本、数据范围和不确定性；
- 任何自动控制联动必须另立安全阶段。

## 9. 版本依赖和执行顺序

```text
v3.5 必须先完成
  ↓
v3.6 与 v3.7 建议连续实施
  ↓
v3.8 仅在存在成熟本地模型时实施
  ↓
v3.9 仅在真实失效和维修数据满足条件时实施
```

不允许跳过 v3.5 的事件治理和审计，直接把模型输出推给 MES；也不允许在没有 v3.6 根因证据的情况下生成强结论维修建议。

## 10. 长期安全原则

1. PLC 安全联锁始终高于 WCS 诊断结果。
2. 诊断失败只能降级，不得中断实时控制。
3. 控制层继续使用确定性规则和状态机，不使用生成式 AI。
4. MES 通知采用幂等和可重试机制，但 MES 不成为实时控制依赖。
5. 模型、规则、阈值、依赖图和建议库变更必须版本化、审批和可回退。
6. 自动停机、自动调整调度和自动执行维修属于独立安全项目。
7. 软件 CI 通过不等于现场联调或正式投产完成。
