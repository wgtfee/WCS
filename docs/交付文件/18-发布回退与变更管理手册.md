# EMS/RGV 发布、回退与变更管理手册

## 1. 目标

本文规定应用版本、配置、点位、数据库和策略变更的申请、验证、发布、观察和回退流程。

## 2. 变更类型

| 类型 | 示例 | 风险等级 |
|---|---|---|
| 应用发布 | Host/Core/Desktop 新版本 | 高 |
| 数据库变更 | 表、字段、索引、初始化逻辑 | 高 |
| PLC 点位变更 | 标签、DB、类型、命令码 | 高 |
| 拓扑/交通变更 | 节点、区段、路口、单轨 | 高 |
| 生产参数变更 | 优先级、拥堵、充电、周期 | 中高 |
| 监控参数变更 | 周期、保留、导出 | 中 |
| 文档变更 | 说明、模板、记录 | 低至中 |

## 3. 版本标识

每次发布记录：

- 发布版本号；
- Git Commit SHA；
- 构建时间；
- CI 结果；
- 数据库 Schema 版本；
- 配置版本；
- PLC 程序版本；
- 点位表版本；
- Desktop 版本。

## 4. 变更申请

申请内容：

- 变更原因；
- 范围；
- 风险；
- 受影响车辆/站点/接口；
- 测试证据；
- 发布步骤；
- 回退步骤；
- 计划窗口；
- 申请人和审批人。

## 5. 发布前 Gate

- 代码评审完成；
- Core/Host/Desktop CI 通过；
- 交付文档更新；
- 数据库备份完成；
- 逻辑备份完成并校验；
- 活动任务可 Drain；
- PLC/点位版本确认；
- 回退包和旧配置存在；
- 现场负责人批准；
- 运维和设备人员到位。

## 6. 蓝绿发布

推荐三个 IIS 站点：

```text
WCS-Blue
WCS-Green
WCS-Gateway
```

Gateway 使用 ARR/URL Rewrite 或其他受控反向代理。

### 6.1 发布流程

1. 当前流量指向 Blue；
2. 部署 Green；
3. Green 连接测试数据库或只读检查；
4. 验证 live/ready；
5. 停止上层创建新任务；
6. Drain Blue 活动任务；
7. 确认车辆停稳和物理占用；
8. 切换 Gateway 到 Green；
9. 小流量验证；
10. 保留 Blue 作为回退版本。

### 6.2 调度单活

Blue 和 Green 不得同时对同一 PLC 拥有写权限。即使 Gateway 只转发到一个站点，也要防止后台 HostedService 在另一个实例继续运行。

## 7. Drain

Drain 状态下：

- 拒绝新生产任务；
- 允许已有任务安全完成；
- 不启动新的充电/优化任务；
- 保留 PLC 状态读取；
- 监控活动任务、命令和占用；
- 达到超时仍有活动任务时人工决定继续等待或安全停止。

## 8. 配置变更

生产配置使用：

```text
读取当前版本
→ 提交 ExpectedVersion
→ ChangeConfiguration 申请
→ 独立审批
→ 保存和应用
→ 观察
```

版本冲突时必须重新读取，不得强制覆盖。

## 9. PLC 点位变更

点位变化必须与 PLC 程序版本绑定。流程：

1. 导出当前点位；
2. 获取新 PLC 版本；
3. 修改点位表；
4. 离线校验；
5. 现场单点读取；
6. 审批应用；
7. 命令握手测试；
8. 保存版本和签署。

## 10. 数据库变更

- 先备份；
- 脚本可重复执行或有版本保护；
- 大表变更评估锁表时间；
- 旧版本回退兼容；
- 不在生产高峰自动创建大索引；
- 变更后验证读写和恢复。

## 11. 发布后观察

至少观察：

- Readiness；
- 车辆在线；
- 任务完成率；
- PLC 响应；
- 一致性差异；
- 命令失败；
- 队列和拥堵；
- CPU、内存、SQL；
- 日志异常；
- 自动备份。

## 12. 回退触发

- P0/P1 缺陷；
- 重复运动命令风险；
- 路权或物理占用异常；
- Readiness 持续失败；
- 数据库不兼容；
- PLC 点位错误；
- 任务完成率严重下降；
- 无法在窗口内修复；
- 现场安全负责人要求。

## 13. 应用回退

1. 停止新任务；
2. Drain 或安全停车；
3. 保存 Trace、日志和快照；
4. 切换回旧站点/旧发布包；
5. 恢复旧配置；
6. 必要时恢复数据库；
7. 三方对账；
8. 单车冒烟；
9. 恢复生产。

## 14. 参数回退

优先使用配置快照回滚。必须：

- 指定 SnapshotId；
- 使用 ChangeConfiguration 审批；
- 创建回滚前安全快照；
- 检查当前版本；
- 不自动回滚 PLC 点位。

## 15. 变更失败处理

- 不在现场临时直接改源代码；
- 不通过修改数据库“修复”状态机；
- 不复用已执行审批；
- 记录失败步骤和 Trace；
- 评估回退而不是连续叠加热修；
- 紧急修复也必须补齐测试和文档。
