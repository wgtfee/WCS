- 已审批维修规则集与 SHA-256 RuleSetHash；
- Confirmed/Supplemented 根因门槛；
- 精确节点规则优先；

- 检查项、部件、工具、备件、安全说明；
- MES 工单号、处理人和完成时间；
- Accepted、Rejected、FalsePositive、Repaired、NoFaultFound、Cancelled；
- 维修前后健康分；
- 反馈 Journal；
- 接受率、确认故障率、误报率和关闭时间；
- 待审批训练标签；
- Host 重启恢复；
- 默认关闭和控制链路隔离。

## 3. Core 测试

`AssetHealthMaintenanceDecisionEngineTests` 覆盖：

1. Confirmed 根因生成检查建议；
2. Pending 和 Rejected 不生成建议；
3. 无已审批规则时不生成伪建议；
4. 相同规则、分析和事件版本生成相同 RecommendationId；
5. Supplemented 根因可匹配精确节点规则；
6. Confirmed 置信度低于门槛时拒绝；
7. 精确节点规则优先于类型规则；
8. Enabled 规则集必须包含版本、来源和审批信息。

## 4. SQL 对象与断言

### 4.1 RuleSetVersion

- Version 唯一；
- RuleSetHash 唯一；
- 同 Version 不同 Hash 拒绝；
- 保存来源和审批信息。

### 4.2 Recommendation

- RecommendationId 唯一；
- 重复生成只保留一条；
- 原始 RecommendationJson 不被反馈覆盖；
- 当前状态和工单摘要可查询。

### 4.3 FeedbackJournal

- FeedbackId 唯一；
- Accepted 和 Repaired 独立保存；
- 重复 FeedbackId 不新增 Journal；
- Actor、工单号、处理人、分数和备注可追溯。

### 4.4 TrainingLabel

- Repaired 生成 `fault-confirmed`；
- 初始状态 PendingApproval；
- 人工 Approved/Rejected；
- 不调用模型训练或激活接口。

## 6. API 验收

- 状态接口返回 Runtime、Store、Metrics；
- 规则接口返回版本、Hash、置信度门槛和规则；
- 建议支持状态和资产过滤；
- 反馈需要 Actor；
- Rejected、FalsePositive、NoFaultFound 必须填写备注；
- PostHealthScore 限制在 0～100；
- 标签复核不允许回写 PendingApproval；
- LoadTest 接口在非 LoadTest 环境返回 404。

## 9. 安全边界测试

必须保持：

- `AssetHealthMaintenance.Enabled=false` 为仓库默认；
- Production RuleSet 为空；
- 无审批信息时启用失败；
- 无规则时不生成建议；
- 未复核根因不生成建议；
- MES 工单只作为元数据；
- 标签不会自动训练或更新模型；
- 无 PLC 写入；
- 无设备停止；
- 无任务取消；
- 无路线、路权、车辆选择或派单修改；
- SQL 失败不阻塞控制链路。
