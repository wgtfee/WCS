# 场景开发与调试操作手册

## 1. 使用环境

S1 仅允许：

```text
ASPNETCORE_ENVIRONMENT=Simulation
或
ASPNETCORE_ENVIRONMENT=SimulationLoadTest
```

同时必须满足：

```text
Simulator.Enabled=true
SimulationGovernance.Enabled=true
AllowedEnvironments 包含当前环境
```

Production 和未批准环境的仿真 API 返回 404。不要通过修改 Controller 绕过该边界。

## 2. 编写场景

示例：

```json
{
  "SchemaVersion": 1,
  "ScenarioId": "counter-smoke",
  "Version": "1.0.0",
  "Seed": 20260729,
  "StartTimeUtc": "2026-07-29T00:00:00+00:00",
  "DurationMilliseconds": 1000,
  "StopOnAssertionFailure": true,
  "Actions": [
    {
      "Id": "set-counter",
      "AtMilliseconds": 100,
      "Order": 0,
      "Kind": "state.set",
      "Target": "counter",
      "Payload": 1
    },
    {
      "Id": "increment-counter",
      "AtMilliseconds": 200,
      "Order": 0,
      "Kind": "state.increment",
      "Target": "counter",
      "Payload": 2
    }
  ],
  "Assertions": [
    {
      "Id": "counter-equals-three",
      "AtMilliseconds": 300,
      "Order": 0,
      "Kind": "state.equals",
      "Target": "counter",
      "Expected": 3
    }
  ]
}
```

同一场景中 Action 与 Assertion 的 Id 必须全局唯一。

## 3. 登记治理版本

先计算场景文件 UTF-8 字节的 SHA-256，再调用：

```text
POST /api/simulation/governance/scenarios/validate
```

请求包含 Manifest 和 `ContentBase64`。Manifest 的 ScenarioId、Version、Seed 与场景文档一致。

同一 `ScenarioId + Version`：

- 相同 ManifestHash 和 ContentSha256 可幂等登记；
- 修改任何受治理内容必须发布新 Version；
- 不得覆盖旧版本。

## 4. 创建运行

```text
POST /api/simulation/scenarios/runs
```

请求：

```json
{
  "ScenarioId": "counter-smoke",
  "Version": "1.0.0",
  "ContentBase64": "...",
  "SpeedFactor": 100,
  "StartPaused": true
}
```

执行内容必须与登记时的 SHA-256 相同。RunRegistry 默认最多 1,000 条，达到上限后拒绝新运行。

## 5. 调试控制

推荐调试顺序：

```text
Create Run（StartPaused=true）
→ Step
→ 查看 Run Snapshot
→ 获取 Checkpoint
→ Resume
→ Advance 或 Run To Completion
→ 查看 FinalStateHash / EvidenceHash
```

接口：

- `POST runs/{runId}/step`：执行一个 Timeline Item；
- `POST runs/{runId}/pause`：暂停；
- `POST runs/{runId}/resume`：恢复为 Running；
- `POST runs/{runId}/advance`：推进至指定虚拟 Offset；
- `POST runs/{runId}/speed`：修改 SpeedFactor；
- `POST runs/{runId}/run`：执行至终态；
- `POST runs/{runId}/cancel`：取消；
- `GET runs/{runId}/checkpoint`：生成 Checkpoint。

终态运行不能再次 Step、Resume 或 Run，返回 409。

## 6. 确定性回放

```text
POST /api/simulation/scenarios/replay
```

服务使用同一治理版本和场景内容执行两次，SpeedFactor 分别为 1 和 100。

通过条件：

```text
FirstEvidenceHash == SecondEvidenceHash
AND FirstStateHash == SecondStateHash
AND Assertions 完全相同
```

不一致返回 409，必须检查 Handler 是否使用系统时间、未治理随机数、非确定性集合遍历或外部可变数据。

## 7. Checkpoint 处理

Checkpoint 是不可变证据，不允许手工修改。恢复前必须校验：

- ScenarioId；
- Version；
- ManifestHash；
- Seed；
- CheckpointHash；
- StateJson；
- Timeline Index；
- Random State。

跨版本 Checkpoint 必须拒绝。

## 8. 常见错误

| 现象 | 原因 | 处理 |
|---|---|---|
| API 404 | 环境或双开关不满足 | 核对 Simulation 环境和配置 |
| Create Run 404 | 治理版本未登记 | 先调用 S0 Validate/Register |
| Create Run 400 | 内容 SHA 不一致或 DSL 非法 | 使用登记时完全相同的 UTF-8 内容 |
| Step/Run 409 | Run 已终态或已取消 | 新建 Run |
| Assertion Failed | Expected 与隔离状态不一致 | 查看 AssertionOutcome 和 Evidence |
| Replay 409 | 出现非确定性行为 | 检查时间、随机数、集合顺序和外部依赖 |
| Registry Capacity | 运行数量达到上限 | 重启隔离 Simulation Host 或提高已验收上限 |

## 9. 安全要求

- 不使用真实 PLC 地址、账号、密钥、拓扑或现场数据；
- 不在 Handler 中直接调用 PLC Write、任务取消、路权释放、车辆选择或派单；
- 不用仿真结果替代安全联锁和现场验收；
- 仿真 Host 与生产 SQL、PLC 网络必须隔离；
- 导出的 Evidence 需记录 exact Head、场景版本、Seed、ManifestHash 和 Artifact Digest。

## 10. 回退

```text
SimulationGovernance__Enabled=false
Simulator__Enabled=false
```

关闭后确认 API 不可见、运行线程结束、控制写入为 0。S1 当前全部状态只在进程内，Host 重启后 RunRegistry 清空；持久化运行仓库不属于 S1。
