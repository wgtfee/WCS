# EMS/RGV 测试计划与验收规范

## 1. 目标

建立从单元测试、集成测试、联调测试、性能测试、故障演练到现场验收的统一质量标准。

## 2. 测试层级

| 层级 | 目标 | 环境 |
|---|---|---|
| 单元测试 | 算法、状态机、幂等、版本和安全规则 | CI |
| 组件测试 | Core 服务组合与内存存储 | CI |
| Host 构建/接口测试 | DI、Controller、配置和 Health | CI/测试环境 |
| Desktop 构建/UI 冒烟 | ViewModel、XAML、API 客户端 | CI/测试环境 |
| PLC 联调 | 点位、心跳、命令和回执 | 现场或仿真 PLC |
| 系统集成 | MES/WMS、SQL、Host、Desktop、PLC | 集成环境 |
| 性能容量 | 吞吐、等待、CPU、内存、数据库 | 隔离测试环境 |
| 故障恢复 | 断线、重启、残留、备份和回退 | 测试/现场窗口 |
| 现场验收 | 实车和生产流程 | 生产现场 |

## 3. CI 验收

每次发布到 `develop` 至少执行：

```powershell
dotnet restore src/Wcs.Core.Tests/Wcs.Core.Tests.csproj
dotnet build src/Wcs.Core.Tests/Wcs.Core.Tests.csproj -c Release --no-restore
dotnet test src/Wcs.Core.Tests/Wcs.Core.Tests.csproj -c Release --no-build

dotnet restore src/Wcs.Host/Wcs.Host.csproj
dotnet build src/Wcs.Host/Wcs.Host.csproj -c Release --no-restore

dotnet restore src/Wcs.Desktop/Wcs.Desktop.csproj
dotnet build src/Wcs.Desktop/Wcs.Desktop.csproj -c Release --no-restore
```

通过标准：0 编译错误、0 测试失败。

## 4. Core 测试范围

必须覆盖：

- 车辆注册和版本拒绝；
- 候选车辆筛选和排序；
- RequestId 幂等；
- 路段原子预留；
- 租约续约和过期；
- 物理占用保护；
- 执行状态机；
- 乱序位置反馈拒绝；
- PLC 命令序号相关；
- 心跳超时；
- 启动恢复；
- 三方冲突；
- 配置乐观锁；
- 双人审批；
- 点位导入；
- 单点联调；
- 动态优先级；
- 站点和单轨；
- 故障接管；
- Trace 和 Metrics；
- 备份校验；
- 隔离演练；
- 仿真确定性；
- 容量安全门槛；
- 生产队列纯快照。

## 5. 功能测试

### 5.1 正常流程

- 单车单任务；
- 多车并行；
- 多站点；
- 装载和卸载；
- 任务完成和资源释放。

### 5.2 边界流程

- 无可用车辆；
- 无路径；
- 路权冲突；
- 站点满载；
- 低电量；
- 单轨反向等待；
- 重复 RequestId；
- 配置版本冲突。

### 5.3 异常流程

- PLC 拒绝；
- 命令超时；
- 心跳冻结；
- 状态序号乱序；
- 数据库不可用；
- Host 重启；
- 车辆故障；
- 物理占用残留。

## 6. PLC 测试

每台车辆至少验证：

1. 心跳；
2. 在线/离线；
3. 节点读取；
4. 状态读取；
5. 命令码写入；
6. 序号写入；
7. 请求位；
8. 确认序号；
9. 接收位；
10. 完成位；
11. 故障码；
12. 断线重连；
13. 重启后对账。

## 7. 交通安全测试

- 同一区段互斥；
- 滚动窗口；
- 追车安全间隔；
- 路口冲突矩阵；
- 单轨同向容量；
- 相向等待；
- 方向老化切换；
- 死锁检测；
- 无物理占用时安全解除；
- 有物理占用时禁止解除。

## 8. 恢复测试

### 8.1 重启场景

- 无活动任务；
- 等待任务；
- 已派单未发送；
- 已发送未确认；
- 已确认未完成；
- 已装载；
- 物理占用；
- 任务已完成但数据库未更新。

### 8.2 通过标准

- 不重复下发运动命令；
- 不丢失物理占用；
- 不自动恢复不确定任务；
- 差异可在报告中定位；
- 人工处置有审计。

## 9. 性能测试

指标：

- API 响应；
- 派单周期耗时；
- PLC 响应；
- 队列等待；
- 每小时完成任务；
- CPU、内存、GC；
- SQL 响应和连接数；
- Trace 和日志开销。

测试必须在隔离环境进行，容量仿真不得突破安全门槛。

## 10. 安全测试

- 未认证访问；
- 无权限危险操作；
- 申请人自审批；
- OperationId 重放；
- TargetId 篡改；
- 配置版本冲突；
- 备份路径越界；
- 备份载荷篡改；
- 超大仿真请求；
- 任意 PLC 地址写入尝试。

## 11. 验收等级

### 11.1 软件研发验收

- CI 全通过；
- 文档齐全；
- 功能和安全测试通过；
- 已知问题有记录。

### 11.2 集成验收

- MES/WMS、数据库、Host、Desktop 和 PLC 联通；
- 端到端流程通过；
- 故障场景通过。

### 11.3 现场验收

- 实车空载和带载；
- 全拓扑覆盖；
- 交通安全；
- 急停和恢复；
- 生产任务连续运行；
- 备份和回退；
- 联合签署。

## 12. 缺陷等级

| 等级 | 定义 | 上线规则 |
|---|---|---|
| P0 | 人身/设备安全或数据严重破坏 | 禁止上线 |
| P1 | 核心任务无法完成、可能双写/重复运动 | 禁止上线 |
| P2 | 重要功能异常、有可控替代方案 | 原则上修复后上线 |
| P3 | 一般功能或界面问题 | 可带条件上线 |
| P4 | 建议和优化 | 进入后续计划 |

## 13. 测试证据

每个关键场景保留：

- 测试编号；
- 版本/Commit；
- 配置和点位版本；
- 前置条件；
- 输入；
- 预期；
- 实际；
- TraceId；
- 日志/截图；
- 结论；
- 测试人和复核人。
