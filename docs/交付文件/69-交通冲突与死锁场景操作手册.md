# 交通冲突与死锁场景操作手册

## 1. 适用范围

本文用于在 `Simulation` 或 `SimulationLoadTest` 环境中编写 S4 冲突域、预约、等待图和死锁场景。

S4 所有处置只改变仿真会话状态，不连接真实车辆、PLC 或生产调度执行链。

## 2. 启动条件

```text
Simulator.Enabled=true
SimulationGovernance.Enabled=true
Environment=Simulation 或 SimulationLoadTest
```

Production 和非批准环境的 `/api/simulation/**` 必须返回 404。

## 3. 推荐场景顺序

```text
定义 S3 区段
→ 定义 S3 车辆
→ 可选分配显式路线
→ 定义 S4 冲突域
→ 申请预约或滚动预约
→ 形成冲突与等待请求
→ 验证等待图
→ 检测死锁
→ 验证受害者
→ 仿真内处置
→ 验证释放、再授权和死锁清除
→ Checkpoint / Replay
```

## 4. 定义冲突域

```json
{
  "Id": "zone-z1",
  "AtMilliseconds": 0,
  "Order": 10,
  "Kind": "traffic.zone.define",
  "Target": "Z1",
  "Payload": {
    "SegmentIds": ["S1", "S1-REVERSE"],
    "Capacity": 1,
    "Kind": "OpposingDirection"
  }
}
```

支持：`SharedSegment`、`OpposingDirection`、`Merge`、`Intersection`、`Custom`。

要求：

- 区段必须已由 S3 定义；
- 一个区段只能属于一个冲突域；
- 单冲突域最多 16 段；
- 容量必须大于 0。

## 5. 申请单段预约

```json
{
  "Id": "reserve-rgv-01",
  "AtMilliseconds": 0,
  "Order": 20,
  "Kind": "traffic.reserve",
  "Target": "RGV-01",
  "Payload": {
    "SegmentId": "S1",
    "Priority": 10,
    "LeaseMilliseconds": 60000
  }
}
```

预约结果包含 `Granted`、活动预约或等待请求，以及阻塞车辆列表。

## 6. 释放预约

```json
{
  "Id": "release-rgv-01",
  "AtMilliseconds": 1000,
  "Order": 0,
  "Kind": "traffic.release",
  "Target": "RGV-01",
  "Payload": {
    "SegmentId": "S1"
  }
}
```

释放后等待请求按 Priority、Sequence、VehicleId 重新评估。

## 7. 预约租约到期

```json
{
  "Id": "expire-reservations",
  "AtMilliseconds": 60000,
  "Order": 0,
  "Kind": "traffic.expire",
  "Target": "all",
  "Payload": {}
}
```

到期只依据虚拟时间。场景必须显式执行 `traffic.expire`，仅经过虚拟时间不会自动扫描状态。

## 8. 滚动预约

```json
{
  "Id": "rolling-reserve-rgv-01",
  "AtMilliseconds": 0,
  "Order": 30,
  "Kind": "traffic.rolling.reserve",
  "Target": "RGV-01",
  "Payload": {
    "LookAheadSegments": 3,
    "Priority": 10,
    "LeaseMilliseconds": 60000
  }
}
```

从 S3 车辆当前 `RouteIndex` 开始申请，遇到首个冲突即停止。

车辆推进后释放已通过区段：

```json
{
  "Id": "rolling-release-rgv-01",
  "AtMilliseconds": 2000,
  "Order": 10,
  "Kind": "traffic.rolling.release",
  "Target": "RGV-01",
  "Payload": {}
}
```

## 9. 死锁检测

```json
{
  "Id": "detect-deadlock",
  "AtMilliseconds": 3000,
  "Order": 0,
  "Kind": "traffic.deadlock.detect",
  "Target": "all",
  "Payload": {}
}
```

典型两车循环：

```text
RGV-01 持有 Z1，等待 Z2（由 RGV-02 持有）
RGV-02 持有 Z2，等待 Z1（由 RGV-01 持有）
```

## 10. 仿真内处置

```json
{
  "Id": "resolve-deadlock",
  "AtMilliseconds": 3100,
  "Order": 0,
  "Kind": "traffic.deadlock.resolve",
  "Target": "DL-000000000007",
  "Payload": {}
}
```

目标必须是检测动作产生的 DeadlockId。处置不会移动车辆、修改路线、取消生产任务或释放现场路权。

## 13. 常见错误

- `segment is not assigned to a traffic zone`：区段未加入冲突域；
- `zone is already defined`：重复定义冲突域；
- `segment already belongs to a traffic zone`：一个区段被重复映射；
- `MaximumZones` / `MaximumReservations` / `MaximumWaitingRequests`：容量已满；
- `reservation lease is outside the configured limit`：租约超出限制；
- `deadlock is already resolved`：重复处置；
- DeadlockId 不存在：检测动作尚未执行或 ID 计算错误。

## 14. Checkpoint 与 Replay

建议在以下位置创建 Checkpoint：

- 两车分别持有不同冲突域；
- 一方已等待、另一方尚未等待；
- 循环等待已形成但尚未检测；
- 死锁已检测但尚未处置；
- 处置完成后。

恢复后继续执行，应得到相同等待图、受害者、释放结果、审计顺序和 FinalStateHash。

## 15. 验收边界

仓库必须完成两轮最新 exact Head 的 35/35。即使仓库全绿，也不代表真实车辆制动、机械互锁、现场通信、路权安全或 HIL 已验收。
