# Wcs.Desktop AtomUI 常用页面第一批迁移说明

## 1. 范围

本批以 `develop` 为基线，先迁移最高频的运输调度与交通控制页面：

- `/TransportScheduling` — EMS / RGV 调度中心；
- `/TransportTraffic` — 交通控制与死锁。

本批仅修改 Desktop 表现层与 AtomUI 门禁，不修改 PLC、CommandBus、TaskScheduler、TaskOrchestrator、Dispatch、Traffic、RouteReservation 或 IDI 自动化权限。

## 2. AtomUI 组件

两个页面均迁移为：

- `Card` + `Statistic` KPI；
- `Button` 操作；
- `TabControl / TabItem`；
- `DataGrid / DataGridTextColumn / DataGridCheckBoxColumn`；
- 复用 `AtomUIProductStyles.axaml` 的页面标题、副标题与状态文本规范。

Avalonia `Grid / StackPanel / UniformGrid` 继续作为布局容器。

## 3. 行为保持

### TransportScheduling

保留原 ViewModel、Command 与绑定：车辆状态、执行任务、路段预留、刷新行为不变。

### TransportTraffic

保留原资源定义、资源占用、等待关系、死锁检测、处置记录与刷新行为。页面迁移不改变交通控制算法与死锁处置语义。

## 4. CI

`WCS Desktop AtomUI Productization` 从 4 页扩展到 6 页，新增两个页面的 AtomUI namespace、Card、Statistic、Button、TabControl、DataGrid 检查，并继续禁止这些已迁移页面回退为 Avalonia 原生 Button/TextBox/DataGrid/TabControl。

## 5. 后续

下一批继续按优先级迁移：

1. TransportProduction；
2. TransportObservability；
3. TransportResilience；
4. Device / Task / Alarm / Event Log；
5. TransportCommissioning / DriverDiagnostics / Administration；
6. 其余页面与 MainWindow Shell / Navigation。
