# 外部依赖故障场景开发与调试操作手册

## 1. 适用范围

本文用于 Simulation & Verification S5 的 MES、SQL Server、HTTP、Network 与 Custom 外部依赖故障场景开发、调试和证据采集。

S5 仅在 `Simulation`、`SimulationLoadTest` 且 Governance 允许时工作。Production 不得开启，也不得把本手册中的仿真 Endpoint 当成真实生产地址。

## 2. 基础配置

```json
{
  "SimulationVirtualExternal": {
    "MaximumEndpoints": 256,
    "MaximumFaults": 2048,
    "MaximumRequests": 10000,
    "MaximumAuditRecords": 5000,
    "MaximumRetryAttempts": 16,
    "DefaultTimeoutMilliseconds": 5000,
    "MaximumDelayMilliseconds": 86400000,
    "CircuitFailureThreshold": 3,
    "CircuitOpenMilliseconds": 30000
  }
}
```

LoadTest 可提高容量，但所有值仍受 `VirtualExternalOptions.Validate()` 的硬边界保护。

## 3. 推荐场景编排顺序

典型顺序：

```text
1. external.endpoint.define
2. external.fault.apply
3. external.request.invoke
4. assertions
5. external.fault.clear / virtual-time advance
6. recovery request
7. assertions
8. checkpoint / replay / final hash verification
```

一个场景中使用稳定、可读的 EndpointId、FaultId、RequestId/ActionId、IdempotencyKey 和 PayloadHash。不要写入真实 URL、连接字符串、Token、密码或未脱敏生产报文。

## 4. Action 使用说明

### 4.1 external.endpoint.define

定义虚拟依赖，Target 为 EndpointId，Kind 为 `Mes`、`SqlServer`、`Http`、`Network` 或 `Custom`。

### 4.2 external.fault.apply

定义一个有虚拟时间窗的故障。常用字段：

- FaultId
- EndpointId/Target
- Kind
- StartsAtOffsetMilliseconds
- EndsAtOffsetMilliseconds
- HttpStatusCode
- DelayMilliseconds
- ErrorCode

Fault 时间窗必须确定，不依赖真实墙钟。

### 4.3 external.request.invoke

调用虚拟 Endpoint。常用字段：

- Operation
- IdempotencyKey
- PayloadHash
- MaxAttempts
- TimeoutMilliseconds
- RetryDelayMilliseconds

`MaxAttempts` 不得超过 `MaximumRetryAttempts`。PayloadHash 只用于确定性业务输入标识，不存真实敏感 Payload。

### 4.4 external.fault.clear

提前清除 Fault，用于验证恢复路径。

### 4.5 external.circuit.reset

显式重置仿真熔断器，仅用于测试场景。它不是生产运维 API，也不会修改真实服务熔断状态。

## 5. Assertion

### external.request.state

验证最终请求状态：Succeeded、Failed、TimedOut 或 RejectedByCircuit。

### external.request.attempts

验证 Attempt 数量，适合重试策略和故障恢复测试。

### external.circuit.state

验证 Closed/Open/HalfOpen。

### external.fault.active

验证指定虚拟偏移上 Fault 是否生效。

建议同时断言状态与 Attempt 数，避免只看最终成功而漏掉错误的重试次数。

## 6. 推荐场景模板

### 6.1 MES 超时后重试成功

```text
define MES endpoint
apply Timeout fault in [0, 1000)
invoke request with bounded attempts and retry delay
advance virtual timeline beyond fault window
assert request state / attempts
```

### 6.2 SQL Deadlock

```text
define SqlServer endpoint
apply SqlDeadlock
invoke idempotent write operation
assert failed/retried attempts
clear fault
invoke again
assert success
```

这里只模拟 SQL Deadlock 结果，不创建真实 SQL Connection 或事务。

### 6.3 熔断 Open/HalfOpen/恢复

连续制造达到阈值的失败，验证 Open；将虚拟偏移推进至 `CircuitOpenUntilOffsetMilliseconds` 后发起探测，验证 HalfOpen，并分别覆盖成功关闭与失败重新 Open。

### 6.4 幂等重复请求

第一次成功请求使用固定 IdempotencyKey；第二次使用同 Endpoint/Key 重放，断言 `IdempotencyReplayed=true` 且 Request 记录没有重复增长。

### 6.5 网络高延迟/丢包

分别用 HighLatency 与 PacketLoss；高延迟用 `DelayMilliseconds` 与 Timeout 组合测试临界值，丢包测试重试与熔断计数。

## 7. 只读检查 API

```text
GET /api/simulation/virtual-external/runs/{runId}/status
GET /api/simulation/virtual-external/runs/{runId}/endpoints
GET /api/simulation/virtual-external/runs/{runId}/endpoints/{endpointId}
GET /api/simulation/virtual-external/runs/{runId}/faults
GET /api/simulation/virtual-external/runs/{runId}/faults/{faultId}
GET /api/simulation/virtual-external/runs/{runId}/requests
GET /api/simulation/virtual-external/runs/{runId}/requests/{requestId}
GET /api/simulation/virtual-external/runs/{runId}/audit?take=100
```

API 只检查活动 Run 的 Checkpoint 快照，不提供直接写操作。Production 或未授权环境返回 404。

## 8. Checkpoint / Replay

S5 状态在 S1 `SimulationStateStore` 中，因此无需独立快照协议。

调试确定性问题时至少比较：

- Endpoint snapshots；
- Fault snapshots；
- Request/Attempt snapshots；
- Circuit 状态；
- Audit sequence；
- OperationSequence；
- FinalStateHash。

相同 Scenario、Seed、初始状态和操作顺序必须得到相同结果。若 Hash 不同，优先排查墙钟、随机源、无序集合遍历、浮点时间计算或外部 I/O。

## 9. CI Evidence

S5 三条正式工作流：

```text
.github/workflows/simulation-external-failures.yml
.github/workflows/simulation-external-determinism.yml
.github/workflows/simulation-s5-full-regression.yml
```

验收时必须记录：

- exact Head SHA；
- Run ID / Run number；
- status / conclusion；
- Artifact Name / ID；
- Artifact expired=false；
- Artifact SHA-256 Digest；
- Full Regression `workflowCount=37`；
- `allSuccess=true`；
- 37 child 全部 exact-head；
- PR Head expected == actual。

## 10. 常见问题

### 10.1 场景结果偶发不同

检查是否引入 `DateTime.Now/UtcNow`、真实睡眠、随机源、真实外部 I/O 或不稳定枚举顺序。S5 Runtime 不允许这些依赖。

### 10.2 SqlCommandTimeout 被隔离扫描误报

静态规则应检测真实 SQL Provider/Connection，而不是使用会误中枚举名的裸 `SqlCommand` Token。不得因此删除 SQL 隔离检查。

### 10.3 Production 能访问 API

这是阻断级问题。检查 Environment、`Simulator:Enabled`、`SimulationGovernance:Enabled`、AllowedEnvironments 和 `SimulationBoundaryGuard`；在修复前不得验收。

### 10.4 请求数量持续增长

检查 IdempotencyKey 是否稳定，以及场景是否错误地每次生成不同业务键。`MaximumRequests` 是保护上限，不是用来掩盖重复业务请求的手段。

## 11. 现场边界

S5 通过只表示软件仿真层对外部依赖异常具备确定性验证能力。真实 MES、SQL Server、网络基础设施、PLC、RGV 和机械系统仍需独立集成、HIL、FAT/SAT 与安全验收。
