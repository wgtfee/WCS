# EMS/RGV 性能容量、仿真与调优指南

## 1. 目标

本文说明如何使用指标、历史回放、离线仿真、策略 A/B 和容量基线评估系统能力，并在不影响生产控制的前提下调整参数。

## 2. 性能指标

### 2.1 业务指标

- 每小时完成任务数；
- 平均等待时间；
- P95 等待时间；
- 交期违约率；
- 失败任务率；
- 最大队列长度；
- 站点拥堵时间；
- 单轨等待时间；
- 车队利用率。

### 2.2 技术指标

- 派单周期耗时；
- 路径计算耗时；
- PLC 读取和命令响应时间；
- API P95/P99；
- CPU、内存和 GC；
- SQL 查询和写入；
- 日志与 Trace 开销；
- 后台周期漂移。

## 3. 仿真场景

来源：

```text
Manual
CurrentSnapshot
HistoricalReplay
CapacityStress
```

场景包含任务、车辆、站点、交通资源、时间窗口、Seed 和故障窗口。

## 4. 确定性

相同场景、策略和 Seed 必须产生相同结果。命令失败样本使用固定哈希输入，确保不同策略共享相同故障样本。

## 5. 内置策略

| 策略 | 重点 |
|---|---|
| BaselineDynamicPriority | 当前生产动态优先级 |
| AgingFirst | 防止长时间等待 |
| DeadlineFirst | 优先交期紧迫任务 |
| CongestionAware | 降低拥堵站点和资源压力 |
| BalancedBatch | 相同目的地批量与综合平衡 |

## 6. 策略 A/B

同一场景比较 2～10 个策略。排序依据：

1. 目标得分；
2. 吞吐；
3. P95 等待。

报告至少包含：

- RunId；
- 策略参数；
- 完整指标；
- 相对基准变化；
- 推荐策略；
- 风险和解释。

推荐不得自动应用。

## 7. 容量基线

输入：

- 仿真时长；
- 车辆数量集合；
- 任务率集合；
- 重复次数；
- 车辆类型；
- 策略；
- Seed。

输出：

- 最大可持续任务率；
- 达到峰值所需最少车辆数；
- 到达任务数；
- 观察窗截止前完成任务数；
- 观察窗截止时未清任务数；
- 真实执行失败数；
- P95 等待；
- 违约率；
- 利用率；
- 可持续结论。

容量基线使用“到达观察窗 + 排空计算”。任务只在观察窗内到达，窗口截止后继续计算已到达任务直至完成或真实失败。吞吐和利用率按观察窗统计；P95 等待和交期违约按排空后的完整结果统计。截止时仍在排队或执行的任务属于未清任务，不属于失败任务。

## 8. 默认可持续门槛

```text
P95 等待 <= 120 秒
交期违约率 <= 5%
失败任务数 = 0
```

项目应根据工艺节拍和缓存容量调整。高负载即使最终可以排空，也会因等待时间或交期违约超限而判为不可持续。

## 9. 资源安全门槛

生产 Host 上执行仿真时必须遵守：

```text
单场景任务数 <= 5,000
单场景车辆数 <= 1,000
仿真窗口 <= 30 天
任务数 × 预测桶 <= 5,000,000
容量网格 <= 200 组合
单点车辆数 <= 200
任务率 <= 10,000/h
单容量点任务数 <= 5,000
总估算任务数 <= 250,000
并发容量基线 = 1
```

更大规模应在独立离线仿真进程或专用测试机执行。

## 10. 调优顺序

建议顺序：

1. 修复车辆离线、位置和命令异常；
2. 修复拓扑和路权配置；
3. 检查站点容量和下游节拍；
4. 调整派单周期和最大每周期派单数；
5. 调整最低派单电量；
6. 调整等待老化；
7. 调整交期权重；
8. 调整拥堵惩罚；
9. 调整单轨方向切换；
10. 评估车辆数量或物理改造。

不要先通过提高优先级权重掩盖设备或站点能力不足。

## 11. 动态优先级调优

### 等待任务长期饥饿

提高 AgingWeight 或缩短老化周期。

### 紧急任务延误

提高 DeadlineWeight，但观察普通任务 P95 和饥饿情况。

### 站点反复满载

提高 CongestionPenalty 只能缓解入口压力；根因可能是下游节拍或容量不足。

### 恢复任务抢占过多

降低 RecoveryWeight，并确认恢复任务是否被正确分类。

## 12. 单轨调优

关注：

- 同向容量；
- 反向等待阈值；
- 清场时间；
- 方向切换频率；
- 物理占用反馈延迟。

方向频繁切换会降低吞吐；单向持续过久会造成反向饥饿。应通过历史回放和现场验证找到平衡。

## 13. PLC 性能

优化优先级：

1. 批量读取；
2. 合理轮询周期；
3. 只读取必要点位；
4. 不在日志中写完整高频载荷；
5. 每车命令串行、车辆间并行；
6. 调整超时前先测量真实 PLC 响应分布。

## 14. 数据库性能

- 活动状态使用业务键 Upsert；
- Journal 查询限制数量和时间窗口；
- 为 Category、RecordId、OccurredAtUtc 建索引；
- 清理历史前先归档；
- 不在调度热路径执行报表聚合；
- 监控连接池和长事务。

## 15. 现场容量验证

离线仿真通过后，现场按阶梯增加流量：

```text
10%
→ 25%
→ 50%
→ 75%
→ 目标负载
```

每一级确认：

- 无安全异常；
- P95 在门槛内；
- 队列可回落；
- PLC 响应稳定；
- CPU/内存/SQL 有余量；
- 无持续人工干预。

## 17. 参数变更要求

任何生产调优必须：

- 有基线数据；
- 有离线对比；
- 有预期收益和风险；
- 有回退参数；
- 有 ChangeConfiguration 审批；
- 小流量验证；
- 观察期记录。
