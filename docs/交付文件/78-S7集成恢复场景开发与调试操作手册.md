# S7 集成恢复场景开发与调试操作手册

## 1. 使用范围

本手册用于开发和调试 Simulation & Verification S7 集成恢复场景。S7 仅运行在 `Simulation` / `SimulationLoadTest`，不得用于 Production 控制。

## 2. 场景基本结构

典型场景顺序：

```text
integration.mission.define
integration.mission.dispatch
integration.mission.advance
integration.mission.advance
integration.mission.ack
integration.mission.ack   # 验证幂等重放
```

随后使用断言：

```text
integration.mission.state
integration.mission.consistent
integration.external.exactly-once
```

## 3. Mission 定义

`integration.mission.define` 的 Payload 主要字段：

```json
{
  "PlcBlockKey": "PLC1.DB100",
  "VehicleId": "RGV1",
  "LoadId": "LOAD1",
  "SourceNodeId": "N1",
  "DestinationNodeId": "N3",
  "ExternalEndpointId": "MES1",
  "ExternalSystemKind": "Mes",
  "HealthAssetId": "ASSET1",
  "Priority": 100,
  "VehicleSpeedMillimetersPerSecond": 1000,
  "VehicleBatteryPercent": 100,
  "InitialHealthScore": 95,
  "InitialFusionRiskScore": 0.05,
  "Segments": [
    {
      "SegmentId": "S1",
      "FromNodeId": "N1",
      "ToNodeId": "N2",
      "LengthMillimeters": 1000,
      "SpeedLimitMillimetersPerSecond": 1000
    },
    {
      "SegmentId": "S2",
      "FromNodeId": "N2",
      "ToNodeId": "N3",
      "LengthMillimeters": 1000,
      "SpeedLimitMillimetersPerSecond": 1000
    }
  ]
}
```

要求：

- Segment ID 不得重复；
- 路线必须拓扑连续；
- 首段起点与 `SourceNodeId` 一致；
- 末段终点与 `DestinationNodeId` 一致；
- Segment 数量不能超过 S7 和 S4 rolling look-ahead 上限。

## 4. 调试 Mission 生命周期

### Defined

检查：PLC Block、Segments、Vehicle、Traffic Zones、External Endpoint、Health Asset 是否都已创建。

### Dispatched

检查：

- PLC request flag = 1；
- RGV 已加载；
- RGV Route 与 Mission Segments 一致；
- 全路线 Reservation 已成功。

### Moving / Completed

推进虚拟时间后检查：

- passed reservation 是否释放；
- 最终 Vehicle 是否到目标节点；
- 是否已 unload；
- completion flag 是否写入仿真 PLC；
- 是否无残留 reservation/waiting。

### Acknowledged

检查：

- External Request 成功；
- IdempotencyKey 使用 MissionId；
- 重复 ack 不新增第二条 Request；
- Health `CensoredNoFailure` Outcome 只有一条；
- PLC ack flag = 1。

## 5. Checkpoint 恢复验证

推荐步骤：

1. 创建 Session；
2. 运行到中间 offset；
3. `CreateCheckpoint()`；
4. 用同一 Scenario + Checkpoint 创建新 Session；
5. 运行到完成；
6. 与不中断运行比较：
   - `FinalStateHash`
   - `EvidenceHash`
   - Assertions

必须完全一致。

## 6. Canonical StateJson 恢复

可使用：

```text
state.ToCanonicalJson()
SimulationStateStore.FromCanonicalJson(...)
state.ComputeHash()
```

恢复前后执行相同后续动作，最终 canonical JSON 和 Hash 必须一致。

## 7. Replay

使用 `ReplayTwiceAsync`。同一 Scenario、Manifest、Seed 和虚拟输入不得因速度倍率、Runner 或执行时刻不同而改变：

- StateHash
- EvidenceHash
- Assertion outcomes

S7 Runtime 禁止墙钟等待和非确定性随机源。

## 8. 只读 API

```text
GET /api/simulation/virtual-integration/runs/{runId}/status
GET /api/simulation/virtual-integration/runs/{runId}/missions
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}/consistency
GET /api/simulation/virtual-integration/runs/{runId}/audit?take=100
```

如果 Run 已经 terminal，现有 `SimulationRunRegistry` 不允许再创建 Checkpoint；需要在场景中保留未来 Timeline Item，在 Mission 已 Acknowledged 但 Run 仍 active 时进行 inspection。不得为方便检查而放宽 RunRegistry 终态语义。

## 10. GitHub API 暂态失败

Full Regression 需要反复读取 Actions API。如果 Runner 出现 `error connecting to api.github.com`，且 child 本身没有失败：

- 不修改代码；
- 不降低 41-child 门槛；
- 保持同一 exact Head；
- 只重跑失败的 Full Regression job；
- 最终 Artifact 采用成功 attempt 最新上传的 ID/Digest。

## 11. Production 检查

必须确认：

```text
Environment=Production
Simulator.Enabled=false
SimulationGovernance.Enabled=false
/api/simulation/** => 404
```

S7 目录不得引用真实 HTTP/SQL/Socket/PLC/RGV 控制、生产调度或真实 Forecast 服务。

## 12. 验收流程

```text
功能代码完成
-> 13/13 + 10/10
-> 41/41 exact Functional Head
-> Artifact/Digest
-> 76~78 + 00/21 文档提交
-> Evidence Head 冻结
-> 13/13 + 10/10 + 41/41 exact Evidence Head
-> PR Conversation 回填第二轮证据
-> Ready
-> squash merge develop
-> compare merge SHA with develop
```

第二轮证据不得再写回仓库，否则会制造新的 Head 并使 Evidence Head 失效。
