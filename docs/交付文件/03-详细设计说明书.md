# EMS/RGV 统一调度详细设计说明书

## 1. 目的

本文描述统一调度核心类、接口、依赖关系、关键算法、状态变更、异常处理和扩展方式，供研发维护、代码评审和二次开发使用。

## 2. 命名空间

核心代码位于：

```text
Wcs.Core.TransportScheduling
```

主要宿主代码：

```text
Wcs.Application.HostedServices
Wcs.Host.Controllers
Wcs.Infrastructure.Persistence.Services
Wcs.Desktop.ViewModels
Wcs.Desktop.Views
```

## 3. 统一车辆模型

`TransportVehicleSnapshot` 是车辆运行状态的不可变快照，至少包括：

- `VehicleId`
- `Kind`
- `State`
- `CurrentNodeId`
- `IsOnline`
- `BatteryPercent`
- `Capabilities`
- `ActiveTaskCount`
- `Version`
- `UpdatedAtUtc`

### 3.1 Upsert 规则

1. 车辆编号不能为空。
2. 新快照版本必须大于已存在版本。
3. 同版本不得以更旧时间覆盖。
4. 业务状态切换优先通过 CAS 方法，不直接修改对象。
5. PLC 同步只更新被认可的反馈字段。

## 4. 派单设计

### 4.1 输入

`TransportDispatchRequest` 包含请求号、起点、终点、车辆类型、能力、优先级和业务属性。

### 4.2 幂等缓存

派单引擎按 `RequestId` 保存不可变派单结果。重复调用时：

- 已成功：返回原分配；
- 已失败且业务仍在同一次请求上下文：返回原失败；
- 已完成并清理：由上层生成新 RequestId 再次发起。

### 4.3 候选车辆过滤

过滤条件：

```text
IsOnline = true
State = Idle
Kind 属于 AllowedVehicleKinds
Capabilities 覆盖 RequiredCapabilities
BatteryPercent >= MinimumDispatchBattery
CurrentNodeId 有效
```

### 4.4 排序

基础评分：

```text
空驶路径权重 × 100
+ 活动任务数 × 1000
+ (100 - 电量)
```

生产层会在任务进入派单前计算有效优先级，不在车辆选择器内部混入生产队列副作用。

### 4.5 原子提交

```text
计算候选路径
→ AdmissionPolicy 检查
→ TryReserve 全部资源
→ Vehicle CAS Idle→Executing
→ 保存 Assignment
```

车辆 CAS 失败时必须释放本次预留并尝试下一候选车辆。

## 5. 路权设计

### 5.1 RouteReservation

关键字段：

- `ReservationId`
- `OwnerId/RequestId`
- `ResourceIds`
- `LeaseToken`
- `ExpiresAtUtc`
- `OccupancyConfirmed`
- `LastConfirmedAtUtc`

### 5.2 原子性

预留管理器先检查所有资源，再一次性写入持有关系。不得边检查边永久占用，避免部分成功。

### 5.3 TTL 与物理占用

TTL 只适用于未确认物理占用的逻辑租约。若 `OccupancyConfirmed=true`，清理器、死锁解除和取消操作都不得直接释放。

## 6. 执行状态机

执行状态主要阶段：

```text
Created
WaitingForPickup
Loading
MovingLoaded
Unloading
Paused
Completed
Faulted
Cancelled
Suspended
```

### 6.1 创建

派单成功后通过 RequestId 创建执行快照。重复创建必须返回已有快照。

### 6.2 开始

开始操作生成取货方向的逻辑移动命令，并进入等待反馈状态。

### 6.3 位置反馈

`TransportPositionFeedback` 必须包含车辆、任务、节点、序号和时间。系统拒绝重复或乱序序号。

位置反馈处理：

1. 校验任务和车辆关系；
2. 校验反馈序号；
3. 将新节点写为可信节点；
4. 释放已经通过且无物理占用的路段；
5. 扩展滚动路权窗口；
6. 生成下一逻辑命令或保持等待。

## 7. 命令设计

### 7.1 TransportExecutionCommand

包含：

- `CommandId`
- `RequestId`
- `VehicleId`
- `CommandType`
- `Sequence`
- 目标节点/参数
- 创建时间

### 7.2 命令泵

后台命令泵每次提取待发送命令：

- 不同车辆并行；
- 同一车辆串行；
- 每车由 Driver 内部信号量保证顺序；
- 单车等待 PLC 确认不阻塞其他车辆。

### 7.3 可靠驱动

下发顺序：

```text
写命令载荷
→ 写命令序号
→ 置 CommandRequest
→ 轮询确认序号和接收位
→ 等待完成位
→ 清理请求位或进入下一命令
```

旧确认序号不得被新命令复用。

## 8. 交通控制设计

### 8.1 TrafficResource

资源类型可表示闭塞区段、路口、单轨、电梯、门禁或其他互斥设施。

### 8.2 Wait-for Graph

当任务等待被其他所有者持有的资源时，记录等待边：

```text
WaitingOwner → HoldingOwner
```

形成环时产生死锁周期。

### 8.3 死锁解除

选择低优先级、低进度且可安全释放的受害者。若持有资源已确认物理占用，则不得自动解除，只生成报警和人工恢复项。

## 9. 生产调度设计

### 9.1 Queue Item

状态：

```text
Queued
Dispatching
Assigned
WaitingForStation
WaitingForTraffic
WaitingForVehicle
Failed
Cancelled
```

### 9.2 动态优先级

```text
EffectivePriority = BasePriority
                  + ProductionOrderPriority
                  + AgingScore
                  + DeadlineScore
                  + RecoveryScore
                  - CongestionPenalty
```

### 9.3 纯读取

`PeekQueue()` 仅返回快照，不刷新优先级、不清理终态、不改变更新时间。真实派单周期使用内部可变读取完成刷新。

## 10. 配置服务

配置服务采用乐观版本：

```text
Get current version
→ SaveAndApply(expectedVersion)
→ 版本一致则持久化并应用
→ 不一致返回冲突
```

运行配置、生产整定、点位映射、站点和单轨定义均采用版本保护。

## 11. 治理服务

危险操作生命周期：

```text
Requested
→ Approved / Rejected
→ Executing
→ Completed / Failed
```

约束：

- 申请人不能审批自己的请求；
- 审批操作类型和目标必须与执行一致；
- OperationId 只能开始一次；
- 每次状态变更形成审计记录。

## 12. 一致性巡检

比较：

- 车辆；
- 活动执行；
- 路权；
- PLC 在线、节点和命令；
- 数据库存储状态。

巡检只生成差异，不自动覆盖生产状态。

## 13. 备份和恢复准备

逻辑备份序列化配置、点位、运行快照、Journal 和基线，计算 SHA-256 后写入不可覆盖文件。

恢复准备只创建 `TransportConfigurationSnapshot`，不调用配置应用接口。

## 14. 仿真服务

仿真服务运行离散事件模型，生产状态输入均使用快照。`SafeTransportSimulationService` 在核心服务外限制场景规模、容量网格、预测桶和并发数量。

## 15. DI 设计

Core 注册内存默认实现，Infrastructure 使用 `Replace` 替换为 SQL/File 实现。装饰器按以下顺序注册：

```text
基础派单引擎
→ 可观测派单装饰器
→ 生产派单服务
→ 可观测生产派单装饰器
```

不得通过接口回指自身造成循环依赖。

## 16. 异常处理

1. 参数错误：抛出 `ArgumentException` 或返回 400。
2. 版本冲突：返回 Conflict。
3. 资源冲突：返回失败结果，不抛出进程级异常。
4. PLC 超时：命令进入失败/超时状态并持久化。
5. 后台任务异常：记录日志，等待下一周期。
6. 数据库不可用：健康和就绪进入异常，禁止自动恢复活动任务。
7. 仿真规模超限：在计算前拒绝。

## 17. 扩展规则

新增车辆类型：

1. 扩展 `TransportVehicleKind`；
2. 实现 `ITransportVehicleDriver`；
3. 增加点位模板；
4. 注册 Driver；
5. 补充选择、执行、恢复和联调测试。

新增交通准入：实现 `ITransportDispatchAdmissionPolicy`，不得直接修改统一派单引擎。

新增持久化类型：优先复用 Journal；只有需要高频查询、唯一约束或独立生命周期时才新增专用表。
