# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V1.9 |
| 对应分支 | `develop` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.5 |
| 安全原则 | 诊断配置不得替代 PLC 联锁、设备安全回路或调度状态机 |

本文汇总 Wcs.Host 的主要配置项。实际默认值以代码和 `appsettings*.json` 为准。生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AnomalyHealthScoring__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthGovernance__MesApiKey=...
```

规则、模型 Profile、Fusion Sources、PLC 点位和 MES 密钥不得以示例值提交到通用配置。生产凭据必须由环境变量或安全配置中心注入。

## 3. 数据库

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 最小权限账号；禁止明文提交 |

数据库承载任务、报警、异常生命周期、资产健康历史及 v3.5 健康事件 Journal。Telemetry Provider 切换不改变这些业务表。

## 4. Simulator 与 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 启用模拟信号并禁止真实 PLC 后台服务 | 实车现场必须 `false` |
| `WcsOptions:PlcPolling:Enabled` | PLC 轮询总开关 | 现场按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| `S7CommPlus` / `PlcModbusPolls` / `PlcOpcUaPolls` / `PlcTagPolls` | 其他驱动配置 | 密码和证书外部注入 |

## 5. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：通用报警监控与防抖规则。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 6. PLC Telemetry

| 参数 | 说明 |
|---|---|
| `Storage:Telemetry:Provider` | `Disabled`、`SqlServer`、`InfluxDb` |
| `DurabilityMode` | `Buffered` 或 `WriteAhead` |
| `ChannelCapacity` | 有界队列容量 |
| `BatchSize` / `FlushIntervalMs` | 批量写入参数 |
| `RetryDelayMs` | Provider 失败重试间隔 |
| `WalBatchSize` / `WalFlushIntervalMs` | WAL 参数 |
| `SpoolDirectory` | 本地持久化目录 |
| `Site` / `Measurement` | 时序标签与 measurement |

必须监控 dropped、conservationDelta、queue、in-flight、WAL pending、目录容量和失败批次。

## 7. AnomalyDetection v1

主要参数：`Enabled`、`WindowSize`、`MinimumSamples`、`MaximumTrackedRuleSignals`、`InactiveStateRetentionSeconds`、`RelatedSampleRetentionSeconds`、`ObserveThreshold`、`WarningThreshold`、`AlarmThreshold`、连续确认次数、恢复次数和 `Rules`。

基础 `Rules` 数组保持为空，现场配置应完整覆盖。

## 8. Machine Learning v2/v2.1/v3.1

| 参数 | 说明 | 建议 |
|---|---|---|
| `Enabled` | ML 推理总开关 | 默认关闭，先 Shadow |
| `ManagementApiEnabled` | 训练、审批、激活、回滚 API | 默认关闭 |
| `ModelDirectory` | 模型和活动版本 | 持久化并备份 |
| `TrainingDirectory` | 特征和冻结数据集 | 受控 ACL |
| `MaximumTrackedWindows` | 最大活动窗口 | 结合现场规模压测 |
| `Profiles` | 模型 Profile 数组 | 通用配置为空 |

## 9. TransportCycleAnalysis v3.2

主要参数包括 `Enabled`、`MinimumBaselineCycles`、`MaximumBaselineCyclesPerContext`、`MaximumTrackedExecutions`、`MaximumCompletedCycles`、`MaximumAnomalies`、`MadMultiplier`、`MinimumMadMilliseconds`、总周期和阶段绝对保护值。

## 10. AnomalyFusion v3.3

| 参数 | 说明 |
|---|---|
| `Enabled` | Fusion 总开关，默认 `false` |
| `ChannelCapacity` | Evidence 有界队列 |
| `EvidenceRetentionSeconds` | 活动证据 TTL |
| `RecoveredEvidenceRetentionSeconds` | 已恢复证据保留 |
| `MaximumTrackedAssets` | 最大资产数 |
| `MaximumEvidencePerAsset` | 单资产证据上限 |
| `ObserveThreshold` / `WarningThreshold` / `AlarmThreshold` | 风险门槛 |
| `RecoveryThreshold` | 恢复门槛 |
| `MinimumIndependentSourcesForAlarm` | Alarm 最少独立来源，默认 2 |
| `Consecutive*Evaluations` | 防抖和恢复连续次数 |
| `Sources` | 来源权重数组，通用配置为空 |

## 11. AnomalyHealthScoring v3.4

| 参数 | 说明 |
|---|---|
| `Enabled` | 评分和历史采样总开关，默认 `false` |
| `HealthyMinimumScore` / `AttentionMinimumScore` / `DegradedMinimumScore` | 健康等级门槛 |
| `MaximumFactors` | 最大扣分解释数 |
| `HistoryProvider` | `Memory` 或 `SqlServer` |
| `SamplingIntervalSeconds` | 采样周期 |
| `MinimumScoreChangeToRecord` | 变化点门槛 |
| `MaximumUnchangedIntervalSeconds` | 心跳记录间隔 |
| `MaximumHistoryPerAsset` | 单资产历史上限 |
| `MaximumTrackedHistoryAssets` | 最大历史资产数 |
| `HistoryRetentionHours` | SQL/内存历史保留 |
| `TrendWindowSize` / `TrendChangeThreshold` | 趋势窗口与方向门槛 |
| `HistoryWriteChannelCapacity` / `HistoryWriteBatchSize` | SQL 异步写入容量 |
| `HistoryWriteRetryDelayMs` | SQL 重试间隔 |
| `HistoryMaintenanceIntervalSeconds` / `HistoryMaintenanceBatchSize` | 清理参数 |

`Memory` Provider 在 Host 重启后丢失历史；`SqlServer` Provider 支持跨重启查询。两者都只用于诊断。

## 12. AssetHealthGovernance v3.5

默认配置：

```json
{
  "AssetHealthGovernance": {
    "Enabled": false,
    "MinimumEventGrade": "Degraded",
    "ConsecutiveUnhealthyEvaluations": 3,
    "ConsecutiveRecoveryEvaluations": 3,
    "EvaluationIntervalSeconds": 10,
    "MaximumUnchangedEventIntervalSeconds": 300,
    "MaximumTrackedAssets": 10000,
    "MaximumEventsQueryCount": 1000,
    "InactiveStateRetentionSeconds": 86400,
    "EventRetentionHours": 2160,
    "MaintenanceIntervalSeconds": 3600,
    "MaintenanceBatchSize": 2000,
    "MesPushEnabled": false,
    "MesBaseUrl": "",
    "MesEndpointPath": "/api/wcs/asset-health-events",
    "MesTimeoutSeconds": 5,
    "MesPollIntervalSeconds": 2,
    "MesBatchSize": 100,
    "MesMaximumAttempts": 10,
    "MesInitialRetrySeconds": 5,
    "MesMaximumRetrySeconds": 300,
    "MesApiKeyHeader": "",
    "MesApiKey": ""
  }
}
```

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `Enabled` | 健康事件治理总开关 | 默认 `false`；依赖 v3.4 当前评分 |
| `MinimumEventGrade` | 产生正式事件的最低等级 | 建议从 `Degraded` 起步 |
| `ConsecutiveUnhealthyEvaluations` | 创建事件连续次数 | 防止瞬时波动 |
| `ConsecutiveRecoveryEvaluations` | 恢复连续次数 | 防止抖动恢复 |
| `EvaluationIntervalSeconds` | 扫描评分周期 | 1～3600 秒，须容量验证 |
| `MaximumUnchangedEventIntervalSeconds` | 不变事件心跳间隔 | 不小于评估周期 |
| `MaximumTrackedAssets` | 内存状态上限 | 高于现场资产数并留余量 |
| `MaximumEventsQueryCount` | API 最大返回数量 | 禁止无界查询 |
| `InactiveStateRetentionSeconds` | 无活动事件状态 TTL | 结合设备离线时长 |
| `EventRetentionHours` | 已恢复 Journal 保留期 | 与审计、备份策略一致 |
| `MaintenanceIntervalSeconds` / `MaintenanceBatchSize` | SQL 清理周期和批次 | 防止长事务 |
| `MesPushEnabled` | MES HTTP Outbox 开关 | 默认 `false`；现场契约验收后开启 |
| `MesBaseUrl` / `MesEndpointPath` | MES 地址与路径 | 生产 HTTPS；禁止示例地址 |
| `MesTimeoutSeconds` | 单次 HTTP 超时 | 不得无限等待 |
| `MesPollIntervalSeconds` / `MesBatchSize` | Outbox 轮询与批量 | 有界处理 |
| `MesMaximumAttempts` | 自动最大尝试次数 | 达到后进入 DeadLetter |
| `MesInitialRetrySeconds` / `MesMaximumRetrySeconds` | 指数退避范围 | 避免故障风暴 |
| `MesApiKeyHeader` / `MesApiKey` | 可选认证头和值 | 密钥只能外部注入 |

### 12.1 MES 契约与幂等

WCS 发送 `Idempotency-Key`、事件 ID 和版本。HTTP 2xx 与 409 均视为幂等成功；5xx、超时和网络错误进入指数退避；达到最大次数进入 DeadLetter，必须通过治理 API 人工重试。

MES 故障不得阻塞 PLC、任务、命令、路权或调度线程。

### 12.2 启用顺序

```text
AnomalyFusion.Enabled=true
→ AnomalyHealthScoring.Enabled=true
→ AssetHealthGovernance.Enabled=true 且 MesPushEnabled=false
→ 只读观察、阈值验收和人工治理验证
→ 联调 MES 沙箱、确认幂等与认证
→ MesPushEnabled=true
```

## 13. TransportObservability、Resilience 与 Simulation

- `TransportObservability`：Trace、Prometheus、OTLP、一致性和调度健康；
- `TransportResilience`：生产就绪、逻辑备份、恢复演练和目录治理；
- `TransportSimulation`：仿真场景、A/B、容量基线和预测上限。

它们与 AnomalyEngine 诊断评分含义不同，不得共用阈值。

## 14. API 安全

只读接口包含状态、列表、详情、历史与趋势。v3.5 的 `acknowledge`、`suppress`、`unsuppress` 和 DeadLetter `retry` 是治理写操作，必须接入项目身份授权，并保存 Actor、原因和时间。

LoadTest、MlLoadTest 等专用入口在非测试环境必须返回 404。

## 15. 变更与回退

配置变更流程：记录当前版本 → 离线回放/专项测试 → 审批 → 备份 → 变更 → 观察指标 → 必要时回退。

v3.5 回退顺序：

```text
AssetHealthGovernance__MesPushEnabled=false
→ AssetHealthGovernance__Enabled=false
```

关闭 v3.5 不影响 PLC、任务、调度、Fusion 或 v3.4 历史查询。不得通过删除 SQL Journal 表作为紧急回退手段。

## 16. 生产检查清单

- [ ] `Simulator.Enabled=false`；
- [ ] SQL、PLC、点位和模型版本已确认；
- [ ] 通用 Rules、Profiles、Sources 数组无示例泄漏；
- [ ] `AnomalyFusion.Enabled`、`AnomalyHealthScoring.Enabled` 和治理开关按顺序审批；
- [ ] `AssetHealthGovernance.Enabled=false` 为仓库生产默认；
- [ ] `AssetHealthGovernance.MesPushEnabled=false` 为仓库生产默认；
- [ ] MES URL、认证、幂等和超时经过沙箱联调；
- [ ] MES 密钥未提交 Git；
- [ ] SQL Journal 表、索引、保留期和备份已确认；
- [ ] Pending、Retrying、DeadLetter 和 LastError 已纳入监控；
- [ ] 治理 API 已接入身份权限和审计；
- [ ] 无 PLC 写入、设备停止、任务取消或调度修改；
- [ ] 现场 MES、网络、权限和投产验收已独立签署。
