# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V2.0 |
| 对应分支 | `feature/anomaly-root-cause-propagation-v3-6` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.6 |
| 安全原则 | 诊断配置不得替代 PLC 联锁、设备安全回路或调度状态机 |

本文汇总 `Wcs.Host` 的主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AnomalyHealthScoring__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthGovernance__MesApiKey=...
AssetHealthRootCause__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
```

规则、模型 Profile、Fusion Sources、PLC 点位、MES 密钥、现场根因图和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、v3.5 事件 Journal，以及 v3.6 图版本、分析快照和人工复核 Journal。Telemetry Provider 切换不改变这些业务表。

## 4. Simulator 与 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 启用模拟信号并禁止真实 PLC 后台服务 | 实车现场必须 `false` |
| `WcsOptions:PlcPolling:Enabled` | PLC 轮询总开关 | 按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| `S7CommPlus` / Modbus / OPC UA / Tag Poll | 其他驱动配置 | 密码和证书外部注入 |

## 5. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：通用报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 6. PLC Telemetry

| 参数 | 说明 |
|---|---|
| `Storage:Telemetry:Provider` | `Disabled`、`SqlServer`、`InfluxDb` |
| `DurabilityMode` | `Buffered` 或 `WriteAhead` |
| `ChannelCapacity` | 有界队列容量 |
| `BatchSize` / `FlushIntervalMs` | 批量写入参数 |
| `RetryDelayMs` | Provider 失败重试间隔 |
| `WalBatchSize` / `WalFlushIntervalMs` | WAL 参数 |
| `SpoolDirectory` | 本地持久化目录 |
| `Site` / `Measurement` | 时序标签和 measurement |

必须监控 dropped、conservationDelta、queue、in-flight、WAL pending、目录容量和失败批次。

## 7. AnomalyDetection v1

主要参数：`Enabled`、`WindowSize`、`MinimumSamples`、最大信号数、状态 TTL、关联样本保留、Observe/Warning/Alarm 门槛、连续确认、恢复次数和 `Rules`。基础 `Rules` 数组保持为空，现场配置应完整覆盖。

## 8. Machine Learning v2/v2.1/v3.1

| 参数 | 说明 | 建议 |
|---|---|---|
| `Enabled` | ML 推理总开关 | 默认关闭，先 Shadow |
| `ManagementApiEnabled` | 训练、审批、激活、回滚 API | 默认关闭 |
| `ModelDirectory` | 模型和活动版本目录 | 持久化并备份 |
| `TrainingDirectory` | 特征和冻结数据集 | 受控 ACL |
| `MaximumTrackedWindows` | 最大活动窗口 | 结合现场规模压测 |
| `Profiles` | 模型 Profile 数组 | 通用配置为空 |

## 9. TransportCycleAnalysis v3.2

主要参数包括 `Enabled`、最小基线周期数、上下文最大周期数、最大执行数、最大已完成周期和异常数、MAD 倍数，以及总周期和阶段绝对保护值。

## 10. AnomalyFusion v3.3

| 参数 | 说明 |
|---|---|
| `Enabled` | Fusion 总开关，默认 `false` |
| `ChannelCapacity` | Evidence 有界队列 |
| `EvidenceRetentionSeconds` | 活动证据 TTL |
| `RecoveredEvidenceRetentionSeconds` | 恢复证据保留 |
| `MaximumTrackedAssets` | 最大资产数 |
| `MaximumEvidencePerAsset` | 单资产证据上限 |
| Observe/Warning/Alarm/Recovery | 融合和恢复门槛 |
| `MinimumIndependentSourcesForAlarm` | Alarm 最少独立来源，默认 2 |
| `Consecutive*Evaluations` | 防抖和恢复连续次数 |
| `Sources` | 来源权重数组，通用配置为空 |

## 11. AnomalyHealthScoring v3.4

| 参数 | 说明 |
|---|---|
| `Enabled` | 评分和历史采样总开关，默认 `false` |
| Healthy/Attention/Degraded MinimumScore | 健康等级门槛 |
| `MaximumFactors` | 最大扣分解释数 |
| `HistoryProvider` | `Memory` 或 `SqlServer` |
| `SamplingIntervalSeconds` | 采样周期 |
| `MinimumScoreChangeToRecord` | 变化点门槛 |
| `MaximumUnchangedIntervalSeconds` | 心跳记录间隔 |
| `MaximumHistoryPerAsset` | 单资产历史上限 |
| `MaximumTrackedHistoryAssets` | 最大历史资产数 |
| `HistoryRetentionHours` | 历史保留时间 |
| Trend 参数 | 窗口和方向门槛 |
| HistoryWrite 参数 | SQL 有界异步写入、批次和重试 |
| HistoryMaintenance 参数 | SQL 清理周期和批次 |

`Memory` Provider 在 Host 重启后丢失历史；`SqlServer` Provider 支持跨重启查询。两者只用于诊断。

## 12. AssetHealthGovernance v3.5

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `Enabled` | 健康事件治理总开关 | 默认 `false`；依赖 v3.4 |
| `MinimumEventGrade` | 正式事件最低等级 | 建议从 `Degraded` 起步 |
| Consecutive Unhealthy/Recovery | 创建和恢复连续次数 | 抑制抖动 |
| `EvaluationIntervalSeconds` | 扫描评分周期 | 1～3600 秒并压测 |
| `MaximumUnchangedEventIntervalSeconds` | 活动事件心跳 | 不小于评估周期 |
| `MaximumTrackedAssets` | 内存状态上限 | 高于现场资产数并留余量 |
| `MaximumEventsQueryCount` | API 返回上限 | 禁止无界查询 |
| Retention/Maintenance | Journal 保留和清理 | 与审计备份一致 |
| `MesPushEnabled` | MES Outbox 开关 | 默认 `false` |
| MES URL/Path/Timeout | HTTP 契约参数 | 生产 HTTPS，禁止示例地址 |
| MES Batch/Attempts/Retry | 有界批次、DeadLetter、指数退避 | 防止故障风暴 |
| MES API Key | 可选认证头和值 | 密钥只允许外部注入 |

MES 2xx 和 409 视为幂等成功；5xx、超时和网络错误重试。MES 故障不得阻塞 PLC、任务、命令、路权或调度线程。

## 13. AssetHealthRootCause v3.6

仓库默认配置：

```json
{
  "AssetHealthRootCause": {
    "Enabled": false,
    "EvaluationIntervalSeconds": 10,
    "CorrelationWindowSeconds": 300,
    "MaximumPropagationDepth": 6,
    "MaximumGraphNodes": 20000,
    "MaximumGraphEdges": 50000,
    "MaximumEventsPerAnalysis": 200,
    "MaximumCandidates": 10,
    "MaximumPaths": 100,
    "MaximumAnalysesQueryCount": 1000,
    "MinimumCandidateConfidence": 0.25,
    "AllowCycles": false,
    "AnalysisRetentionHours": 2160,
    "MaintenanceIntervalSeconds": 3600,
    "MaintenanceBatchSize": 2000,
    "Graph": {
      "Version": "",
      "Source": "",
      "ApprovedBy": "",
      "ApprovedAtUtc": null,
      "Nodes": [],
      "Edges": []
    }
  }
}
```

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `Enabled` | 根因分析总开关 | 默认 `false` |
| `EvaluationIntervalSeconds` | 活动健康事件扫描周期 | 不进入控制线程 |
| `CorrelationWindowSeconds` | 事件时间关联窗口 | 结合工艺传播延迟验证 |
| `MaximumPropagationDepth` | 图搜索最大深度 | 防止深链和环路失控 |
| `MaximumGraphNodes` / `MaximumGraphEdges` | 活动图容量 | 必须覆盖现场并经过压测 |
| `MaximumEventsPerAnalysis` | 单次参与事件上限 | 禁止无界关联 |
| `MaximumCandidates` | 返回根因候选上限 | 控制响应大小 |
| `MaximumPaths` | 单次传播路径上限 | 控制内存和 JSON 大小 |
| `MaximumAnalysesQueryCount` | API 查询上限 | 禁止无界查询 |
| `MinimumCandidateConfidence` | 候选排序过滤门槛 | 不是故障概率或安全等级 |
| `AllowCycles` | 允许有向环 | 生产默认 `false` |
| `AnalysisRetentionHours` | 分析保留时间 | 与审计备份一致 |
| Maintenance 参数 | SQL 分批清理 | 防止长事务 |
| `Graph.Version` | 图版本 | 同版本不同 Hash 会拒绝 |
| `Graph.Source` | 图来源 | 记录设计/现场配置来源 |
| `Graph.ApprovedBy` / `ApprovedAtUtc` | 图审批信息 | 启用时必填 |
| `Graph.Nodes` | 节点数组 | NodeId、EntityId 唯一 |
| `Graph.Edges` | 有向边数组 | 统一 Upstream → Downstream |

节点支持 Asset、Component、Signal、Task、Station、Segment；关系支持 DependsOn、Feeds、Controls、LocatedAt、Carries。边权必须在 `(0,1]`。

启用依赖顺序：

```text
AnomalyFusion.Enabled=true
→ AnomalyHealthScoring.Enabled=true
→ AssetHealthGovernance.Enabled=true
→ v3.5 活动事件 AssetId 与 Graph.EntityId 完成映射验收
→ AssetHealthRootCause.Enabled=true
```

v3.6 使用 Coverage、Topology、Temporal、Severity 生成可解释候选；置信度仅是诊断排序，不是实际故障概率。Confirmed、Rejected、Supplemented 复核写 SQL Journal，但不会修改活动图。要采纳补充关系必须创建新图版本并重新审批。

## 14. TransportObservability、Resilience 与 Simulation

- `TransportObservability`：Trace、Prometheus、OTLP、一致性和调度健康；
- `TransportResilience`：生产就绪、逻辑备份、恢复演练和目录治理；
- `TransportSimulation`：仿真场景、A/B、容量基线和预测上限。

这些能力与 AnomalyEngine 诊断含义不同，不得共用门槛。

## 15. API 安全

v3.6 只读接口：

```text
GET /api/anomaly/root-cause/status
GET /api/anomaly/root-cause/graph
GET /api/anomaly/root-cause/analyses
GET /api/anomaly/root-cause/analyses/{analysisId}
GET /api/anomaly/root-cause/events/{eventId}/latest
GET /api/anomaly/root-cause/analyses/{analysisId}/reviews
```

治理写接口：

```text
POST /api/anomaly/root-cause/analyses/{analysisId}/reviews
```

该接口必须接入项目身份授权并保存 Actor、Decision、节点、说明和时间。LoadTest/MlLoadTest 专用入口在非测试环境必须返回 404。

## 16. 变更与回退

变更流程：记录当前版本和 GraphHash → 离线校验/回放 → 设备与工艺审批 → 备份 → 发布 → 观察指标 → 必要时回退。

回退顺序：

```text
AssetHealthRootCause__Enabled=false
→ AssetHealthGovernance__MesPushEnabled=false（仅需同时关闭 MES 时）
→ AssetHealthGovernance__Enabled=false（仅需关闭 v3.5 时）
```

关闭 v3.6 不影响 v3.5、v3.4、Fusion、PLC、任务和调度。不得通过删除 SQL 表作为紧急回退手段。
