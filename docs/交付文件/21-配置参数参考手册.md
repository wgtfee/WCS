# EMS/RGV、PLC 异常检测与统一仿真配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V3.1 |
| 对应分支 | `feature/simulation-s7-integration-recovery` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.9、Simulation S0～S7 |
| 安全原则 | 诊断、维修建议、模型、Forecast 和仿真结果不得替代 PLC 联锁、设备安全回路、机械互锁或调度状态机 |

本文汇总 `Wcs.Host` 主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
-> appsettings.{Environment}.json
-> 环境变量
-> 命令行或外部安全配置源
```

环境变量使用双下划线，例如：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
AssetHealthMaintenance__RuleSet__Version=maintenance-rules-v1
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=true
AssetFailureForecast__Enabled=true
Simulator__Enabled=true
SimulationGovernance__Enabled=true
SimulationScenarioEngine__MaximumTimelineItems=100000
SimulationRunRegistry__MaximumRuns=1000
SimulationVirtualPlc__MaximumBlocks=128
SimulationVirtualRgv__MaximumVehicles=256
SimulationVirtualTraffic__MaximumZones=256
SimulationVirtualExternal__MaximumEndpoints=256
SimulationVirtualHealth__MaximumAssets=256
SimulationVirtualIntegration__MaximumMissions=256
```

真实规则、Profile、Fusion Sources、PLC 点位、MES 密钥、根因图、维修规则、模型、数据集、许可证、场景、Manifest、真实 Endpoint 和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、事件、根因、维修反馈，以及 v3.9 模型版本、Forecast 和 Outcome Journal。v3.8/v3.9 模型文件与 active Manifest 存储在本地受控目录。

Simulation S0～S7 的场景、运行注册表、虚拟 PLC/RGV/Traffic/External/Health/Integration Mission、Forecast Oracle、Outcome 与 Audit 都是仿真状态，不写生产 SQL，也不得作为生产任务、路权、外部系统、Forecast 或恢复状态源。

## 4. Simulator、SimulationGovernance 与真实 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 模拟信号并禁止真实 PLC 后台服务 | Production 必须 `false` |
| `SimulationGovernance:Enabled` | 统一场景治理和 API 总开关 | Production 不得开启 |
| `ScenarioDirectory` | 场景文件目录 | 不存放真实生产数据 |
| `MaximumScenarioBytes` | 单场景内容上限 | 默认 1 MB，硬上限 16 MB |
| `MaximumRegisteredScenarioVersions` | 进程内 Registry 版本上限 | 默认 10,000 |
| `MaximumEvidenceRecords` | 单次 Evidence 记录上限 | 默认 10,000 |
| `MaximumEvidenceValueCharacters` | 单条 Evidence Value 字符上限 | 默认 4,096 |
| `AllowedEnvironments` | 允许访问 Simulation API 的环境 | 仅 `Simulation`、`SimulationLoadTest` |
| `WcsOptions:PlcPolling:Enabled` | 真实 PLC 轮询总开关 | 按现场验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |

仿真治理必须同时满足：

```text
Simulator.Enabled=true
AND SimulationGovernance.Enabled=true
AND Environment in {Simulation, SimulationLoadTest}
AND Environment != Production
```

其他环境的 `/api/simulation/**` 返回 404。Production 即使错误配置 Simulator 或白名单，也必须 fail closed。

## 12. SimulationVirtualIntegration S7

### 12.1 容量与策略参数

| 参数 | Simulation | SimulationLoadTest | 硬边界/说明 |
|---|---:|---:|---|
| `MaximumMissions` | 256 | 2,000 | 1～100,000；单运行集成 Mission 上限 |
| `MaximumSegmentsPerMission` | 16 | 64 | 1～1,000，同时不能超过 S4 rolling look-ahead |
| `MaximumAuditRecords` | 10,000 | 50,000 | 1～1,000,000；环形审计上限 |
| `ReservationLeaseMilliseconds` | 60,000 | 60,000 | 1ms～365 天，且不能超过 S4 最大租约 |
| `ExternalAckMaximumAttempts` | 3 | 5 | 1～100，且不能超过 S5 MaximumRetryAttempts |
| `ExternalAckTimeoutMilliseconds` | 5,000 | 10,000 | 必须在 S5 MaximumDelay 内 |
| `ExternalAckRetryDelayMilliseconds` | 1,000 | 1,000 | 0～365 天，且必须在 S5 MaximumDelay 内 |

### 12.2 集成链路

S7 只组合 S2～S6 Virtual Runtime：

```text
Virtual PLC
-> Virtual Traffic Reservation
-> Virtual RGV Movement
-> Virtual External Ack
-> Virtual Health Outcome
```

Mission 状态：

```text
Defined -> Dispatched -> Moving -> Completed -> Acknowledged
```

所有 Mission 与子系统状态进入同一 S1 `SimulationStateStore`，因此 Checkpoint、StateJson Restore、FinalStateHash 和 Replay 覆盖整条集成链。

### 12.3 exactly-once 与恢复

- External Ack 使用 MissionId 作为 IdempotencyKey；
- 重复 Ack 不创建第二条成功 Request；
- Health `CensoredNoFailure` Outcome 恰好一条；
- 恢复后不得残留该 Mission 的 Reservation、Waiting 或 Active Deadlock；
- Checkpoint resume 与不中断执行最终 StateHash、EvidenceHash、Assertions 必须一致。

### 12.4 安全边界

S7 Runtime 禁止真实 `HttpClient`、SQL/SqlSugar、Socket/TCP/UDP、真实 PLC/S7/Snap7、生产 CommandBus/TaskScheduler/TaskOrchestrator/DeviceManager、生产 Dispatch/Traffic/Reservation 组件、真实 Forecast Service/ONNX，以及墙钟等待和非确定性随机源。

## 13. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 15. AnomalyDetection 与 ML

- v1：规则异常；
- v2～v3.3：ML、上下文、周期分析与 Fusion；
- v3.4：健康评分；
- v3.5：事件治理与 MES Outbox；
- v3.6：根因图；
- v3.7：维修决策与反馈；
- v3.8：可插拔本地模型/ONNX；
- v3.9：故障概率、RUL 与 Outcome。

真实模型、规则、图、数据集和许可证必须独立受控；仓库/Production 危险能力默认关闭。

## 16. Simulation Host API 安全

S0 场景登记、S1 运行控制、S2～S7 inspection 只允许隔离 Simulation 环境。

S7 新增只读 API：

```text
GET /api/simulation/virtual-integration/runs/{runId}/status
GET /api/simulation/virtual-integration/runs/{runId}/missions
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}/consistency
GET /api/simulation/virtual-integration/runs/{runId}/audit?take=100
```

S2～S7 inspection API 均不得提供绕过 Scenario DSL 的 PLC 写、车辆运动、路线修改、预约、死锁处置、Fault 注入、真实外部请求、生产 Forecast 写入、Mission Ack 或生产调度操作。

## 18. 变更、回退与生产检查

优先回退：

```text
SimulationGovernance__Enabled=false
-> Simulator__Enabled=false
-> 按需关闭 Forecast / PluggableRuntime / ML / Maintenance 等独立能力
```

生产检查：

- [ ] Environment 明确为 Production；
- [ ] `Simulator.Enabled=false`；
- [ ] `SimulationGovernance.Enabled` 未开启；
- [ ] AllowedEnvironments 不含 Production；
- [ ] `/api/simulation/**` 返回 404；
- [ ] S1～S7 Simulation 组件没有生产控制入口；
- [ ] S5/S7 不含真实 Endpoint、ConnectionString、Token、密码或未脱敏 Payload；
- [ ] S6/S7 不加载真实模型、不写生产 Forecast SQL；
- [ ] S7 不引用真实 HTTP/SQL/Socket/PLC/RGV/生产调度组件；
- [ ] Registry、Evidence、Timeline、State、Run、Virtual PLC/RGV/Traffic/External/Health/Integration 和队列容量有界；
- [ ] 无 PLC 写入、设备停止、任务取消、生产路权释放、车辆选择、派单或调度修改；
- [ ] Simulation Evidence 不替代真实进程恢复、HIL、机械安全、协议、MES/SQL/网络联调、真实模型验证和现场验收。
