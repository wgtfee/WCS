# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 目的

本文汇总 Wcs.Host 中与 EMS/RGV 调度、PLC、Telemetry、异常检测、机器学习、运输周期、证据融合、资产健康评分、可观测性、韧性、仿真、数据库和部署相关的主要配置项。实际默认值以当前 `appsettings.json` 和代码为准，生产修改必须经过版本、测试、审批和变更管理。

> 本版本新增 AnomalyEngine v3.4 资产健康评分参数。原有调度、PLC、Telemetry、异常检测、ML、周期和 Fusion 参数定义保持不变。

## 2. 配置源和合并规则

ASP.NET Core 配置优先级通常为：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线表示层级：

```text
ConnectionStrings__WcsDb=...
Storage__Telemetry__InfluxDb__Token=...
AnomalyDetection__MachineLearning__Enabled=true
AnomalyFusion__Enabled=true
AnomalyHealthScoring__Enabled=true
```

数组可能按下标合并。通用配置中的下列数组必须保持空数组，现场应在最终环境配置中完整提供：

- `AnomalyDetection:Rules`；
- `AnomalyDetection:MachineLearning:Profiles`；
- `AnomalyFusion:Sources`。

不要在基础数组中放示例对象，否则环境配置可能只覆盖部分字段，造成规则、Profile 或来源权重泄漏。

## 3. ConnectionStrings

```json
{
  "ConnectionStrings": {
    "WcsDb": "..."
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| WcsDb | SQL Server 连接字符串 | 使用专用最小权限账号，不使用开发密码 |

业务任务、报警、资源锁、异常生命周期等仍使用 SQL Server，不随 PLC Telemetry Provider 切换。

## 4. Simulator

```json
{
  "Simulator": {
    "Enabled": true,
    "TransportTps": 2
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | 启用内置模拟轮询，并禁止真实 PLC 连接 | 实车现场必须为 false |
| TransportTps | 模拟运输速率 | 仅开发、演示和隔离测试使用 |

`Enabled=true` 时模拟信号仍经过结构体解析、StateCenter、EventBus、Telemetry、异常检测和 SignalR 链路。

## 5. WcsOptions

### 5.1 PlcPolling

| 参数 | 说明 | 建议范围 |
|---|---|---|
| Enabled | PLC 轮询总开关 | 现场 true |
| IntervalMs | 基础轮询间隔 | 50～1000ms，按 PLC 和网络负载验证 |

### 5.2 Persistence

| 参数 | 说明 | 建议 |
|---|---|---|
| IntervalSeconds | 通用状态持久化周期 | 典型 5～30 秒 |

关键命令和状态变化不能只依赖周期快照。

### 5.3 Snapshot

| 参数 | 说明 |
|---|---|
| IntervalSeconds | 快照周期 |
| MaxSnapshots | 内存/仓库快照保留数量 |

### 5.4 AlarmMonitor / AlarmRules

用于通用 WCS 报警监视和规则配置。PLC 异常检测产生的正式异常可通过 `RaiseAlarm` 桥接到 AlarmCenter，但不会替代原有报警规则。

## 6. Storage.Telemetry

```json
{
  "Storage": {
    "Telemetry": {
      "Provider": "SqlServer",
      "DurabilityMode": "Buffered",
      "ChannelCapacity": 100000,
      "BatchSize": 1000,
      "FlushIntervalMs": 1000,
      "RetryDelayMs": 2000,
      "WalBatchSize": 256,
      "WalFlushIntervalMs": 10,
      "SpoolDirectory": "data/plc-telemetry-spool",
      "Site": "default",
      "Measurement": "plc_signal"
    }
  }
}
```

| 参数 | 说明 | 建议 |
|---|---|---|
| Provider | `Disabled`、`SqlServer`、`InfluxDb` | 按现场部署选择 |
| DurabilityMode | `Buffered` 或 `WriteAhead` | 高耐久现场使用 WriteAhead |
| ChannelCapacity | 内存队列容量 | 根据采样峰值和内存压测 |
| BatchSize | 单批数据库写入点数 | 500～2000 起步 |
| FlushIntervalMs | 正常批量刷新间隔 | 500～2000ms |
| RetryDelayMs | Provider 失败重试间隔 | 避免过于频繁 |
| WalBatchSize | WriteAhead 单个 WAL 批大小 | 默认 256 |
| WalFlushIntervalMs | WAL 聚合等待 | 越小延迟越低、IO 越高 |
| SpoolDirectory | WAL/spool 目录 | 使用本地持久化 SSD 和受控 ACL |
| Site | 时序标签中的站点 | 使用稳定站点编号 |
| Measurement | Influx measurement/table 名 | 上线后避免随意更改 |

必须监控 dropped、conservationDelta、queue、in-flight、walPending、spoolPending、失败和目录容量。

## 7. AnomalyDetection v1

主要参数：

| 参数 | 说明 |
|---|---|
| Enabled | 规则和统计异常总开关 |
| WindowSize / MinimumSamples | Median/MAD 窗口和最低样本 |
| MaximumTrackedRuleSignals | 最大规则×信号状态数 |
| InactiveStateRetentionSeconds | 已恢复空闲状态 TTL |
| RelatedSampleRetentionSeconds | 一致性关联样本 TTL |
| MaximumCleanupItemsPerSweep | 单次清理上限 |
| ObserveThreshold / WarningThreshold / AlarmThreshold | 异常等级门槛 |
| ConsecutiveWarningCount / ConsecutiveAlarmCount | 连续确认次数 |
| RecoveryCount | 连续恢复次数 |
| Rules | 现场规则数组，基础配置必须为空 |

规则字段、跨信号一致性、Severity 和 RaiseAlarm 详细说明见文档 22～26。

## 10. AnomalyFusion v3.3

```json
{
  "AnomalyFusion": {
    "Enabled": false,
    "ChannelCapacity": 20000,
    "EvidenceRetentionSeconds": 300,
    "RecoveredEvidenceRetentionSeconds": 60,
    "InactiveStateRetentionSeconds": 600,
    "MaximumTrackedAssets": 20000,
    "MaximumEvidencePerAsset": 100,
    "MaximumSnapshots": 5000,
    "ObserveThreshold": 0.35,
    "WarningThreshold": 0.65,
    "AlarmThreshold": 0.85,
    "RecoveryThreshold": 0.25,
    "MinimumIndependentSourcesForAlarm": 2,
    "ConsecutiveWarningEvaluations": 2,
    "ConsecutiveAlarmEvaluations": 2,
    "ConsecutiveRecoveryEvaluations": 3,
    "SourceDiversityBonus": 0.05,
    "MaximumSourceDiversityBonus": 0.15,
    "Sources": []
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | Fusion 总开关 | 默认 false；先只读启用 |
| ChannelCapacity | Evidence 有界队列容量 | 结合峰值压测 |
| EvidenceRetentionSeconds | 活动 Evidence TTL | 不替代正式恢复事件 |
| RecoveredEvidenceRetentionSeconds | 已恢复 Evidence 保留 | 30～300 秒起步 |
| InactiveStateRetentionSeconds | 空闲 Normal 资产 TTL | 300～3600 秒起步 |
| MaximumTrackedAssets | 最大资产状态数 | 高于现场设备数并留余量 |
| MaximumEvidencePerAsset | 单资产 Evidence 上限 | 防止异常风暴 |
| MaximumSnapshots | 状态迁移历史上限 | 仅内存审计窗口 |
| Observe/Warning/AlarmThreshold | 融合风险门槛 | 必须顺序递增 |
| RecoveryThreshold | 正式恢复门槛 | 低于 Warning |
| MinimumIndependentSourcesForAlarm | Alarm 独立来源数 | 默认 2，不建议降为 1 |
| Consecutive*Evaluations | 升级和恢复连续次数 | 抑制抖动 |
| SourceDiversityBonus | 独立来源奖励 | 有限奖励 |
| MaximumSourceDiversityBonus | 奖励上限 | 默认 0.15 |
| Sources | 来源权重数组 | 基础配置为空，现场完整覆盖 |

## 11. AnomalyHealthScoring v3.4

```json
{
  "AnomalyHealthScoring": {
    "Enabled": false,
    "HealthyMinimumScore": 85,
    "AttentionMinimumScore": 70,
    "DegradedMinimumScore": 40,
    "MaximumFactors": 10,
    "SamplingIntervalSeconds": 10,
    "MinimumScoreChangeToRecord": 1,
    "MaximumUnchangedIntervalSeconds": 300,
    "MaximumHistoryPerAsset": 720,
    "MaximumTrackedHistoryAssets": 10000,
    "HistoryRetentionHours": 24,
    "TrendWindowSize": 12,
    "TrendChangeThreshold": 2,
    "MaximumHistoryQueryCount": 1000
  }
}
```

| 参数 | 说明 | 约束/建议 |
|---|---|---|
| Enabled | 当前评分和历史采样总开关 | 默认 false；依赖 AnomalyFusion |
| HealthyMinimumScore | Healthy 最低分 | 1～100 |
| AttentionMinimumScore | Attention 最低分 | 不高于 Healthy |
| DegradedMinimumScore | Degraded 最低分 | 不高于 Attention |
| MaximumFactors | 最大扣分解释因素数 | 1～100 |
| SamplingIntervalSeconds | 当前评分采样周期 | 1～3600 秒 |
| MinimumScoreChangeToRecord | 变化点记录门槛 | 0～100 分；默认 1 |
| MaximumUnchangedIntervalSeconds | 无变化心跳点间隔 | 不小于采样周期 |
| MaximumHistoryPerAsset | 单资产最大历史点数 | 2～100,000 |
| MaximumTrackedHistoryAssets | 最大历史资产数 | 100～10,000 |
| HistoryRetentionHours | 历史保留时间 | 1～8,760 小时 |
| TrendWindowSize | 默认趋势窗口点数 | 2～单资产上限 |
| TrendChangeThreshold | 改善/恶化方向门槛 | 0～100 分 |
| MaximumHistoryQueryCount | 单次历史查询上限 | 1～单资产上限 |

当前 Provider 固定为 `Memory`：

- Host 重启后历史丢失；
- 不写 SQL Server、InfluxDB 或文件；
- 不能作为长期审计或维修档案；
- 后续持久化必须实现 `IAssetHealthScoreHistoryStore` 并完成背压、重试、容量和恢复测试。

记录条件为首次出现、等级变化、达到分数变化门槛或达到无变化心跳间隔。

## 12. TransportObservability

`TransportObservability` 是调度运行健康与一致性层；`AnomalyHealthScoring` 是基于异常证据融合的资产诊断层。两者不能使用同一门槛或同一业务含义。

主要参数：

- Enabled；
- ConsistencyInspectionIntervalSeconds；
- HealthEvaluationIntervalSeconds；
- TraceRetentionCount；
- DegradedScoreThreshold；
- UnhealthyScoreThreshold；
- RaiseConsistencyAlarms；
- EnablePrometheusEndpoint；
- EnableOtlpExporter；
- OtlpEndpoint。

## 13. TransportResilience

主要参数：

- Enabled；
- PreflightIntervalSeconds；
- AutomaticBackupEnabled；
- BackupIntervalMinutes；
- BackupRetentionCount；
- MaximumJournalRecords；
- MaximumBackupAgeMinutes；
- RequireReadyBeforeAutomaticBackup；
- BackupDirectory。

模型、训练数据、Telemetry spool 和内存健康历史不由逻辑备份自动替代，需单独制定策略。

## 14. TransportSimulation

主要安全上限：

- MaximumScenarioTasks；
- MaximumStoredRuns；
- MaximumStoredComparisons；
- ForecastBucketSeconds；
- DefaultTravelSeconds；
- DefaultServiceSeconds；
- SustainableP95WaitingSeconds；
- SustainableDeadlineMissRatePercent；
- HistoricalJournalLimit。

生产环境不要随意提高容量上限，更大规模仿真使用独立离线环境。

## 15. 站点、单轨和驱动配置

站点关注 Capacity、MaximumQueuedTasks、Enabled；单轨关注 OrderedNodeIds、Capacity、方向切换和等待策略；驱动关注 DriverId、Kind、Protocol、Endpoint、连接和超时参数。

## 16. PLC 点位和连接

现场必须确认 PlcConnections、PlcBlocks、S7CommPlus、Modbus、OPC UA 和 Tag Poll 的地址、点位、字段、版本和访问权限。密码不得提交仓库。

## 17. Desktop、IIS 和 Host

关注：

- ASPNETCORE_ENVIRONMENT；
- Host ServerUrl；
- 监听地址和 HTTPS；
- 服务账号和目录 ACL；
- stdout/Serilog；
- 应用池回收和反向代理超时；
- 模型、训练、WAL、备份目录；
- 健康历史内存容量和 Host RSS。

## 18. API 安全开关

只读接口包括：

- `/api/anomaly/status`；
- `/api/anomaly/active`；
- `/api/anomaly/ml/status`；
- `/api/transport/cycle-analysis/status`；
- `/api/anomaly/fusion/status`；
- `/api/anomaly/fusion/assets`；
- `/api/anomaly/fusion/assets/{assetId}`；
- `/api/anomaly/health/status`；
- `/api/anomaly/health/assets`；
- `/api/anomaly/health/assets/{assetId}`；
- `/api/anomaly/health/history/status`；
- `/api/anomaly/health/assets/{assetId}/history`；
- `/api/anomaly/health/assets/{assetId}/trend`。

训练、冻结、审批、模型激活等管理接口仅在 `ManagementApiEnabled=true` 时存在。LoadTest/MlLoadTest 接口不得在生产环境开放。

## 19. 参数变更流程

```text
记录当前配置、规则、模型、Fusion 和评分版本
→ 说明变更原因、范围和影响设备
→ 离线测试/回放/影子运行
→ 申请和独立审批
→ 备份配置、模型和数据
→ 应用变更
→ 观察 Telemetry、异常、Fusion、健康历史和资源指标
→ 必要时关闭健康评分、Fusion、报警或回滚模型
```

## 20. 配置检查清单

- [ ] ConnectionString 使用生产专用账号；
- [ ] Simulator.Enabled 正确；
- [ ] PLC 地址、点位和字段版本正确；
- [ ] Telemetry Provider 和 DurabilityMode 已确认；
- [ ] Token、密码未提交仓库；
- [ ] Rules、Profiles、Sources 基础数组为空且现场覆盖完整；
- [ ] ManagementApiEnabled 默认关闭；
- [ ] TransportCycleAnalysis 启用顺序和基线参数已确认；
- [ ] AnomalyFusion 默认关闭或已完成审批；
- [ ] MinimumIndependentSourcesForAlarm 未被无依据降低；
- [ ] Fusion 守恒和容量正常；
- [ ] AnomalyHealthScoring 默认关闭或已完成审批；
- [ ] 健康等级门槛顺序正确；
- [ ] 采样、变化、心跳、历史容量和保留期已压测；
- [ ] 当前 Provider=Memory 的重启丢失限制已被接受；
- [ ] 健康评分和趋势未接入自动控制；
- [ ] 可观测性、韧性、Desktop 和目录权限正确；
- [ ] 配置版本、测试证据和审批记录已保存。
