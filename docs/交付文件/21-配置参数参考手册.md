# EMS/RGV、PLC 异常检测与统一仿真配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V2.9 |
| 对应分支 | `feature/simulation-s5-external-failures` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.9、Simulation S0～S5 |
| 安全原则 | 诊断、维修建议、模型、Forecast 和仿真结果不得替代 PLC 联锁、设备安全回路、机械互锁或调度状态机 |

本文汇总 `Wcs.Host` 主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线，例如：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
AssetHealthMaintenance__RuleSet__Version=maintenance-rules-v1
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=true
AssetFailureForecast__Enabled=true
Simulator__Enabled=true
SimulationGovernance__Enabled=true
SimulationScenarioEngine__MaximumTimelineItems=100000
SimulationRunRegistry__MaximumRuns=1000
SimulationVirtualPlc__MaximumBlocks=128
SimulationVirtualRgv__MaximumVehicles=256
SimulationVirtualTraffic__MaximumZones=256
SimulationVirtualExternal__MaximumEndpoints=256
SimulationVirtualExternal__MaximumRequests=10000
```

规则、Profile、Fusion Sources、PLC 点位、MES 密钥、根因图、维修规则、真实模型、数据集、许可证、场景、Manifest、真实 Endpoint 和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、事件、根因、维修反馈，以及 v3.9 模型版本、Forecast 和 Outcome Journal。v3.8/v3.9 模型文件与 active Manifest 存储在本地受控目录。

Simulation S0～S5 的场景目录、运行注册表、虚拟 PLC、虚拟 RGV、冲突域、预约、等待请求、等待图、死锁、外部 Endpoint、Fault、Request、Circuit 与 Audit 均为进程内仿真实现，不写生产 SQL，不得被视为生产任务、路权或外部系统真实状态源。

## 4. Simulator、SimulationGovernance 与真实 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 模拟信号并禁止真实 PLC 后台服务 | Production 必须 `false` |
| `Simulator:TransportTps` | 旧模拟任务生成速率 | 仅用于批准的仿真环境 |
| `SimulationGovernance:Enabled` | 统一场景治理和 API 总开关 | Production 不得开启 |
| `ScenarioDirectory` | 场景文件目录 | 必填，最长 1,024 字符，不存放真实生产数据 |
| `MaximumScenarioBytes` | 单场景内容上限 | 默认 1 MB，硬上限 16 MB |
| `MaximumRegisteredScenarioVersions` | 进程内 Registry 版本上限 | 默认 10,000，硬上限 100,000 |
| `MaximumEvidenceRecords` | 单次 Evidence 记录上限 | 默认 10,000，硬上限 1,000,000 |
| `MaximumEvidenceValueCharacters` | 单条 Evidence Value 字符上限 | 默认 4,096，硬上限 1,048,576 |
| `AllowedEnvironments` | 允许访问 Simulation API 的环境 | 仅 `Simulation`、`SimulationLoadTest` |
| `WcsOptions:PlcPolling:Enabled` | 真实 PLC 轮询总开关 | 按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| S7CommPlus / Modbus / OPC UA / Tag Poll | 其他驱动配置 | 密码和证书外部注入 |

仿真治理必须同时满足：

```text
Simulator.Enabled=true
AND SimulationGovernance.Enabled=true
AND Environment ∈ {Simulation, SimulationLoadTest}
AND Environment != Production
```

其他环境的 `/api/simulation/**` 返回 404。Production 即使误把 Simulator 设置为 true 或错误加入白名单，API 仍优先拒绝，模拟后台服务也必须失败关闭。

## 6. SimulationRunRegistry S1

| 参数 | Simulation | SimulationLoadTest | 说明 |
|---|---:|---:|---|
| `MaximumRuns` | 1,000 | 5,000 | 进程内运行数量上限 |

运行注册表只保存在进程内。重启后运行列表丢失；这不是生产任务状态存储，也不接入任务、路权、车辆或派单控制链。

## 10. SimulationVirtualExternal S5

### 10.1 容量与策略参数

| 参数 | Simulation | SimulationLoadTest | 硬边界/说明 |
|---|---:|---:|---|
| `MaximumEndpoints` | 256 | 2,000 | 1～100,000；虚拟外部依赖数量 |
| `MaximumFaults` | 2,048 | 20,000 | 1～1,000,000；Fault 数量 |
| `MaximumRequests` | 10,000 | 100,000 | 1～1,000,000；请求记录数量 |
| `MaximumAuditRecords` | 5,000 | 50,000 | 1～1,000,000；环形审计上限 |
| `MaximumRetryAttempts` | 16 | 32 | 1～100；单请求最大 Attempt |
| `DefaultTimeoutMilliseconds` | 5,000 | 5,000 | 必须 >0 且不超过 MaximumDelay |
| `MaximumDelayMilliseconds` | 86,400,000 | 604,800,000 | 最大允许 365 天虚拟时间 |
| `CircuitFailureThreshold` | 3 | 5 | 1～100；连续失败开路阈值 |
| `CircuitOpenMilliseconds` | 30,000 | 30,000 | Open 状态持续虚拟时间 |

### 10.2 支持的系统与故障

系统类型：`Mes`、`SqlServer`、`Http`、`Network`、`Custom`。

故障类型：`Timeout`、`Unavailable`、`HttpStatus`、`InvalidResponse`、`DuplicateResponse`、`SqlDeadlock`、`SqlCommandTimeout`、`ConnectionReset`、`HighLatency`、`PacketLoss`、`HalfOpen`。

### 10.3 确定性与安全边界

- Endpoint、Fault、Request、Attempt、Circuit、Audit 与 OperationSequence 进入 S1 `SimulationStateStore`；
- RetryDelay、Timeout、Fault Window 和 Circuit Open/Probe 都只使用虚拟偏移；
- 成功 IdempotencyKey 重放不得创建第二条业务 Request；
- Host 只读检查从活动 Run 的 Checkpoint 重建快照；
- 不保存真实 URL、SQL ConnectionString、Token、密码或生产 Payload；
- 不允许 `HttpClient`、真实 SQL Provider、Socket/TCP/UDP、PLC Client、CommandBus、TaskScheduler、TaskOrchestrator、DeviceManager 或生产交通控制依赖；
- 不允许 `DateTime.Now/UtcNow`、`Task.Delay`、`Thread.Sleep`、`Random.Shared` 参与确定性 Runtime。

## 11. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

- v3.3：AnomalyFusion Sources、Evidence、等级门槛和独立来源数；
- v3.4：AnomalyHealthScoring 历史 Provider、采样、趋势、SQL 队列和保留；
- v3.5：AssetHealthGovernance、MES Outbox、重试和 DeadLetter；
- v3.6：AssetHealthRootCause Graph、Version、Hash、窗口、传播深度和审批；
- v3.7：AssetHealthMaintenance RuleSet、建议、反馈和标签；

仓库/Production 的危险能力默认关闭；真实模型、规则、图、数据集和许可证必须独立受控。

## 14. Forecast 输出与启用顺序

输出约束：

```text
0 <= P24 <= P72 <= P168 <= 1
0 <= RulLower <= RulMedian <= RulUpper <= MaximumRulHours
```

推荐启用顺序：

```text
SqlServer 健康历史验收
→ 冻结 FeatureSchema/数据集版本
→ 真实失效/删失/维修标签审批
→ 离线训练、校准、覆盖率和许可证验收
→ 本地模型、Manifest、SHA 发布
→ 权限化 Management API
→ 单资产手工 Evaluate
→ Outcome 观察
→ 项目签署后启用 Forecast
```

## 15. Simulation Host API 安全

治理写操作必须接入身份授权并保存 Actor、原因和时间。S0 场景登记、S1 运行控制、S2～S5 检查只允许隔离 Simulation 环境。

S2、S3、S4 Host API 继续保持原有只读检查。S5 新增：

```text
GET /api/simulation/virtual-external/runs/{runId}/status
GET /api/simulation/virtual-external/runs/{runId}/endpoints
GET /api/simulation/virtual-external/runs/{runId}/endpoints/{endpointId}
GET /api/simulation/virtual-external/runs/{runId}/faults
GET /api/simulation/virtual-external/runs/{runId}/faults/{faultId}
GET /api/simulation/virtual-external/runs/{runId}/requests
GET /api/simulation/virtual-external/runs/{runId}/requests/{requestId}
GET /api/simulation/virtual-external/runs/{runId}/audit?take=100
```

S2～S5 Host 检查 API 均不得提供绕过场景 DSL 的 PLC 写、车辆运动、路线修改、预约、死锁处置、Fault 注入、真实外部请求或生产调度操作。

## 17. 变更、回退与生产检查

优先回退：

```text
SimulationGovernance__Enabled=false
→ Simulator__Enabled=false
→ 按需关闭 Forecast / PluggableRuntime / ML / Maintenance 等独立能力
```

生产检查：

- [ ] Environment 明确为 Production；
- [ ] `Simulator.Enabled=false`；
- [ ] `SimulationGovernance.Enabled` 未开启；
- [ ] AllowedEnvironments 不含 Production；
- [ ] `/api/simulation/**` 返回 404；
- [ ] S1～S5 Simulation 组件没有生产控制入口；
- [ ] `SimulationVirtualExternal` 不含真实 Endpoint、ConnectionString、Token、密码或未脱敏 Payload；
- [ ] 真实 HTTP/SQL/Socket/PLC/RGV 客户端未被 S5 Runtime 引用；
- [ ] Rules、Profiles、Sources、Graph、Maintenance RuleSet 和场景无示例泄漏；
- [ ] Production ML、PluggableRuntime 和 Forecast 默认关闭；
- [ ] 模型/场景目录 ACL、备份、Hash 和防篡改完整；
- [ ] Registry、Evidence、Timeline、State、Run、Virtual PLC/RGV/Traffic/External 和所有队列容量有界；
- [ ] Governance、Outcome 和治理写 API 已接入身份权限；
- [ ] 无 PLC 写入、设备停止、任务取消、生产路权释放、车辆选择、派单或调度修改；
- [ ] Simulation Evidence 不替代 HIL、机械安全、真实协议、MES/SQL/网络联调和现场验收；
- [ ] 真实准确率、HIL、权限、许可证、维修策略和正式投产已独立签署。
