# EMS/RGV、PLC 异常检测与统一仿真配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V2.7 |
| 对应分支 | `feature/simulation-s3-virtual-rgv` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.9、Simulation S0～S3 |
| 安全原则 | 诊断、维修建议、模型、Forecast 和仿真结果不得替代 PLC 联锁、设备安全回路或调度状态机 |

本文汇总 `Wcs.Host` 主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线，例如：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
AssetHealthMaintenance__RuleSet__Version=maintenance-rules-v1
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=true
AssetFailureForecast__Enabled=true
Simulator__Enabled=true
SimulationGovernance__Enabled=true
SimulationScenarioEngine__MaximumTimelineItems=100000
SimulationRunRegistry__MaximumRuns=1000
SimulationVirtualPlc__MaximumBlocks=128
SimulationVirtualRgv__MaximumVehicles=256
```

规则、Profile、Fusion Sources、PLC 点位、MES 密钥、根因图、维修规则、真实模型、数据集、许可证、场景、Manifest 和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、事件、根因、维修反馈，以及 v3.9 模型版本、Forecast 和 Outcome Journal。v3.8/v3.9 模型文件与 active Manifest 存储在本地受控目录。Simulation S0～S3 的场景目录、运行注册表、虚拟 PLC 和虚拟 RGV 状态均为进程内实现，不写生产 SQL。

## 4. Simulator、SimulationGovernance 与真实 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 模拟信号并禁止真实 PLC 后台服务 | Production 必须 `false` |
| `Simulator:TransportTps` | 旧模拟任务生成速率 | 仅用于批准的仿真环境 |
| `SimulationGovernance:Enabled` | 统一场景治理和 API 总开关 | Production 不得开启 |
| `ScenarioDirectory` | 场景文件目录 | 必填，最长 1,024 字符，不存放真实生产数据 |
| `MaximumScenarioBytes` | 单场景内容上限 | 默认 1 MB，硬上限 16 MB |
| `MaximumRegisteredScenarioVersions` | 进程内 Registry 版本上限 | 默认 10,000，硬上限 100,000 |
| `MaximumEvidenceRecords` | 单次 Evidence 记录上限 | 默认 10,000，硬上限 1,000,000 |
| `MaximumEvidenceValueCharacters` | 单条 Evidence Value 字符上限 | 默认 4,096，硬上限 1,048,576 |
| `AllowedEnvironments` | 允许访问 Simulation API 的环境 | 仅 `Simulation`、`SimulationLoadTest` |
| `WcsOptions:PlcPolling:Enabled` | 真实 PLC 轮询总开关 | 按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| S7CommPlus / Modbus / OPC UA / Tag Poll | 其他驱动配置 | 密码和证书外部注入 |

仿真治理必须同时满足：

```text
Simulator.Enabled=true
AND SimulationGovernance.Enabled=true
AND Environment ∈ {Simulation, SimulationLoadTest}
AND Environment != Production
```

其他环境的 `/api/simulation/**` 返回 404。Production 即使误把 Simulator 设置为 true 或错误加入白名单，API 仍优先拒绝，模拟后台服务也必须失败关闭。

## 5. SimulationScenarioEngine S1

| 参数 | Simulation | SimulationLoadTest | 说明 |
|---|---:|---:|---|
| `MaximumTimelineItems` | 100,000 | 500,000 | 单场景 Action + Assertion 上限 |
| `MaximumStateEntries` | 10,000 | 50,000 | 单运行状态键上限 |
| `MaximumStateValueCharacters` | 4,096 | 4,096 | 单状态值和 Evidence Value 上限 |
| `MaximumCheckpointBytes` | 16,777,216 | 67,108,864 | Checkpoint canonical 内容上限 |
| `MaximumSpeedFactor` | 1,000 | 10,000 | 虚拟时钟倍率上限 |

S1 使用严格 JSON、确定性 Timeline、虚拟时钟、Checkpoint 和 Replay。速度倍率不得改变状态、断言或 Evidence 结果。

## 6. SimulationRunRegistry S1

| 参数 | Simulation | SimulationLoadTest | 说明 |
|---|---:|---:|---|
| `MaximumRuns` | 1,000 | 5,000 | 进程内运行数量上限 |

运行注册表只保存在进程内。重启后运行列表丢失；这不是生产任务状态存储，也不接入任务、路权、车辆或派单控制链。

## 7. SimulationVirtualPlc S2

| 参数 | Simulation | SimulationLoadTest | 说明 |
|---|---:|---:|---|
| `MaximumBlocks` | 128 | 256 | 单运行虚拟 DB 块上限 |
| `MaximumBlockBytes` | 65,536 | 65,536 | 单 DB 块字节上限 |
| `MaximumOperationBytes` | 65,536 | 65,536 | 单次底层虚拟读写长度上限 |
| `MaximumScenarioTransferBytes` | 1,536 | 1,536 | DSL 与 StateStore 单次传输上限，同时作为 DB 分块大小 |
| `MaximumFaults` | 1,024 | 10,000 | 单运行故障定义上限 |
| `MaximumFaultPayloadBytes` | 1,536 | 1,536 | Stuck/OutOfRange 等故障载荷上限 |
| `MaximumAuditRecords` | 1,000 | 10,000 | 环形操作审计保留上限 |

S2 约束：

- DB 标识必须为 `PLC_NAME.DB<number>`；
- DB 数据按 1,536 字节分块存入 S1 `SimulationStateStore`；
- Connection、Fault、OperationSequence 和 Audit 自动进入 Checkpoint、Replay 与 FinalStateHash；
- Fault 支持 Disconnect、Timeout、ReadFailure、WriteFailure、Stuck、BitFlip、Jitter、OutOfRange；
- Timeout 是结构化失败结果，不使用真实墙钟等待；
- Jitter 由会话随机盐、OperationSequence、FaultId 和字节位置确定；
- Host 只提供只读检查，不提供绕过 DSL 的直接写块或直接故障注入 API；
- S2 不引用真实 PLC 客户端、Socket、PLC Writer、CommandBus 或调度组件。

## 8. SimulationVirtualRgv S3

| 参数 | Simulation | SimulationLoadTest | 说明 |
|---|---:|---:|---|
| `MaximumVehicles` | 256 | 2,000 | 单运行虚拟 RGV 数量上限 |
| `MaximumSegments` | 2,048 | 10,000 | 单运行有向区段数量上限 |
| `MaximumRouteSegments` | 256 | 2,048 | 单车显式路线区段上限 |
| `MaximumAuditRecords` | 5,000 | 50,000 | 环形 RGV 操作审计保留上限 |
| `MaximumSegmentLengthMillimeters` | 10,000,000 | 10,000,000 | 单区段长度上限，单位毫米 |
| `MaximumSpeedMillimetersPerSecond` | 20,000 | 20,000 | 车辆和区段速度上限，单位毫米/秒 |
| `BatteryDrainBasisPointsPerMeter` | 1 | 1 | 每米消耗的电量基点数，10,000 基点等于 100% |

S3 约束：

- 区段是显式有向边，包含 FromNode、ToNode、长度、限速和 Enabled；
- 车辆包含节点/区段位置、进度、路线游标、速度、电量基点、载荷、在线状态和能力；
- 路线由场景显式提供有序区段列表，必须从车辆当前节点开始并保持拓扑连续；
- 运动只由 `rgv.vehicle.advance` 按虚拟时间推进，不使用真实计时器或后台线程；
- 车辆速度受区段限速约束，电量按毫米距离和整数余数确定性扣减；
- 所有状态进入 S1 `SimulationStateStore`，参与 Checkpoint、Replay 和 FinalStateHash；
- Host 只提供只读检查，不提供直接运动、路线修改、派单或路权操作；
- S3 不引用真实 RGV 驱动、Socket、PLC 客户端、CommandBus、`UnifiedTransportDispatchEngine`、交通协调器或死锁处理；
- 路径搜索、车辆选择、派单、滚动路权、冲突和死锁验证属于 S4。

## 9. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 10. PLC Telemetry

| 参数 | 说明 |
|---|---|
| `Storage:Telemetry:Provider` | `Disabled`、`SqlServer`、`InfluxDb` |
| `DurabilityMode` | `Buffered` 或 `WriteAhead` |
| `ChannelCapacity` | 有界队列容量 |
| `BatchSize` / `FlushIntervalMs` | 批量写入参数 |
| `RetryDelayMs` | Provider 失败重试间隔 |
| `WalBatchSize` / `WalFlushIntervalMs` | WAL 参数 |
| `SpoolDirectory` | 本地持久化目录 |
| `Site` / `Measurement` | 时序标签和 measurement |

必须监控 dropped、conservationDelta、queue、in-flight、WAL pending、目录容量和失败批次。

## 11. AnomalyDetection v1

主要参数包括 `Enabled`、`WindowSize`、`MinimumSamples`、最大信号数、状态 TTL、关联样本保留、Observe/Warning/Alarm 门槛、连续确认、恢复次数和 `Rules`。基础 `Rules` 数组保持为空。

## 12. Machine Learning v2/v2.1/v3.1

| 参数 | 说明 | 建议 |
|---|---|---|
| `Enabled` | ML 总开关 | 默认关闭，先 Shadow |
| `ManagementApiEnabled` | 训练、审批、激活、回滚和 Forecast 写 API | 默认关闭并接入身份权限 |
| `ModelDirectory` | 模型和活动版本目录 | 持久化、受控 ACL、备份 |
| `TrainingDirectory` | 特征和冻结数据集 | 受控 ACL |
| `MaximumTrackedWindows` | 最大活动窗口 | 结合现场规模压测 |
| `Profiles` | 模型 Profile 数组 | 通用和 Production 配置为空 |

Profile 参数包括信号、窗口、训练数量、Isolation Forest、阈值、连续异常/恢复、Shadow/Canary/Active、漂移、上下文和同群参数。

## 13. TransportCycleAnalysis v3.2

主要参数包括最小基线周期数、上下文最大周期数、最大执行数、已完成周期/异常上限、MAD 倍数以及总周期和阶段绝对保护值。

## 14. AnomalyFusion v3.3

主要参数包括 Enabled、ChannelCapacity、Evidence Retention、MaximumTrackedAssets、EvidencePerAsset、Observe/Warning/Alarm/Recovery、MinimumIndependentSourcesForAlarm、ConsecutiveEvaluations 和 Sources。通用 Sources 数组保持为空。

## 15. AnomalyHealthScoring v3.4

主要参数包括 Enabled、等级门槛、MaximumFactors、HistoryProvider、采样周期、变化记录门槛、心跳间隔、单资产历史上限、资产数、保留期、趋势、SQL 写入队列和清理批次。正式 Forecast 使用前必须评估 SqlServer 历史完整性和时间语义。

## 16. AssetHealthGovernance v3.5

核心参数包括 Enabled、MinimumEventGrade、连续不健康/恢复、EvaluationInterval、Retention/Maintenance、MES Outbox、批次、重试、DeadLetter 和密钥。MES 故障不得阻塞 PLC、任务、命令、路权或调度线程。

## 17. AssetHealthRootCause v3.6

仓库默认 `Enabled=false`、`AllowCycles=false`、Graph Version/Source/ApprovedBy 为空、Nodes/Edges 为空。核心参数包括关联窗口、传播深度、容量上限、MinimumCandidateConfidence、图版本、Hash、来源和审批。

## 18. AssetHealthMaintenance v3.7

仓库和 Production 默认 `Enabled=false`，RuleSet Version/Source/ApprovedBy 为空，Rules 为空。无匹配规则时不生成建议；训练标签 Approved 不自动训练或激活模型。

## 19. PluggableRuntime v3.8

仓库和 Production 默认关闭。核心参数包括 `PluggableRuntime.Enabled`、MaximumTrackedWindows、InactiveStateRetentionSeconds，以及 Profiles 中的 ProfileId、AdapterKind、Required。外部 Profile 禁止在线训练和 AutoTrain，同一 Profile 不得双推理；模型只允许本地相对路径、SHA 校验和 CPU ONNX。

## 20. AssetFailureForecast v3.9

主要参数：Enabled、ModelDirectory、EvaluationIntervalSeconds、MinimumHistoryPoints、MinimumHistorySpanHours、MaximumHistoryPoints、MaximumAssetsPerEvaluation、MaximumForecastsQueryCount、ForecastRetentionHours、Maintenance 参数、MaximumModelArtifactMegabytes、MinimumTrainingAssets、MinimumFailureEvents、MinimumValidationAuc、MaximumValidationBrierScore、MinimumPredictionIntervalCoverage。

Manifest 必须包含 TrainingDatasetVersion、CensoredRecordCount、ValidationRulMaeHours、审批信息、14 维 FeatureNames、标准化数组、输入输出名称和 Shape、MaximumRulHours、ArtifactSha256。

输出约束：

```text
0 <= P24 <= P72 <= P168 <= 1
0 <= RulLower <= RulMedian <= RulUpper <= MaximumRulHours
```

数据不足或输出不满足约束时不得写入预测结果。

## 21. Forecast 启用依赖顺序

```text
AnomalyHealthScoring.HistoryProvider=SqlServer
→ 健康历史完整性和时间语义验收
→ 冻结 14 维 FeatureSchema 和数据集版本
→ 真实失效、删失和维修标签审批
→ 离线训练、校准、覆盖率和许可证验收
→ 本地模型、Manifest 和 SHA 发布
→ ManagementApiEnabled=true（接入权限后）
→ 单资产手工 Evaluate
→ 记录 Outcome 并观察指标
→ AssetFailureForecast.Enabled=true（项目签署后）
```

## 22. API 安全

治理写操作必须接入身份授权并保存 Actor、原因和时间。S0 场景登记、S1 运行控制、S2/S3 只读检查只允许隔离 Simulation 环境。LoadTest、MlLoadTest、ForecastLoadTest、Simulation 和 SimulationLoadTest 入口在非批准环境必须返回 404。

S2 Host 检查 API：

```text
GET /api/simulation/virtual-plc/runs/{runId}/status
GET /api/simulation/virtual-plc/runs/{runId}/blocks
GET /api/simulation/virtual-plc/runs/{runId}/blocks/{plcName}/db/{blockNumber}
GET /api/simulation/virtual-plc/runs/{runId}/faults
GET /api/simulation/virtual-plc/runs/{runId}/audit
```

S3 Host 检查 API：

```text
GET /api/simulation/virtual-rgv/runs/{runId}/status
GET /api/simulation/virtual-rgv/runs/{runId}/vehicles
GET /api/simulation/virtual-rgv/runs/{runId}/vehicles/{vehicleId}
GET /api/simulation/virtual-rgv/runs/{runId}/vehicles/{vehicleId}/transport-snapshot
GET /api/simulation/virtual-rgv/runs/{runId}/segments
GET /api/simulation/virtual-rgv/runs/{runId}/segments/{segmentId}
GET /api/simulation/virtual-rgv/runs/{runId}/occupancy
GET /api/simulation/virtual-rgv/runs/{runId}/audit
```

## 23. 变更、回退与生产检查

回退顺序：

```text
SimulationGovernance__Enabled=false
→ Simulator__Enabled=false
→ AssetFailureForecast__Enabled=false（仅需关闭 v3.9 时）
→ AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=false（仅需关闭 v3.8 时）
→ AnomalyDetection__MachineLearning__Enabled=false（仅需关闭全部 ML 时）
→ AssetHealthMaintenance__Enabled=false（仅需关闭 v3.7 时）
```

生产检查：

- [ ] Environment 明确为 Production；
- [ ] `Simulator.Enabled=false`；
- [ ] `SimulationGovernance.Enabled` 未开启；
- [ ] AllowedEnvironments 不含 Production；
- [ ] `/api/simulation/**` 返回 404；
- [ ] `SimulationScenarioEngine`、`SimulationRunRegistry`、`SimulationVirtualPlc`、`SimulationVirtualRgv` 没有生产控制入口；
- [ ] Rules、Profiles、Sources、Graph、Maintenance RuleSet 和场景无示例泄漏；
- [ ] Production ML、PluggableRuntime 和 Forecast 默认关闭；
- [ ] 真实模型、数据集、场景、许可证和密钥未提交仓库；
- [ ] 模型/场景目录 ACL、备份、Hash 和防篡改完整；
- [ ] Registry、Evidence、Timeline、State、Run、Virtual PLC Block/Fault/Audit、Virtual RGV Vehicle/Segment/Route/Audit 和所有队列容量有界；
- [ ] Manifest 数据集或场景版本、样本统计、验证指标、审批和 FeatureSchema/Seed 完整；
- [ ] 数据不足时不生成概率或 RUL；
- [ ] Outcome 和治理写 API 已接入身份权限；
- [ ] 坏 Hash 时 Host 健康且模型/场景拒载；
- [ ] 训练标签 Approved 不自动更新活动模型；
- [ ] 无 PLC 写入、设备停止、任务取消、路权释放、车辆选择、派单或调度修改；
- [ ] Simulation Evidence 不替代 HIL、机械安全、真实协议和现场验收；
- [ ] 真实准确率、HIL、权限、许可证、维修策略和正式投产已独立签署。
