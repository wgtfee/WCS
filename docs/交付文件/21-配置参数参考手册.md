# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V2.2 |
| 对应分支 | `feature/pluggable-onnx-runtime-v3-8` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.8 |
| 安全原则 | 诊断、维修建议和模型输出不得替代 PLC 联锁、设备安全回路或调度状态机 |

本文汇总 `Wcs.Host` 主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
AssetHealthMaintenance__RuleSet__Version=maintenance-rules-v1
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=true
```

规则、Profile、Fusion Sources、PLC 点位、MES 密钥、根因图、维修规则、真实模型、Manifest 和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、v3.5 事件 Journal、v3.6 图/分析/复核，以及 v3.7 规则版本、建议、反馈和训练标签。v3.8 外部模型文件和 Manifest 存储在本地模型目录，Candidate 和后续生命周期仍写既有 SQL 表。

## 4. Simulator 与 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 启用模拟信号并禁止真实 PLC 后台服务 | 实车现场必须 `false` |
| `WcsOptions:PlcPolling:Enabled` | PLC 轮询总开关 | 按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| S7CommPlus / Modbus / OPC UA / Tag Poll | 其他驱动配置 | 密码和证书外部注入 |

## 5. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：通用报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 6. PLC Telemetry

| 参数 | 说明 |
|---|---|
| `Storage:Telemetry:Provider` | `Disabled`、`SqlServer`、`InfluxDb` |
| `DurabilityMode` | `Buffered` 或 `WriteAhead` |
| `ChannelCapacity` | 有界队列容量 |
| `BatchSize` / `FlushIntervalMs` | 批量写入参数 |
| `RetryDelayMs` | Provider 失败重试间隔 |
| `WalBatchSize` / `WalFlushIntervalMs` | WAL 参数 |
| `SpoolDirectory` | 本地持久化目录 |
| `Site` / `Measurement` | 时序标签和 measurement |

必须监控 dropped、conservationDelta、queue、in-flight、WAL pending、目录容量和失败批次。

## 7. AnomalyDetection v1

主要参数：`Enabled`、`WindowSize`、`MinimumSamples`、最大信号数、状态 TTL、关联样本保留、Observe/Warning/Alarm 门槛、连续确认、恢复次数和 `Rules`。基础 `Rules` 数组保持为空。

## 8. Machine Learning v2/v2.1/v3.1

| 参数 | 说明 | 建议 |
|---|---|---|
| `Enabled` | ML 总开关 | 默认关闭，先 Shadow |
| `ManagementApiEnabled` | 训练、审批、激活、回滚 API | 默认关闭并接入身份权限 |
| `ModelDirectory` | 模型和活动版本目录 | 持久化、受控 ACL、备份 |
| `TrainingDirectory` | 特征和冻结数据集 | 受控 ACL |
| `MaximumTrackedWindows` | 最大活动窗口 | 结合现场规模压测 |
| `Profiles` | 模型 Profile 数组 | 通用和 Production 配置为空 |

Profile 主要参数包括信号、窗口、训练数量、Isolation Forest 树数/采样数、污染率、Observe/Warning/Alarm、连续异常/恢复、Shadow/Canary/Active、漂移、上下文和同群参数。

## 9. TransportCycleAnalysis v3.2

主要参数包括 `Enabled`、最小基线周期数、上下文最大周期数、最大执行数、最大已完成周期和异常数、MAD 倍数，以及总周期和阶段绝对保护值。

## 10. AnomalyFusion v3.3

| 参数 | 说明 |
|---|---|
| `Enabled` | Fusion 总开关，默认 `false` |
| `ChannelCapacity` | Evidence 有界队列 |
| Evidence Retention | 活动和恢复证据 TTL |
| MaximumTrackedAssets / EvidencePerAsset | 容量上限 |
| Observe/Warning/Alarm/Recovery | 融合和恢复门槛 |
| `MinimumIndependentSourcesForAlarm` | Alarm 最少独立来源 |
| `Consecutive*Evaluations` | 防抖和恢复连续次数 |
| `Sources` | 来源权重数组，通用配置为空 |

## 11. AnomalyHealthScoring v3.4

主要参数：Enabled、等级门槛、MaximumFactors、HistoryProvider、采样周期、变化记录门槛、心跳间隔、单资产历史上限、资产数、保留期、趋势、SQL 写入队列和清理批次。

`Memory` Provider 在 Host 重启后丢失历史；`SqlServer` Provider 支持跨重启查询。两者只用于诊断。

## 12. AssetHealthGovernance v3.5

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `Enabled` | 健康事件治理总开关 | 默认 `false` |
| `MinimumEventGrade` | 正式事件最低等级 | 建议从 `Degraded` 起步 |
| Consecutive Unhealthy/Recovery | 创建和恢复连续次数 | 抑制抖动 |
| `EvaluationIntervalSeconds` | 扫描周期 | 不进入控制线程 |
| Retention/Maintenance | Journal 保留和清理 | 与审计备份一致 |
| `MesPushEnabled` | MES Outbox | 默认 `false` |
| MES Batch/Attempts/Retry | 批次、DeadLetter、指数退避 | 防止故障风暴 |

MES 2xx 和 409 视为幂等成功；MES 故障不得阻塞 PLC、任务、命令、路权或调度线程。

## 13. AssetHealthRootCause v3.6

仓库默认：`Enabled=false`、`AllowCycles=false`、Graph Version/Source/ApprovedBy 为空、Nodes/Edges 为空。

核心参数：关联窗口、传播深度、节点/边/事件/候选/路径上限、MinimumCandidateConfidence、图版本/Hash/来源/审批、Nodes、Edges。Confirmed、Rejected、Supplemented 写 SQL Journal，但不会修改活动图。

## 14. AssetHealthMaintenance v3.7

仓库与 Production 默认 `Enabled=false`，RuleSet Version/Source/ApprovedBy 为空，Rules 为空。

核心参数：EvaluationInterval、MaximumRules、MaximumItemsPerRecommendation、查询上限、MinimumRootCauseConfidence、保留和清理、RuleSet Version/Source/Approval/Rules。

精确 RootCauseNodeId 规则优先于类型规则；无匹配规则时不生成建议。训练标签由 Repaired、FalsePositive、NoFaultFound 反馈形成，Approved 不会自动训练或激活模型。

## 15. PluggableRuntime v3.8

仓库与 Production 默认：

```json
{
  "AnomalyDetection": {
    "MachineLearning": {
      "Enabled": false,
      "ManagementApiEnabled": false,
      "PluggableRuntime": {
        "Enabled": false,
        "MaximumTrackedWindows": 5000,
        "InactiveStateRetentionSeconds": 300,
        "Profiles": []
      },
      "Profiles": []
    }
  }
}
```

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `PluggableRuntime.Enabled` | 外部模型覆盖层总开关 | 默认 `false` |
| `MaximumTrackedWindows` | 外部 Profile 特征窗口总上限 | 结合 Profile/设备数压测 |
| `InactiveStateRetentionSeconds` | 无活动异常推理状态保留 | 1～86400 秒 |
| `Profiles[].ProfileId` | 显式接管的现有 ML Profile | 必须唯一且已启用 |
| `Profiles[].AdapterKind` | `Onnx` 或受支持 Adapter | 必须与 Manifest 一致 |
| `Profiles[].Required` | 缺少活动模型是否记为失败 | 不等于 Host 启动失败 |

外部 Profile 额外约束：

- `CollectTrainingData=false`；
- `AutoTrain=false`；
- 同一 Profile 不进入旧 Isolation Forest 引擎；
- `DeploymentMode` 仍使用 Shadow、Canary、Active；
- 活动异常期间禁止切版；
- 外部训练 API 被拒绝；
- Candidate、Detected/Recovered、Fusion 和健康链路继续使用现有实现。

### 15.1 本地目录

```text
<ModelDirectory>/external/<ProfileId>/
├── active.json
├── manifest-<Version>.json
└── <ArtifactFile>
```

`ArtifactFile` 必须是相对文件，禁止绝对路径和 `..`；单 Artifact 最大 256 MB；加载前验证 SHA-256。

### 15.2 Manifest

必填：SchemaVersion、ProfileId、Version、AdapterKind、AdapterId、ArtifactFile、ArtifactSha256、CreatedUtc、Source、ApprovedBy、ApprovedAtUtc、FeatureNames、Means、StandardDeviations、InputName、OutputName、InputShape、ScoreTransform、DecisionThreshold 和 Calibration。

同一模型 Version 不得对应不同 ArtifactSha256、FeatureSchema 或审批元数据。

### 15.3 ONNX

- CPU-only Microsoft ONNX Runtime；
- float32 输入和输出；
- 输入 `[1|-1, featureCount]`；
- InputName / OutputName 与模型一致；
- InferenceSession 按活动版本缓存并在切版/关闭时 Dispose；
- 不允许 URL 下载或云端推理；
- 模型输出只产生诊断 Evidence 和异常生命周期。

### 15.4 状态 API

```text
GET /api/anomaly/ml/adapters/status
```

返回 Adapter、活动版本、ManifestHash、ArtifactSha256、Predictions、Raised、Recovered、Failures、活动异常和窗口指标。

## 16. 启用依赖顺序

```text
AnomalyFusion.Enabled=true
→ AnomalyHealthScoring.Enabled=true
→ AssetHealthGovernance.Enabled=true
→ AssetHealthRootCause.Enabled=true
→ AssetHealthMaintenance.Enabled=true（按需）

MachineLearning.Enabled=true
→ Profile 与 FeatureSchema 冻结
→ 本地模型和 Manifest 审批
→ PluggableRuntime.Enabled=true
→ Shadow
→ Canary
→ Active
```

v3.8 不要求 v3.7 开启，但其 Evidence 可继续进入 Fusion、健康、根因和维修反馈链路。

## 17. TransportObservability、Resilience 与 Simulation

- `TransportObservability`：Trace、Prometheus、OTLP、一致性和调度健康；
- `TransportResilience`：生产就绪、逻辑备份、恢复演练和目录治理；
- `TransportSimulation`：仿真场景、A/B、容量基线和预测上限。

这些能力与 AnomalyEngine 诊断含义不同，不得共用门槛。

## 18. API 安全

复核、反馈、标签审批和模型激活属于治理写操作，必须接入项目身份授权并保存 Actor、Decision、原因和时间。

```text
POST /api/anomaly/maintenance/recommendations/{id}/feedback
POST /api/anomaly/maintenance/training-labels/{id}/review
POST /api/anomaly/ml/models/{profileId}/{version}/activate
```

外部 Profile 不允许在 WCS 内训练。LoadTest/MlLoadTest 专用入口在非测试环境必须返回 404。

## 19. 变更、回退与生产检查

回退顺序：

```text
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=false
→ AnomalyDetection__MachineLearning__Enabled=false（仅需关闭全部 ML 时）
→ AssetHealthMaintenance__Enabled=false（仅需关闭 v3.7 时）
```

生产检查：

- [ ] `Simulator.Enabled=false`；
- [ ] Rules、Profiles、Sources、Graph、Maintenance RuleSet 无示例泄漏；
- [ ] Production ML 和 PluggableRuntime 默认关闭；
- [ ] 真实模型未提交仓库，目录 ACL、备份、Hash 和许可证完整；
- [ ] Manifest Source、审批、FeatureSchema 和张量维度完整；
- [ ] 外部 Profile 禁止在线训练和 AutoTrain；
- [ ] Shadow、Canary、Active 和回滚已演练；
- [ ] 活动异常期间切版被阻断；
- [ ] 坏 Hash 时 Host 健康且模型拒载；
- [ ] 训练标签 Approved 不自动更新活动模型；
- [ ] 无 PLC 写入、设备停止、任务取消或调度修改；
- [ ] 现场模型、权限、网络、许可证和正式投产已独立签署。
