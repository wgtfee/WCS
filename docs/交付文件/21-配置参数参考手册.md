# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 目的

本文汇总 Wcs.Host 中与 EMS/RGV 调度、PLC、Telemetry、异常检测、机器学习、运输周期、证据融合、可观测性、韧性、仿真、数据库和部署相关的主要配置项。实际默认值以当前 `appsettings.json` 和代码为准，生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源和合并规则

ASP.NET Core 配置优先级通常为：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线表示层级：

```text
ConnectionStrings__WcsDb=...
Storage__Telemetry__InfluxDb__Token=...
AnomalyDetection__MachineLearning__Enabled=true
AnomalyFusion__Enabled=true
```

数组可能按下标合并。通用配置中的下列数组必须保持空数组，现场应在最终环境配置中完整提供：

- `AnomalyDetection:Rules`；
- `AnomalyDetection:MachineLearning:Profiles`；
- `AnomalyFusion:Sources`。

不要在基础数组中放示例对象，否则环境配置可能只覆盖部分字段，造成规则、Profile 或来源权重泄漏。

## 3. ConnectionStrings

```json
{
  "ConnectionStrings": {
    "WcsDb": "..."
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| WcsDb | SQL Server 连接字符串 | 使用专用最小权限账号，不使用开发密码 |

业务任务、报警、资源锁、异常生命周期等仍使用 SQL Server，不随 PLC Telemetry Provider 切换。

## 4. Simulator

```json
{
  "Simulator": {
    "Enabled": true,
    "TransportTps": 2
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | 启用内置模拟轮询，并禁止真实 PLC 连接 | 实车现场必须为 false |
| TransportTps | 模拟运输速率 | 仅开发、演示和隔离测试使用 |

`Enabled=true` 时模拟信号仍经过结构体解析、StateCenter、EventBus、Telemetry、异常检测和 SignalR 链路。

## 5. WcsOptions

### 5.1 PlcPolling

```json
{
  "WcsOptions": {
    "PlcPolling": {
      "Enabled": true,
      "IntervalMs": 100
    }
  }
}
```

| 参数 | 说明 | 建议范围 |
|---|---|---|
| Enabled | PLC 轮询总开关 | 现场 true |
| IntervalMs | 基础轮询间隔 | 50～1000ms，按 PLC 和网络负载验证 |

### 5.2 Persistence

| 参数 | 说明 | 建议 |
|---|---|---|
| IntervalSeconds | 通用状态持久化周期 | 典型 5～30 秒 |

关键命令和状态变化不能只依赖周期快照。

### 5.3 Snapshot

| 参数 | 说明 |
|---|---|
| IntervalSeconds | 快照周期 |
| MaxSnapshots | 内存/仓库快照保留数量 |

### 5.4 AlarmMonitor / AlarmRules

用于通用 WCS 报警监视和规则配置。PLC 异常检测产生的正式异常可通过 `RaiseAlarm` 桥接到 AlarmCenter，但不会替代原有报警规则。

## 6. Storage.Telemetry

```json
{
  "Storage": {
    "Telemetry": {
      "Provider": "SqlServer",
      "DurabilityMode": "Buffered",
      "ChannelCapacity": 100000,
      "BatchSize": 1000,
      "FlushIntervalMs": 1000,
      "RetryDelayMs": 2000,
      "WalBatchSize": 256,
      "WalFlushIntervalMs": 10,
      "SpoolDirectory": "data/plc-telemetry-spool",
      "Site": "default",
      "Measurement": "plc_signal",
      "InfluxDb": {
        "ApiVersion": "V2",
        "Url": "http://127.0.0.1:8086",
        "Token": "",
        "Organization": "wcs",
        "Bucket": "wcs_plc",
        "Database": "wcs_plc",
        "Gzip": false
      }
    }
  }
}
```

### 6.1 通用参数

| 参数 | 说明 | 建议 |
|---|---|---|
| Provider | `Disabled`、`SqlServer`、`InfluxDb` | 按现场部署选择 |
| DurabilityMode | `Buffered` 或 `WriteAhead` | 高耐久现场使用 WriteAhead |
| ChannelCapacity | 内存队列容量 | 根据采样峰值和内存压测 |
| BatchSize | 单批数据库写入点数 | 500～2000 起步 |
| FlushIntervalMs | 正常批量刷新间隔 | 500～2000ms |
| RetryDelayMs | Provider 失败重试间隔 | 避免过于频繁 |
| WalBatchSize | WriteAhead 单个 WAL 批大小 | 默认 256 |
| WalFlushIntervalMs | WAL 聚合等待 | 越小延迟越低、IO 越高 |
| SpoolDirectory | WAL/spool 目录 | 使用本地持久化 SSD 和受控 ACL |
| Site | 时序标签中的站点 | 使用稳定站点编号 |
| Measurement | Influx measurement/table 名 | 上线后避免随意更改 |

### 6.2 InfluxDb

| 参数 | 说明 |
|---|---|
| ApiVersion | `V2` 或实现支持的 V3 模式 |
| Url | InfluxDB 内网地址 |
| Token | 访问令牌，禁止提交生产值 |
| Organization | InfluxDB 组织 |
| Bucket | V2 Bucket |
| Database | V3/兼容数据库名 |
| Gzip | 是否压缩写入请求 |

### 6.3 运行门槛

必须监控：

- dropped；
- conservationDelta；
- queue / in-flight；
- walPending / spoolPending；
- batch failures 和 last error；
- spool 目录容量。

## 7. AnomalyDetection v1

```json
{
  "AnomalyDetection": {
    "Enabled": false,
    "WindowSize": 120,
    "MinimumSamples": 30,
    "MaximumTrackedRuleSignals": 20000,
    "InactiveStateRetentionSeconds": 300,
    "RelatedSampleRetentionSeconds": 60,
    "MaximumCleanupItemsPerSweep": 10000,
    "ObserveThreshold": 0.70,
    "WarningThreshold": 0.85,
    "AlarmThreshold": 0.95,
    "ConsecutiveWarningCount": 3,
    "ConsecutiveAlarmCount": 5,
    "RecoveryCount": 10,
    "DurationSweepIntervalMs": 1000,
    "AlarmDelayRaiseMs": 0,
    "AlarmDelayRecoverMs": 1000,
    "Rules": []
  }
}
```

### 7.1 引擎参数

| 参数 | 说明 | 注意事项 |
|---|---|---|
| Enabled | v1 总开关 | 默认 false |
| WindowSize | Median/MAD 最大窗口样本数 | 仅统计规则创建窗口 |
| MinimumSamples | 统计基线最低样本数 | 太小容易不稳定 |
| MaximumTrackedRuleSignals | 最大规则×信号状态数 | 需结合高基数压测 |
| InactiveStateRetentionSeconds | 已恢复且空闲状态 TTL | 活动异常不会淘汰 |
| RelatedSampleRetentionSeconds | 一致性关联样本 TTL | 防止陈旧状态参与判断 |
| MaximumCleanupItemsPerSweep | 单次清理上限 | 避免长停顿 |
| ObserveThreshold | 观察级分数 | 主要用于记录 |
| WarningThreshold | Warning 门槛 | 结合连续计数 |
| AlarmThreshold | 高等级门槛 | 不替代 PLC 联锁 |
| ConsecutiveWarningCount | 默认连续异常次数 | 抑制毛刺 |
| ConsecutiveAlarmCount | 默认高等级连续次数 | 应高于 Warning 或按项目确认 |
| RecoveryCount | 默认连续恢复次数 | 防止反复抖动 |
| DurationSweepIntervalMs | 持续时间规则扫描周期 | 不宜大于允许误差 |
| AlarmDelayRaiseMs | 报警桥接抬升延迟 | 0 表示无额外延迟 |
| AlarmDelayRecoverMs | 恢复延迟 | 默认 1000ms |

### 7.2 PlcAnomalyRule

| 参数 | 说明 |
|---|---|
| RuleId | 稳定唯一规则编号 |

| Minimum / Maximum | 数值上下限 |
| MaximumRatePerSecond | 最大单位秒变化率 |
| MaximumTrueDurationMs | Boolean true 最大持续时间 |
| StatisticalBaselineEnabled | 启用 Median/MAD |
| MadMultiplier | MAD 倍数 |
| MinimumMad | MAD 最小保护值 |
| RelatedSignalPattern | 一致性关联信号 |
| WhenValueEquals | 主信号触发值 |
| RelatedExpectedValue | 关联信号期望值 |
| RelatedMinimum / RelatedMaximum | 关联数值允许区间 |
| MaximumRelatedAgeMs | 关联样本最大年龄 |
| Severity | Observe、Warning、Error、Critical |
| RaiseAlarm | 是否桥接 AlarmCenter |
| ConsecutiveAbnormalCount | 规则级异常次数覆盖 |
| ConsecutiveRecoveryCount | 规则级恢复次数覆盖 |
| Description | 现场可读描述 |

## 9. TransportCycleAnalysis v3.2

```json
{
  "TransportCycleAnalysis": {
    "Enabled": false,
    "MinimumBaselineCycles": 30,
    "MaximumBaselineCyclesPerContext": 500,
    "MaximumTrackedExecutions": 20000,
    "MaximumCompletedCycles": 5000,
    "MaximumAnomalies": 5000,
    "MadMultiplier": 6.0,
    "MinimumMadMilliseconds": 100.0,
    "MinimumTotalDurationMilliseconds": 0,
    "MinimumPhaseDurationMilliseconds": 0
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | 周期分析总开关 | 默认 false，先在测试环境开启 |
| MinimumBaselineCycles | 开始检测前最少合法正常周期 | 30～100 起步 |
| MaximumBaselineCyclesPerContext | 每路线/载荷上下文基线容量 | 按路线数和内存压测 |
| MaximumTrackedExecutions | 最大并行跟踪执行数 | 大于最大在途任务数 |
| MaximumCompletedCycles | 最近周期 API 保留量 | 有界内存审计窗口 |
| MaximumAnomalies | 最近周期异常保留量 | 有界内存审计窗口 |
| MadMultiplier | 慢阶段/慢周期 MAD 倍数 | 6～10 起步 |
| MinimumMadMilliseconds | 稳健尺度下限 | 防止完全一致基线过敏 |
| MinimumTotalDurationMilliseconds | 总周期最低检测耗时 | 可过滤极短任务 |
| MinimumPhaseDurationMilliseconds | 阶段最低检测耗时 | 可过滤毫秒级阶段 |

故障、取消和非法完成周期不会进入正常基线。

## 10. AnomalyFusion v3.3

```json
{
  "AnomalyFusion": {
    "Enabled": false,
    "ChannelCapacity": 20000,
    "EvidenceRetentionSeconds": 300,
    "RecoveredEvidenceRetentionSeconds": 60,
    "InactiveStateRetentionSeconds": 600,
    "MaximumTrackedAssets": 20000,
    "MaximumEvidencePerAsset": 100,
    "MaximumSnapshots": 5000,
    "ObserveThreshold": 0.35,
    "WarningThreshold": 0.65,
    "AlarmThreshold": 0.85,
    "RecoveryThreshold": 0.25,
    "MinimumIndependentSourcesForAlarm": 2,
    "ConsecutiveWarningEvaluations": 2,
    "ConsecutiveAlarmEvaluations": 2,
    "ConsecutiveRecoveryEvaluations": 3,
    "SourceDiversityBonus": 0.05,
    "MaximumSourceDiversityBonus": 0.15,
    "Sources": []
  }
}
```

### 10.1 参数

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | Fusion 总开关 | 默认 false；先只读启用 |
| ChannelCapacity | Evidence 有界队列容量 | 结合峰值 Written/Read/Pending 压测 |
| EvidenceRetentionSeconds | 活动 Evidence 默认 TTL | 不替代 PLC 恢复事件 |
| RecoveredEvidenceRetentionSeconds | 已恢复 Evidence 保留时间 | 30～300 秒起步 |
| InactiveStateRetentionSeconds | 空闲 Normal 资产 TTL | 300～3600 秒起步 |
| MaximumTrackedAssets | 最大资产状态数 | 高于现场设备数并保留余量 |
| MaximumEvidencePerAsset | 单资产最大 Evidence 数 | 防止异常风暴无限增长 |
| MaximumSnapshots | 状态迁移历史上限 | 仅内存审计窗口 |
| ObserveThreshold | Observe 门槛 | 小于 WarningThreshold |
| WarningThreshold | Warning 门槛 | 结合连续评估 |
| AlarmThreshold | Alarm 分数门槛 | 还需满足独立来源数 |
| RecoveryThreshold | Warning/Alarm 恢复门槛 | 必须低于 WarningThreshold |
| MinimumIndependentSourcesForAlarm | Alarm 最少独立来源 | 默认 2，不建议降为 1 |
| ConsecutiveWarningEvaluations | Warning 连续评估次数 | 抑制瞬时毛刺 |
| ConsecutiveAlarmEvaluations | Alarm 连续评估次数 | 默认 2 |
| ConsecutiveRecoveryEvaluations | 恢复连续评估次数 | 防止状态抖动 |
| SourceDiversityBonus | 每增加一个独立来源的有限奖励 | 默认 0.05 |
| MaximumSourceDiversityBonus | 来源多样性奖励上限 | 默认 0.15 |
| Sources | 来源权重覆盖数组 | 基础配置保持空数组 |

### 10.2 来源策略

标准 Source：

```text
RULE_THRESHOLD
RULE_RATE
RULE_DURATION
RULE_STATISTICAL
RULE_CONSISTENCY
ISOLATION_FOREST
PEER_MEDIAN_MAD
CYCLE_SEQUENCE
CYCLE_PHASE_DURATION
CYCLE_TOTAL_DURATION
```

需要覆盖时在最终环境配置中完整提供：

```json
{
  "AnomalyFusion": {
    "Sources": [
      {
        "Source": "ISOLATION_FOREST",
        "Weight": 0.85,
        "DefaultConfidence": 0.75
      }
    ]
  }
}
```

来源权重修改必须通过回放、影子观察和审批。不要用提高权重掩盖模型准确性问题。

### 10.3 运行门槛

必须监控：

- `Ingress.Written`；
- `Ingress.Read`；
- `Ingress.Pending`；
- `Ingress.Dropped`；
- `Fusion.EvidenceDropped`；
- `TrackedAssets`；
- `ActiveEvidence`；
- `EvidenceExpired`；
- `EvictedAssets`；
- Warning、Alarm、Recovery 转换数量。

守恒关系：

```text
Pending = max(0, Written - Dropped - Read)
```

Fusion v3.3 只读，不得仅凭配置把结果接入自动停止设备或调度决策。

## 17. Desktop、IIS 和 Host

Desktop 至少配置 Host ServerUrl，不保存数据库、PLC 凭据和用户明文密码。

IIS/Host 关注：

- ASPNETCORE_ENVIRONMENT；
- 监听地址和端口；
- HTTPS 证书；
- 服务账号；
- stdout 和 Serilog；
- 应用池回收；
- 反向代理超时；
- 模型、训练、WAL 和备份目录权限。

## 18. API 安全开关

只读运行接口：

- `/api/anomaly/status`；
- `/api/anomaly/active`；
- `/api/anomaly/ml/status`；
- `/api/transport/cycle-analysis/status`；
- `/api/anomaly/fusion/status`；
- `/api/anomaly/fusion/assets`；
- `/api/anomaly/fusion/assets/{assetId}`。

受控管理接口：

- 训练、冻结数据集、审批、模型列表和激活 API 仅在 `ManagementApiEnabled=true` 时存在。

测试专用接口：

- `/api/anomaly/load`；
- `/api/anomaly/load/collect-gc`；
- `/api/anomaly/fusion/load/plc-lifecycle`；
- `/api/transport/cycle-analysis/load/scenario`：仅 `LoadTest`；
- `/api/anomaly/ml/load`：仅 `MlLoadTest`。

生产环境不得设置为 LoadTest 或 MlLoadTest。

## 19. 参数变更流程

```text
记录当前配置、规则和模型版本
→ 说明变更原因、范围和影响设备
→ 离线测试/回放/影子运行
→ 申请和独立审批
→ 备份配置、模型和数据
→ 应用变更
→ 观察 telemetry、异常、Fusion 和资源指标
→ 必要时关闭 Fusion、报警或回滚模型
```
