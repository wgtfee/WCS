# EMS/RGV 与 PLC 异常检测配置参数参考手册

## 1. 目的

本文汇总 Wcs.Host 中与 EMS/RGV 调度、PLC、Telemetry、异常检测、机器学习、可观测性、韧性、仿真、数据库和部署相关的主要配置项。实际默认值以当前 `appsettings.json` 和代码为准，生产修改必须经过版本、测试和变更管理。

## 2. 配置源和合并规则

ASP.NET Core 配置通常来自：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

注意：数组可能按下标合并。通用配置中的 `AnomalyDetection:Rules` 和 `MachineLearning:Profiles` 应保持空数组，现场完整配置应由最终环境配置提供，避免示例字段泄漏。

环境变量使用双下划线表示层级，例如：

```text
ConnectionStrings__WcsDb=...
Storage__Telemetry__InfluxDb__Token=...
AnomalyDetection__MachineLearning__Enabled=true
```

## 3. ConnectionStrings

```json
{
  "ConnectionStrings": {
    "WcsDb": "..."
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| WcsDb | SQL Server 连接字符串 | 使用专用最小权限账号，不使用开发密码 |

业务任务、报警、资源锁、异常生命周期等仍使用 SQL Server，不随 PLC Telemetry Provider 切换。

## 4. Simulator

```json
{
  "Simulator": {
    "Enabled": true,
    "TransportTps": 2
  }
}
```

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | 启用内置模拟轮询，并禁止真实 PLC 连接 | 实车现场必须为 false |
| TransportTps | 模拟运输速率 | 仅开发、演示和隔离测试使用 |

`Enabled=true` 时模拟信号仍经过结构体解析、StateCenter、EventBus、Telemetry、异常检测和 SignalR 链路。

## 5. WcsOptions

### 5.1 PlcPolling

```json
{
  "WcsOptions": {
    "PlcPolling": {
      "Enabled": true,
      "IntervalMs": 100
    }
  }
}
```

| 参数 | 说明 | 建议范围 |
|---|---|---|
| Enabled | PLC 轮询总开关 | 现场 true |
| IntervalMs | 基础轮询间隔 | 50～1000ms，按 PLC 和网络负载验证 |

### 5.2 Persistence

| 参数 | 说明 | 建议 |
|---|---|---|
| IntervalSeconds | 通用状态持久化周期 | 典型 5～30 秒 |

关键命令和状态变化不能只依赖周期快照。

### 5.3 Snapshot

| 参数 | 说明 |
|---|---|
| IntervalSeconds | 快照周期 |
| MaxSnapshots | 内存/仓库快照保留数量 |

### 5.4 AlarmMonitor / AlarmRules

用于通用 WCS 报警监视和规则配置。PLC 异常检测产生的正式异常可通过 `RaiseAlarm` 桥接到 AlarmCenter，但不会替代原有报警规则。

## 6. Storage.Telemetry

```json
{
  "Storage": {
    "Telemetry": {
      "Provider": "SqlServer",
      "DurabilityMode": "Buffered",
      "ChannelCapacity": 100000,
      "BatchSize": 1000,
      "FlushIntervalMs": 1000,
      "RetryDelayMs": 2000,
      "WalBatchSize": 256,
      "WalFlushIntervalMs": 10,
      "SpoolDirectory": "data/plc-telemetry-spool",
      "Site": "default",
      "Measurement": "plc_signal",
      "InfluxDb": {
        "ApiVersion": "V2",
        "Url": "http://127.0.0.1:8086",
        "Token": "",
        "Organization": "wcs",
        "Bucket": "wcs_plc",
        "Database": "wcs_plc",
        "Gzip": false
      }
    }
  }
}
```

### 6.1 通用参数

| 参数 | 说明 | 建议 |
|---|---|---|
| Provider | `Disabled`、`SqlServer`、`InfluxDb` | 按现场部署选择 |
| DurabilityMode | `Buffered` 或 `WriteAhead` | 高耐久现场使用 WriteAhead |
| ChannelCapacity | 内存队列容量 | 根据采样峰值和内存压测 |
| BatchSize | 单批数据库写入点数 | 500～2000 起步 |
| FlushIntervalMs | 正常批量刷新间隔 | 500～2000ms |
| RetryDelayMs | Provider 失败重试间隔 | 避免过于频繁 |
| WalBatchSize | WriteAhead 单个 WAL 批大小 | 默认 256 |
| WalFlushIntervalMs | WAL 聚合等待 | 越小延迟越低、IO 越高 |
| SpoolDirectory | WAL/spool 目录 | 使用本地持久化 SSD 和受控 ACL |
| Site | 时序标签中的站点 | 使用稳定站点编号 |
| Measurement | Influx measurement/table 名 | 上线后避免随意更改 |

### 6.2 InfluxDb

| 参数 | 说明 |
|---|---|
| ApiVersion | `V2` 或实现支持的 V3 模式 |
| Url | InfluxDB 内网地址 |
| Token | 访问令牌，禁止提交生产值 |
| Organization | InfluxDB 组织 |
| Bucket | V2 Bucket |
| Database | V3/兼容数据库名 |
| Gzip | 是否压缩写入请求 |

### 6.3 运行门槛

必须监控：

- dropped；
- conservationDelta；
- queue / in-flight；
- walPending / spoolPending；
- batch failures 和 last error；
- spool 目录容量。

## 7. AnomalyDetection v1

```json
{
  "AnomalyDetection": {
    "Enabled": false,
    "WindowSize": 120,
    "MinimumSamples": 30,
    "MaximumTrackedRuleSignals": 20000,
    "InactiveStateRetentionSeconds": 300,
    "RelatedSampleRetentionSeconds": 60,
    "MaximumCleanupItemsPerSweep": 10000,
    "ObserveThreshold": 0.70,
    "WarningThreshold": 0.85,
    "AlarmThreshold": 0.95,
    "ConsecutiveWarningCount": 3,
    "ConsecutiveAlarmCount": 5,
    "RecoveryCount": 10,
    "DurationSweepIntervalMs": 1000,
    "AlarmDelayRaiseMs": 0,
    "AlarmDelayRecoverMs": 1000,
    "Rules": []
  }
}
```

### 7.1 引擎参数

| 参数 | 说明 | 注意事项 |
|---|---|---|
| Enabled | v1 总开关 | 默认 false |
| WindowSize | Median/MAD 最大窗口样本数 | 仅统计规则创建窗口 |
| MinimumSamples | 统计基线最低样本数 | 太小容易不稳定 |
| MaximumTrackedRuleSignals | 最大规则×信号状态数 | 需结合高基数压测 |
| InactiveStateRetentionSeconds | 已恢复且空闲状态 TTL | 活动异常不会淘汰 |
| RelatedSampleRetentionSeconds | 一致性关联样本 TTL | 防止陈旧状态参与判断 |
| MaximumCleanupItemsPerSweep | 单次清理上限 | 避免长停顿 |
| ObserveThreshold | 观察级分数 | 主要用于记录 |
| WarningThreshold | Warning 门槛 | 结合连续计数 |
| AlarmThreshold | 高等级门槛 | 不替代 PLC 联锁 |
| ConsecutiveWarningCount | 默认连续异常次数 | 抑制毛刺 |
| ConsecutiveAlarmCount | 默认高等级连续次数 | 应高于 Warning 或按项目确认 |
| RecoveryCount | 默认连续恢复次数 | 防止反复抖动 |
| DurationSweepIntervalMs | 持续时间规则扫描周期 | 不宜大于允许误差 |
| AlarmDelayRaiseMs | 报警桥接抬升延迟 | 0 表示无额外延迟 |
| AlarmDelayRecoverMs | 恢复延迟 | 默认 1000ms |

### 7.2 PlcAnomalyRule

| 参数 | 说明 |
|---|---|
| RuleId | 稳定唯一规则编号 |
| Enabled | 规则开关 |
| PlcPattern | PLC 通配符 |
| DevicePattern | DeviceId 通配符 |
| SignalPattern | 主信号通配符 |
| Minimum / Maximum | 数值上下限 |
| MaximumRatePerSecond | 最大单位秒变化率 |
| MaximumTrueDurationMs | Boolean true 最大持续时间 |
| StatisticalBaselineEnabled | 启用 Median/MAD |
| MadMultiplier | MAD 倍数 |
| MinimumMad | MAD 最小保护值 |
| RelatedSignalPattern | 一致性关联信号 |
| WhenValueEquals | 主信号触发值 |
| RelatedExpectedValue | 关联信号期望值 |
| RelatedMinimum / RelatedMaximum | 关联数值允许区间 |
| MaximumRelatedAgeMs | 关联样本最大年龄 |
| Severity | Observe、Warning、Error、Critical |
| RaiseAlarm | 是否桥接 AlarmCenter |
| ConsecutiveAbnormalCount | 规则级异常次数覆盖 |
| ConsecutiveRecoveryCount | 规则级恢复次数覆盖 |
| Description | 现场可读描述 |

## 8. AnomalyDetection.MachineLearning v2

```json
{
  "AnomalyDetection": {
    "MachineLearning": {
      "Enabled": false,
      "ManagementApiEnabled": false,
      "ModelDirectory": "data/anomaly-models",
      "TrainingDirectory": "data/anomaly-training",
      "MaintenanceIntervalMs": 1000,
      "MaximumTrackedWindows": 20000,
      "InactiveInferenceStateRetentionSeconds": 300,
      "Profiles": []
    }
  }
}
```

### 8.1 全局参数

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | ML 总开关 | 默认 false |
| ManagementApiEnabled | 训练、版本列表和激活 API | 默认 false，仅维护窗口临时开启 |
| ModelDirectory | 模型版本和 active.json 目录 | 独立持久化目录并备份 |
| TrainingDirectory | 特征训练数据目录 | 受控 ACL 和数据保留策略 |
| MaintenanceIntervalMs | 窗口/状态维护周期 | 默认 1000ms |
| MaximumTrackedWindows | 最大活动窗口数量 | 按设备数和内存压测 |
| InactiveInferenceStateRetentionSeconds | 推理状态 TTL | 不影响活动异常 |
| Profiles | 设备族模型配置 | 基础配置保持空数组 |

### 8.2 PlcMlProfile

| 参数 | 说明 |
|---|---|
| ProfileId | 稳定唯一编号 |
| Enabled | Profile 开关 |
| PlcPattern | PLC 匹配模式 |
| DevicePattern | 设备族匹配模式 |
| WindowSeconds | 固定特征窗口秒数 |
| MinimumSamplesPerSignal | 每信号完整窗口最低样本数 |
| CollectTrainingData | 是否收集训练窗口 |
| AutoTrain | 是否达到最低数量后自动训练 |
| MinimumTrainingWindows | 允许训练的最低窗口数 |
| MaximumTrainingWindows | 本地保留/读取的最大训练窗口数 |
| TreeCount | Isolation Forest 树数 |
| SampleSize | 每棵树子采样数 |
| Contamination | 校准集尾部比例 |
| RandomSeed | 确定性随机种子 |
| ObserveThreshold | 最低观察阈值 |
| WarningThreshold | 正式异常最低阈值 |
| AlarmThreshold | 高等级参考阈值 |
| ConsecutiveAbnormalCount | 正式激活连续窗口数 |
| ConsecutiveRecoveryCount | 正式恢复连续正常窗口数 |
| Severity | 生命周期严重级别 |
| RaiseAlarm | 是否桥接 AlarmCenter |
| Signals | 特征信号列表 |

### 8.3 PlcMlSignalDefinition

| 参数 | 说明 |
|---|---|
| Name | 特征中的稳定信号名 |
| Pattern | PLC 字段通配符 |
| Kind | `Numeric` 或 `Boolean` |

模型版本会固化特征名称和顺序。修改 Signals 后不能直接加载旧模型，应重新训练并完成验收。

## 9. TransportObservability

```json
{
  "TransportObservability": {
    "Enabled": true,
    "ConsistencyInspectionIntervalSeconds": 30,
    "HealthEvaluationIntervalSeconds": 10,
    "TraceRetentionCount": 5000,
    "DegradedScoreThreshold": 80,
```

| 参数 | 说明 |

| EnableOtlpExporter | 是否发送 OTLP |
| OtlpEndpoint | 离线 Collector 地址 |

## 10. TransportResilience

```json
{
  "TransportResilience": {
    "Enabled": true,
    "PreflightIntervalSeconds": 60,
    "AutomaticBackupEnabled": true,
    "BackupIntervalMinutes": 60,
    "BackupRetentionCount": 48,
    "MaximumJournalRecords": 5000,
    "MaximumBackupAgeMinutes": 180,
    "RequireReadyBeforeAutomaticBackup": false,
    "BackupDirectory": "data/transport-backups"
  }
}
```

主要参数用于生产就绪检查、自动逻辑备份、保留份数、Journal 上限、备份过期和目录。模型、训练数据和 telemetry spool 不属于该逻辑备份的自动替代品，需单独纳入备份策略。

## 11. TransportSimulation

主要安全上限：

- MaximumScenarioTasks；
- MaximumStoredRuns；
- MaximumStoredComparisons；
- ForecastBucketSeconds；
- DefaultTravelSeconds；
- DefaultServiceSeconds；
- SustainableP95WaitingSeconds；
- SustainableDeadlineMissRatePercent；
- HistoricalJournalLimit。

生产环境不要随意提高容量上限，更大规模仿真使用独立离线环境。

## 12. 生产整定参数

`TransportProductionTuningOptions` 管理：

- 任务老化和交期权重；
- 恢复任务权重；
- 站点拥堵惩罚；
- 每周期最大派单数；
- 派单和趋势周期；
- 单轨方向等待老化；
- 最低派单电量。

这些参数应通过配置版本和治理流程保存。

## 15. Desktop、IIS 和 Host

Desktop 至少配置 Host ServerUrl，不保存数据库、PLC 凭据和用户明文密码。

IIS/Host 关注：

- ASPNETCORE_ENVIRONMENT；
- 监听地址和端口；
- HTTPS 证书；
- 服务账号；
- stdout 和 Serilog；
- 应用池回收；
- 反向代理超时；
- 模型、训练、WAL 和备份目录权限。

## 16. API 安全开关

- `/api/anomaly/status` 和 `/api/anomaly/active`：运行状态查询；
- `/api/anomaly/ml/status`：ML 状态查询；
- 训练、模型列表和激活 API：仅 `ManagementApiEnabled=true` 时存在；
- `/api/anomaly/load`：仅 `LoadTest` 环境；
- `/api/anomaly/ml/load`：仅 `MlLoadTest` 环境。

生产环境不得设置为 LoadTest 或 MlLoadTest。

## 17. 参数变更流程

```text
记录当前值、规则版本和模型版本
→ 说明变更原因和影响设备
→ 离线测试/影子运行
→ 申请和独立审批
→ 备份配置、模型和数据
→ 应用变更
→ 观察 telemetry、异常和资源指标
→ 必要时关闭报警或回滚模型
```
