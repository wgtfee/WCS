# EMS/RGV、PLC 异常检测与统一仿真配置参数参考手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 文档版本 | V2.5 |
| 对应分支 | `feature/simulation-s0-governance` |
| 最新范围 | EMS/RGV 十二阶段、Telemetry、AnomalyEngine v1～v3.9、Simulation S0 |
| 安全原则 | 诊断、维修建议、模型、Forecast 和仿真结果不得替代 PLC 联锁、设备安全回路或调度状态机 |

本文汇总 `Wcs.Host` 主要配置。实际默认值以代码和 `appsettings*.json` 为准；生产修改必须经过版本、测试、审批和变更管理。

## 2. 配置源与凭据

配置优先级：

```text
appsettings.json
→ appsettings.{Environment}.json
→ 环境变量
→ 命令行或外部安全配置源
```

环境变量使用双下划线：

```text
ConnectionStrings__WcsDb=...
AnomalyFusion__Enabled=true
AssetHealthGovernance__Enabled=true
AssetHealthRootCause__Graph__Version=site-graph-v1
AssetHealthMaintenance__RuleSet__Version=maintenance-rules-v1
AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=true
AssetFailureForecast__Enabled=true
Simulator__Enabled=true
SimulationGovernance__Enabled=true
SimulationGovernance__MaximumRegisteredScenarioVersions=10000
SimulationGovernance__MaximumEvidenceValueCharacters=4096
```

规则、Profile、Fusion Sources、PLC 点位、MES 密钥、根因图、维修规则、真实模型、数据集、许可证、场景、Manifest 和审批信息不得以示例值写入通用生产配置。凭据必须由环境变量或安全配置中心注入。

## 3. SQL Server

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `ConnectionStrings:WcsDb` | SQL Server 连接字符串 | 使用最小权限账号，禁止明文提交 |

SQL Server 承载任务、报警、异常生命周期、健康历史、事件、根因、维修反馈，以及 v3.9 模型版本、Forecast 和 Outcome Journal。v3.8/v3.9 模型文件与 active Manifest 存储在本地受控目录。S0 场景 Registry 仅在内存中，不写生产 SQL；持久化场景仓库属于 S1 后续范围。

## 4. Simulator、SimulationGovernance 与 PLC

| 参数 | 说明 | 生产建议 |
|---|---|---|
| `Simulator:Enabled` | 模拟信号并禁止真实 PLC 后台服务 | Production 必须 `false` |
| `Simulator:TransportTps` | 旧模拟任务生成速率 | 仅用于批准的仿真环境 |
| `SimulationGovernance:Enabled` | 统一场景治理和 API 总开关 | Production 不得开启 |
| `ScenarioDirectory` | 场景文件目录 | 必填，最长 1,024 字符，不存放真实生产数据 |
| `MaximumScenarioBytes` | 单场景内容上限 | 默认 1 MB，硬上限 16 MB |
| `MaximumRegisteredScenarioVersions` | 进程内 Registry 版本上限 | 默认 10,000，硬上限 100,000 |
| `MaximumEvidenceRecords` | 单次 Evidence 记录上限 | 默认 10,000，硬上限 1,000,000 |
| `MaximumEvidenceValueCharacters` | 单条 Evidence Value 字符上限 | 默认 4,096，硬上限 1,048,576 |
| `AllowedEnvironments` | 允许访问治理 API 的环境 | 仅 `Simulation`、`SimulationLoadTest` |
| `WcsOptions:PlcPolling:Enabled` | PLC 轮询总开关 | 按点位验收开启 |
| `WcsOptions:PlcPolling:IntervalMs` | 基础轮询周期 | 50～1000ms，必须压测 |
| `PlcConnections` / `PlcBlocks` | S7 连接和 DB 块 | 使用正式点位版本 |
| S7CommPlus / Modbus / OPC UA / Tag Poll | 其他驱动配置 | 密码和证书外部注入 |

仿真治理需要同时满足：

```text
Simulator.Enabled=true
AND SimulationGovernance.Enabled=true
AND Environment ∈ {Simulation, SimulationLoadTest}
AND Environment != Production
```

其他环境的 `/api/simulation/governance/**` 返回 404。Production 即使误把 Simulator 设置为 true或错误加入白名单，API 仍优先拒绝，模拟后台服务也必须失败关闭。

## 5. 通用 WCS 运行时

- `WcsOptions:Persistence:IntervalSeconds`：通用状态持久化周期；
- `WcsOptions:Snapshot:IntervalSeconds`：快照周期；
- `WcsOptions:Snapshot:MaxSnapshots`：内存快照上限；
- `WcsOptions:AlarmMonitor` / `AlarmRules`：报警监控与防抖。

关键命令、路权、任务状态和安全状态不能只依赖周期快照。

## 6. PLC Telemetry

| 参数 | 说明 |
|---|---|
| `Storage:Telemetry:Provider` | `Disabled`、`SqlServer`、`InfluxDb` |
| `DurabilityMode` | `Buffered` 或 `WriteAhead` |
| `ChannelCapacity` | 有界队列容量 |
| `BatchSize` / `FlushIntervalMs` | 批量写入参数 |
| `RetryDelayMs` | Provider 失败重试间隔 |
| `WalBatchSize` / `WalFlushIntervalMs` | WAL 参数 |
| `SpoolDirectory` | 本地持久化目录 |
| `Site` / `Measurement` | 时序标签和 measurement |

必须监控 dropped、conservationDelta、queue、in-flight、WAL pending、目录容量和失败批次。

## 7. AnomalyDetection v1

主要参数：`Enabled`、`WindowSize`、`MinimumSamples`、最大信号数、状态 TTL、关联样本保留、Observe/Warning/Alarm 门槛、连续确认、恢复次数和 `Rules`。基础 `Rules` 数组保持为空。

## 8. Machine Learning v2/v2.1/v3.1

| 参数 | 说明 | 建议 |
|---|---|---|
| `Enabled` | ML 总开关 | 默认关闭，先 Shadow |
| `ManagementApiEnabled` | 训练、审批、激活、回滚和 Forecast 写 API | 默认关闭并接入身份权限 |
| `ModelDirectory` | 模型和活动版本目录 | 持久化、受控 ACL、备份 |
| `TrainingDirectory` | 特征和冻结数据集 | 受控 ACL |
| `MaximumTrackedWindows` | 最大活动窗口 | 结合现场规模压测 |
| `Profiles` | 模型 Profile 数组 | 通用和 Production 配置为空 |

Profile 参数包括信号、窗口、训练数量、Isolation Forest、阈值、连续异常/恢复、Shadow/Canary/Active、漂移、上下文和同群参数。

## 9. TransportCycleAnalysis v3.2

主要参数包括最小基线周期数、上下文最大周期数、最大执行数、已完成周期/异常上限、MAD 倍数以及总周期和阶段绝对保护值。

## 10. AnomalyFusion v3.3

| 参数 | 说明 |
|---|---|
| `Enabled` | Fusion 总开关，默认 `false` |
| `ChannelCapacity` | Evidence 有界队列 |
| Evidence Retention | 活动和恢复证据 TTL |
| MaximumTrackedAssets / EvidencePerAsset | 容量上限 |
| Observe/Warning/Alarm/Recovery | 融合和恢复门槛 |
| `MinimumIndependentSourcesForAlarm` | Alarm 最少独立来源 |
| `Consecutive*Evaluations` | 防抖和恢复次数 |
| `Sources` | 来源权重数组，通用配置为空 |

## 11. AnomalyHealthScoring v3.4

主要参数：Enabled、等级门槛、MaximumFactors、HistoryProvider、采样周期、变化记录门槛、心跳间隔、单资产历史上限、资产数、保留期、趋势、SQL 写入队列和清理批次。

`Memory` Provider 重启后丢失历史；v3.9 正式使用时必须评估 `SqlServer` Provider、保留周期、采样频率和时间语义是否满足模型数据字典。

## 12. AssetHealthGovernance v3.5

核心参数：Enabled、MinimumEventGrade、连续不健康/恢复、EvaluationInterval、Retention/Maintenance、MES Outbox、批次、重试、DeadLetter 和密钥。MES 故障不得阻塞 PLC、任务、命令、路权或调度线程。

## 13. AssetHealthRootCause v3.6

仓库默认 `Enabled=false`、`AllowCycles=false`、Graph Version/Source/ApprovedBy 为空、Nodes/Edges 为空。核心参数包括关联窗口、传播深度、容量上限、MinimumCandidateConfidence、图版本/Hash/来源/审批。

## 14. AssetHealthMaintenance v3.7

仓库和 Production 默认 `Enabled=false`，RuleSet Version/Source/ApprovedBy 为空，Rules 为空。无匹配规则时不生成建议；训练标签 Approved 不自动训练或激活模型。

## 15. PluggableRuntime v3.8

仓库与 Production 默认：

```json
{
  "AnomalyDetection": {
    "MachineLearning": {
      "Enabled": false,
      "ManagementApiEnabled": false,
      "PluggableRuntime": {
        "Enabled": false,
        "MaximumTrackedWindows": 5000,
        "InactiveStateRetentionSeconds": 300,
        "Profiles": []
      },
      "Profiles": []
    }
  }
}
```

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `PluggableRuntime.Enabled` | 外部模型覆盖层总开关 | 默认 `false` |
| `MaximumTrackedWindows` | 外部 Profile 特征窗口上限 | 结合设备数压测 |
| `InactiveStateRetentionSeconds` | 推理状态保留 | 1～86400 秒 |
| `Profiles[].ProfileId` | 显式接管的 ML Profile | 必须唯一且已启用 |
| `Profiles[].AdapterKind` | Adapter 类型 | 必须与 Manifest 一致 |
| `Profiles[].Required` | 缺少模型是否记失败 | 不等于 Host 启动失败 |

外部 Profile 必须禁止在线训练和 AutoTrain，同一 Profile 不得双推理；模型只允许本地相对路径、SHA 校验和 CPU ONNX。

## 16. AssetFailureForecast v3.9

仓库与 Production 默认：

```json
{
  "AssetFailureForecast": {
    "Enabled": false,
    "ModelDirectory": "data/failure-forecast-models",
    "EvaluationIntervalSeconds": 300,
    "MinimumHistoryPoints": 48,
    "MinimumHistorySpanHours": 24,
    "MaximumHistoryPoints": 2000,
    "MaximumAssetsPerEvaluation": 1000,
    "MaximumForecastsQueryCount": 1000,
    "ForecastRetentionHours": 8760,
    "MaintenanceIntervalSeconds": 3600,
    "MaintenanceBatchSize": 2000,
    "MaximumModelArtifactMegabytes": 256,
    "MinimumTrainingAssets": 30,
    "MinimumFailureEvents": 10,
    "MinimumValidationAuc": 0.65,
    "MaximumValidationBrierScore": 0.30,
    "MinimumPredictionIntervalCoverage": 0.70
  }
}
```

| 参数 | 说明 | 生产约束 |
|---|---|---|
| `Enabled` | Forecast 总开关 | 默认 `false` |
| `ModelDirectory` | active.json、版本 Manifest 和 ONNX | 本地受控 ACL、备份、防篡改 |
| `EvaluationIntervalSeconds` | 周期评估间隔 | 10～86400 秒，先手工评估 |
| `MinimumHistoryPoints` | 最小健康点数 | 数据不足不预测 |
| `MinimumHistorySpanHours` | 最小历史跨度 | 数据不足不预测 |
| `MaximumHistoryPoints` | 单资产读取上限 | 不得小于最小点数 |
| `MaximumAssetsPerEvaluation` | 单轮资产上限 | 结合 CPU/SQL 压测 |
| `MaximumForecastsQueryCount` | API 查询上限 | 禁止无界查询 |
| `ForecastRetentionHours` | Forecast/Outcome 保留 | 与可靠性审计一致 |
| Maintenance 参数 | SQL 清理周期和批次 | 小批次、可监控 |
| `MaximumModelArtifactMegabytes` | 模型文件上限 | 默认 256 MB |
| `MinimumTrainingAssets` | 训练资产最低数 | 软件最低门槛，不是生产标准 |
| `MinimumFailureEvents` | 真实失效最低数 | 不足时模型拒载 |
| `MinimumValidationAuc` | 验证 AUC 下限 | 默认 0.65 |
| `MaximumValidationBrierScore` | 校准误差上限 | 默认 0.30 |
| `MinimumPredictionIntervalCoverage` | RUL 区间覆盖下限 | 默认 0.70 |

Manifest 还必须包含 TrainingDatasetVersion、CensoredRecordCount、ValidationRulMaeHours、审批信息、14 维 FeatureNames、标准化数组、输入输出名称和 Shape、MaximumRulHours、ArtifactSha256。

输出约束：

```text
0 <= P24 <= P72 <= P168 <= 1
0 <= RulLower <= RulMedian <= RulUpper <= MaximumRulHours
```

不满足时整次预测失败且不写 SQL。

## 17. Forecast 启用依赖顺序

```text
AnomalyHealthScoring.HistoryProvider=SqlServer
→ 健康历史完整性和时间语义验收
→ 冻结 14 维 FeatureSchema 和数据集版本
→ 真实失效、删失和维修标签审批
→ 离线训练、校准、覆盖率和许可证验收
→ 本地模型、Manifest 和 SHA 发布
→ ManagementApiEnabled=true（接入权限后）
→ 单资产手工 Evaluate
→ 记录 Outcome 并观察指标
→ AssetFailureForecast.Enabled=true（项目签署后）
```

v3.9 不要求 v3.7 或 v3.8 外部 Profile 开启，但依赖稳定的 v3.4 健康历史和本地 ONNX Runtime 资产。

## 18. TransportObservability、Resilience 与 TransportSimulation

这些能力与 AnomalyEngine 和统一仿真治理的含义不同，不得共用阈值。`TransportSimulation` 现有容量预测参数不等于 S0 的场景版本治理；后续 S1 会在不破坏现有能力的前提下统一场景 DSL 和虚拟时钟。

Forecast 资源指标应单独记录 CPU、内存、推理耗时、SQL 延迟、InsufficientData、Failures 和模型目录容量。

## 19. SimulationGovernance S0

Simulation 环境配置：

```json
{
  "Simulator": {
    "Enabled": true,
    "TransportTps": 2
  },
  "SimulationGovernance": {
    "Enabled": true,
    "ScenarioDirectory": "data/simulation-scenarios",
    "MaximumScenarioBytes": 1048576,
    "MaximumRegisteredScenarioVersions": 10000,
    "MaximumEvidenceRecords": 10000,
    "MaximumEvidenceValueCharacters": 4096,
    "AllowedEnvironments": [
      "Simulation",
      "SimulationLoadTest"
    ]
  }
}
```

Manifest 必须包含 ScenarioId、Version、Seed、ScenarioFile、ContentSha256、Source 和审批信息。相同 ScenarioId+Version 只允许相同 Hash 的幂等登记。S0 Registry 为内存实现，不用于生产数据持久化。

`MaximumScenarioBytes`、Registry 版本数、Evidence 记录数和值长度均必须有界；Seed 必须显式记录；Evidence Sequence 必须非负且唯一，发生时间必须位于 Evidence 时间窗。Simulation API 不能开放到 Development、UAT 或 Production，Production 永远禁止。

## 20. API 安全

治理写操作必须接入身份授权并保存 Actor、原因和时间：

```text
POST /api/anomaly/maintenance/recommendations/{id}/feedback
POST /api/anomaly/maintenance/training-labels/{id}/review
POST /api/anomaly/ml/models/{profileId}/{version}/activate
POST /api/anomaly/forecast/assets/{assetId}/evaluate
POST /api/anomaly/forecast/models/{version}/activate
POST /api/anomaly/forecast/forecasts/{forecastId}/outcomes
POST /api/simulation/governance/scenarios/validate
```

S0 场景校验接口只做内存版本登记，尚未接入正式身份系统，因此只允许隔离 Simulation 环境。外部 Profile 和 Forecast 模型不允许在 WCS 内训练。LoadTest、MlLoadTest、ForecastLoadTest、Simulation 和 SimulationLoadTest 入口在非批准环境必须返回 404。

## 21. 变更、回退与生产检查

回退顺序：

```text
SimulationGovernance__Enabled=false
→ Simulator__Enabled=false
→ AssetFailureForecast__Enabled=false（仅需关闭 v3.9 时）
→ AnomalyDetection__MachineLearning__PluggableRuntime__Enabled=false（仅需关闭 v3.8 时）
→ AnomalyDetection__MachineLearning__Enabled=false（仅需关闭全部 ML 时）
→ AssetHealthMaintenance__Enabled=false（仅需关闭 v3.7 时）
```

生产检查：

- [ ] Environment 明确为 Production；
- [ ] `Simulator.Enabled=false`；
- [ ] `SimulationGovernance.Enabled` 未开启；
- [ ] AllowedEnvironments 不含 Production；
- [ ] 仿真 API 返回 404；
- [ ] Rules、Profiles、Sources、Graph、Maintenance RuleSet 和场景无示例泄漏；
- [ ] Production ML、PluggableRuntime 和 Forecast 默认关闭；
- [ ] 真实模型、数据集、场景、许可证和密钥未提交仓库；
- [ ] 模型/场景目录 ACL、备份、Hash 和防篡改完整；
- [ ] Registry、Evidence 和所有队列容量有界；
- [ ] Manifest 数据集或场景版本、样本统计、验证指标、审批和 FeatureSchema/Seed 完整；
- [ ] 数据不足时不生成概率或 RUL；
- [ ] Outcome 和治理写 API 已接入身份权限；
- [ ] Brier、RUL MAE 和区间覆盖持续监控；
- [ ] 坏 Hash 时 Host 健康且模型/场景拒载；
- [ ] 训练标签 Approved 不自动更新活动模型；
- [ ] 无 PLC 写入、设备停止、任务取消、路权释放或调度修改；
- [ ] 真实准确率、HIL、权限、许可证、维修策略和正式投产已独立签署。
