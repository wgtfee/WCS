# S10 统一仿真与验证中心操作手册

## 1. 用途

统一仿真验证中心用于在受控环境中查看 S0～S10 的能力目录、环境可用性、只读 API 前缀和安全边界。

它不是生产控制页面，不负责执行场景、注入故障、写 PLC、移动 RGV、操作路权或完成真实 HIL 验收。

## 2. 访问前提

Host 必须运行在以下受控环境之一：

- `Simulation`；
- `SimulationLoadTest`；
- `HIL`；
- `TrialRun`。

Production 环境固定返回 404。Development 或任意未批准环境也会 fail-closed 返回 404。

统一 API：

```text
GET /api/simulation/verification/overview
```

Desktop 菜单：

```text
统一仿真验证中心
```

## 3. 页面区域

### 3.1 顶部状态

显示：

- 当前 Host Environment；
- 页面模式；
- Simulation 检查能力是否可用；
- HIL 检查能力是否可用；
- 当前可用阶段数；
- 真实 HIL 状态。

正常的软件侧状态应显示：

```text
页面模式 = 只读安全模式
真实 HIL = Pending
```

在没有真实现场证据时，`Pending` 是正确结果，不是软件故障。

### 3.2 阶段能力矩阵

矩阵精确包含：

```text
S0 治理与隔离
S1 场景引擎
S2 虚拟 PLC
S3 虚拟 RGV
S4 虚拟交通
S5 外部依赖故障
S6 合成健康与 RUL
S7 全链路集成恢复
S8 容量长稳与 HIL 准备
S9 真实 HIL 与试运行
S10 统一验证中心
```

每行显示：

- 当前环境是否可用；
- 是否需要 RunId；
- 软件/仿真或真实台架边界；
- 对应只读 API 前缀；
- 能力摘要。

### 3.3 详情区

选择阶段后查看：

- 阶段编号；
- 阶段名称；
- 能力说明；
- API 前缀；
- 安全说明。

S10 当前只展示 API 前缀，不自动跳转或调用各阶段控制操作。

## 4. 环境行为

### 4.1 Simulation / SimulationLoadTest

预期：

- S0～S8：Available；
- S9：UnavailableInCurrentEnvironment；
- S10：Available；
- SimulationInspectionAvailable=true；
- HilInspectionAvailable=false。

### 4.2 HIL / TrialRun

预期：

- S0～S8：UnavailableInCurrentEnvironment；
- S9：Available；
- S10：Available；
- SimulationInspectionAvailable=false；
- HilInspectionAvailable=true。

HIL 页面可用不代表真实 HIL 已执行。

### 4.3 Production

预期：

```text
HTTP 404
Desktop 显示安全拒绝/不可用
```

不得为方便展示而开放 Production。

## 5. 刷新与故障判断

点击“刷新状态”后，Desktop 重新读取 Overview API。

常见结果：

| 结果 | 含义 | 处理 |
|---|---|---|
| 正常显示阶段矩阵 | 受控环境与配置正确 | 继续只读检查 |
| 404 / 安全拒绝 | Production、未批准环境或两类边界均未开启 | 检查环境和配置，不绕过 Guard |
| HTTP 连接失败 | Desktop 无法访问 Host | 检查 `WcsDesktop.ServerUrl` 和 Host 状态 |
| 真实 HIL Pending | 尚无现场真实证据 | 按 S9 操作手册执行现场流程 |
| 可用阶段数量异常 | 配置边界或返回契约异常 | 停止验收，检查 Host 配置与日志 |

## 6. 禁止操作

不得通过修改页面、抓包或手工 JSON 把下列字段改为 true：

```text
RealHilExecuted
ProtocolValidated
MechanicalSafetyAccepted
SiteAccepted
```

不得在 S10 页面增加：

- POST/PUT/PATCH/DELETE API；
- 场景执行按钮；
- 故障注入按钮；
- PLC 写入按钮；
- RGV 移动按钮；
- 路权、预约或死锁处置按钮；
- HIL Arm/Begin/Abort/Recover；
- Protocol/Mechanical/Site Acceptance 写入。

任何此类需求必须回到对应受控系统和审批流程，不得通过统一页面绕过。

## 7. 验收步骤

1. 确认 PR Head；
2. 确认 `WCS S10 Unified Verification Console` 对该 exact Head 成功；
3. 核对 10/10 契约测试；
4. 核对 Host 和 Avalonia Desktop Release 构建；
5. 在 Simulation 环境验证 S0～S8 + S10；
6. 在 HIL 环境验证 S9 + S10，仅检查只读状态；
7. 在 Production 环境确认 404；
8. 核对页面无控制入口；
9. 运行 `WCS S10 Software Full Regression`；
10. 核对 46/46、One Hour Soak、Artifact 和 SHA-256 Digest；
11. 确认 PR Head 在证据收集期间未移动。

## 8. 与 S9 的关系

S10 软件页面可以先完成，但项目最终现场完成仍依赖 S9 的真实证据：

- self-hosted `wcs-hil` Runner；
- 真实 PLC/RGV 台架；
- 每个 Trial Step 的 `RealHardwareObserved=true`；
- ProtocolValidated；
- MechanicalSafetyAccepted；
- SiteAccepted；
- Evidence Manifest / Bundle SHA-256；
- Real HIL Evidence Gate 成功。

S10 不会也不能替代以上步骤。
