## 6. 历史与趋势单元测试

`AssetHealthScoreHistoryStoreTests` 覆盖：

### 6.1 小变化去重

场景：

- 首次评分 80；
- 10 秒后评分 79.5；
- 变化小于 1 分；
- 61 秒后达到测试心跳间隔。

验收：

- 首次记录；
- 10 秒小变化去重；
- 达到心跳间隔后记录；
- RecordedPoints=2；
- DeduplicatedPoints=1。

### 6.2 等级变化强制记录

即使分数只变化 0.2，只要等级从 Attention 变为 Degraded，必须记录，并保存 PreviousGrade、GradeChanged 和 ScoreDelta。

### 6.3 单资产容量和时间保留

场景：

- 单资产上限 3；
- 连续写入 5 个变化点；
- 保留期 1 小时；
- 执行维护。

验收：

- 写入后只保留最新 3 点；
- 维护后删除过期点；
- EvictedPoints 精确计数。

### 6.4 趋势方向

- 90 → 80 → 70：Deteriorating，Delta=-20；
- 40 → 60：Improving，Delta=+20；
- 验证每小时健康分斜率。

### 6.5 资产容量

最大历史资产数为 2 时写入 A、B、C，必须淘汰最久未记录的 A，并保持 EvictedAssets 和 EvictedPoints 守恒。

## 8. 容量验收口径

默认理论上限：

```text
10,000 assets × 720 points = 7,200,000 points
```

该值是配置硬上限，不代表建议长期占满。生产启用前必须根据对象大小、Host RSS、GC 后托管存活量和查询负载重新压测。

验收要求：

- 单资产点数不超过 MaximumHistoryPerAsset；
- 资产数不超过 MaximumTrackedHistoryAssets；
- 过期点可被 MaintainAsync 清理；
- 最久未记录资产可被确定性淘汰；
- 小变化不会无界写入；
- 等级变化不被去重；
- 查询结果不超过 MaximumHistoryQueryCount；
- 功能关闭时不启动采样后台服务；
- 仓储失败不得影响 PLC、调度和 v3.3 Fusion。

## 9. API 验收

| API | 预期 |
|---|---|
| `GET /api/anomaly/health/status` | 返回评分开关、Fusion 状态和等级门槛 |
| `GET /api/anomaly/health/assets` | 最差资产优先，支持 minimumGrade |
| `GET /api/anomaly/health/assets/{assetId}` | 返回当前评分或 404 |
| `GET /api/anomaly/health/history/status` | 返回 Provider、容量和计数 |
| `GET /api/anomaly/health/assets/{assetId}/history` | 返回正序变化点，支持 fromUtc/maxCount |
| `GET /api/anomaly/health/assets/{assetId}/trend` | 返回趋势窗口，没有历史时 404 |

所有 API 均为 GET，只读。

## 12. 已知限制

1. 当前历史 Provider 为内存，Host 重启后历史丢失；
2. 当前不提供跨节点共享历史；
3. 当前不提供 SQL/InfluxDB 查询和分区；
4. 趋势基于已记录变化点，不是固定时间等间隔原始序列；
5. 当前不进行预测和剩余寿命计算；
6. 当前不自动创建维修工单；
7. 健康分不参与自动控制。
