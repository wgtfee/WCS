> 适用范围：WCS Runtime Engine（仓储输送调度系统）

## 0. 一张图看懂整个系统

```
【采集层】PLC / 模拟器
      │  每 100ms 轮询 DB 块
      ▼
SignalSnapshotCenter（新旧帧对比）──► EventDetector（边沿检测）
      │                                    │
      ▼                                    ▼
StateCenter（设备/任务/报警/对象 实时态）   EventBus（业务事件）
      │                                    │
      ├──── SignalR ──► Desktop 实时界面    ├─► TaskGenerator（信号→自动生成任务）
      │                                    ├─► AlarmCenter（报警管线）
      └──── PersistBackgroundService       └─► TelemetryBuffer（遥测归档）
            每 10s 快照写入 SQL Server

【调度层】生产队列 ──每秒派单──► 执行状态机 ──100ms命令泵──► 车辆 PLC
                     ▲                              │
                     └────── 位置反馈 ◄─────────────┘
（交通控制中心全程管路权；死锁自动检测）
```

一句话总结：
- **数据从下往上**：PLC 信号 → 内存实时态 → 数据库历史；
- **指令从上往下**：任务/派单决策 → 执行命令 → 写回 PLC；
- **桌面端只是观察窗和控制台**，所有业务规则都在 Host 内。

## 1. PLC 数据是怎么被记录的

### 1.1 采集链路（自动运行，无需人工干预）

1. **轮询读取**：`S7PollingService` 按 DB 块注册表（`PlcStructRegistry`）每 100ms 读一次 PLC 数据块；
2. **结构化解析**：原始字节按 C# struct 定义（`[PlcStruct]` 特性标注的字段映射）解析成强类型对象；
3. **新旧帧对比**：`SignalSnapshotCenter` 保存每个块的上一帧，逐字段对比产生**边沿**（上升沿 0→1 / 下降沿 1→0）；
4. **状态同步**：所有字段值无条件更新进 `StateCenter`（内存实时态）；
5. **事件发布**：发生变化的字段经 `EventDetector` 验证管道后发布到 `EventBus`；
6. **持久化**：
   - `PersistBackgroundService` 每 10 秒把 StateCenter 快照 upsert 到 SQL Server；
   - 若启用遥测存储（`Storage:Telemetry:Provider = SqlServer / InfluxDb`），每次信号变化还会作为时序点归档到 `Wcs_PlcTelemetry` 表或 InfluxDB。

### 1.2 字段命名约定（决定系统能识别什么信号）

struct 字段名按 `设备ID_信号后缀` 命名，EventDetector 靠后缀识别业务含义：

| 后缀 | 含义 | 触发行为 |
|---|---|---|
| `_ARRIVED` | 托盘到位 | **上升沿**发布托盘到位事件 → 可自动生成搬运任务 |
| `_REQUESTOUT` | 出库请求 | **上升沿**发布出库请求事件 |
| `_FAULT` / `_ARALM` | 设备故障 | 上升沿报故障，下降沿自动报恢复 |
| `_READY` | 输送线就绪 | 双沿发布就绪状态变化 |

> 新增点位：在 struct 中加字段并注册到 `PlcStructRegistry`（代码注册或 appsettings 的 PlcBlockConfig），重启即生效。详见《08-PLC通信与点位配置说明书》。

### 1.3 在哪里查看 PLC 数据

| 想看什么 | 去哪里 | 说明 |
|---|---|---|
| 设备当前状态（运行/空闲/故障） | 桌面端 **运行中心 → 设备状态** | 实时推送，无需刷新 |
| 原始信号变化流水 | **记录与审计 → 实时事件日志** | SignalR 推送的 RawSignal 流水 |
| 历史趋势 / 事后追溯 | 数据库 `Wcs_PlcTelemetry` 表 | 需开启遥测 Provider |
| 当前内存快照 | `GET /api/devices`、`GET /api/overview` | 接口直读实时态 |

## 2. 任务怎么下发

系统支持三种下发方式，最终都汇入同一个调度器。

### 方式一：桌面手动创建（最直接）

**入口：运行中心 → 任务管理**

1. 填写「设备 ID」「路径」和优先级；
2. 点创建 → 任务立即出现在列表顶部；
3. 之后状态流转（排队→执行中→完成）由系统实时推送到该行，**不需要手动刷新**。
4. 取消：点行内取消按钮提交取消请求，终态以实时状态为准。

对应接口：`POST /api/tasks`（body: deviceId/routeId/priority）、`POST /api/tasks/{taskId}/cancel`。

### 方式二：PLC 信号自动触发（生产常态）

现场托盘放到到位感应位后：

```
托盘到位传感器 0→1
  → EventDetector 识别 _ARRIVED 字段上升沿
  → 发布 PalletArrivedEvent
  → TaskGenerator 查规则引擎匹配路线规则
  → 自动生成任务并入队（同一信号 5 秒幂等去重，防抖动重复建任务）
```

要启用哪种"到位 → 去哪"的规则，在规则引擎中配置（设备 → 目标路径映射）。这种方式**零人工**，是产线正常运行的主通道。

### 方式三：生产派单队列（EMS/RGV 场景）

**入口：调度控制 → 生产派单看板**

- 通过 `POST /api/transport/production/queue` 提交搬运请求（起点站、目标站、载荷、优先级）；
- Host 后台**每 1 秒自动跑一次派单竞争**：按有效优先级排序 → 站点容量准入 → 选车 → 路权预检；
- 派不上的任务留在队列里并给出原因（等站点 / 等路权 / 无可用车辆），条件满足后下一周期自动重试；
- 页面每 3 秒自动刷新队列与最近派单决策，也可点「立即调度」马上竞争一轮（不影响后台周期）。

### 任务生命周期（状态机）

```
Created(已创建) → Queued(排队) → Running(执行中) ─┬─► Completed(已完成)
                            │                     ├─► Failed(失败)
                            ├─► Paused(暂停)──────┤
                            └─► Cancelled(已取消)  └─► Recovered(已恢复→重新入队)
```

## 3. 执行流程怎么查看

### 3.1 EMS/RGV 任务的内部执行链（理解了它，看任何页面都不会迷路）

```
生产队列任务
  ↓ ①派单周期（每 1s）：选车 + 计算路径 + 创建路权预留
执行状态机 Assigned（已指派）
  ↓ ②生成 MoveToNode/Load/Unload 逻辑命令
命令泵（每 100ms）：同车串行、异车并行发给车辆驱动
  ↓ ③车辆真实移动
位置反馈上报（节点级，Sequence 单调递增）
  ↓ ④执行引擎推进节点索引、释放走过路段、向前滚动预约窗口
Loading → MovingToDestination → Unloading → Completed
        （前方路段被占时自动转 WaitingForRoute，腾空后自动恢复前进）
```

### 3.2 监控页面速查（全部自动刷新，不用手点）

| 我想知道… | 打开哪页 | 刷新频率 |
|---|---|---|
| 每台车现在在哪、干什么 | **调度控制 → 车辆调度中心** | 2 秒 |
| 派单为什么没派出去 | **调度控制 → 生产派单看板**（看决策记录的 Reason 列） | 3 秒 |
| 任务走到哪个状态了 | **运行中心 → 任务管理**（行内实时变化） | 实时推送 |
| 有没有报警 | **运行中心 → 告警中心** | 实时推送 |
| 全局数量概览 | **运行中心 → 运行总览** | 实时推送 |
| 事件时间线（排障用） | **记录与审计 → 实时事件日志** | 实时推送 |

### 3.3 常用查询 API（对接 MES / 二次开发）

| 用途 | 接口 |
|---|---|
| 全局概览 | `GET /api/overview` |
| 车辆快照 | `GET /api/transport/vehicles` |

## 4. 故障处理手册

### 4.1 报警的产生与确认（输送线设备类）

报警不是"一跳就响"，经过五层管线过滤噪声：

```
信号跳变 → ①防抖（DelayRaise/DelayRecover 窗口内来回跳不算）
        → ②风暴抑制（60 秒窗口超阈值自动静默，防止刷屏）
        → ③屏蔽检查（检修中的设备可挂屏蔽名单）
        → ④状态机（PendingRaise → Active → Acknowledged → PendingRecover → Recovered）
        → ⑤聚合（同组子报警挂在根因下，面板只显示根因）
```

**操作流程（告警中心页）：**
1. 看到 **Active（激活）** 报警 → 先现场处置，再点「确认」（Acknowledge），表示"我已知悉"；
2. 故障消除后信号下降沿 → 系统自动走 **PendingRecover → Recovered**，无需手工恢复；
3. 误报排查：先看是否处于模拟器故障注入场景，再查点位接线。

### 4.2 任务失败 / 设备故障的处理步骤

1. **定位**：任务管理页看到 Failed 行 + ErrorMessage；同时告警中心会有对应设备故障报警；
2. **隔离**：故障设备上的后续任务会被调度器自动避开（站点准入与健康检查）；若任务卡在故障设备，走第 3 步；
3. **重试或转移**：
   - 可重试任务：通过恢复接口重新入队（状态转 Recovered，受最大重试次数限制）；
   - EMS/RGV 车辆故障：见 4.3 故障接管；
4. **复盘**：事件日志页拉时间线；`Wcs_TaskHistory` / `Wcs_TransportHistory` 表有完整历史归档。

### 4.3 车辆故障接管（EMS/RGV 专用）

车辆报故障码或离线时的标准动作：

1. **评估**：`POST /api/transport/production/fault-takeover/evaluate`
   系统检查故障车辆的执行任务：原车是否已取货、是否已进入单轨区段、是否有已确认的物理占用；
2. **安全规则（系统强制，不可绕过）**：
   - 原车未清场 → **不会**派接替车进同区段（杜绝双车相撞）；
   - 已过取货点的任务 → 只能停驶等待人工恢复，不能自动换车；
   - 尚未取货的任务 → 允许自动取消并由备用车重新接单；
3. **执行转移**：按评估结果调用任务重分配接口（`POST /api/transport/optimization/executions/{requestId}/reassign`），全过程留审计记录；
4. **原车恢复**：司机/维修确认车辆正常后，从驱动诊断页发上线命令，车辆重新参与派单。

### 4.4 交通死锁

- 系统基于真实等待关系（谁占着谁要走的路）做 Wait-For Graph 检测，**不会**把"都在忙"误判成死锁；
- 检出死锁会在 **交通控制与死锁** 页展示环上的车辆、路段和 CycleId；
- 处理：优先等系统自动解除（滚动预约过期回收）；确需人工干预时用页面上的强制放行（走审批操作流，留痕）。

### 4.5 Host 重启后的状态恢复

系统内置快照恢复机制，重启后自动还原（按模块顺序）：

```
StateCenter（设备/任务实时态）→ AlarmCenter（报警状态）
→ ObjectTracking（对象位置）→ TransportTraffic（路权与等待队列）…
```

- 持久层每 10 秒落一次快照，因此重启最多丢失最后 10 秒的内存态；
- 未完成的运输任务重启后会进入一致性巡检：**备份与恢复演练**页可主动做备份校验和恢复演练，建议每次升级前演练一次；
- 数据库不可用时 Host 无法启动（基础设施强依赖），仿真环境需另行提供连接串。

## 5. 常见问题（FAQ）

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 任务创建了一直 Queued | 无可用车辆 / 目标站点满 / 路权不足 | 生产派单看板看决策 Reason 列 |
| 设备状态不动 | PLC 断线或轮询服务未启动 | 看 Host 日志 `[S7]` 条目；驱动诊断页轮询测试 |
| 桌面端数据不刷新 | SignalR 断连 | 看左上角连接状态，自动重连间隔 5 秒 |
| 同一信号生成了两条任务 | 信号 5 秒幂等窗口外二次抖动 | 检查传感器；必要时调大幂等窗口 |
| 报警风暴刷屏 | 风暴抑制阈值偏高 | 调整 AlarmRules 中 SuppressionWindowSec/Threshold |
| 仿真页签全是只读 | 环境/治理开关未开 | 见下方"环境边界" |

**环境边界（重要）**：仿真能力默认关闭。启用三步——
① `Simulator:Enabled=true`；② `SimulationGovernance:Enabled=true`；
③ `ASPNETCORE_ENVIRONMENT` 设为 `SimulationGovernance:AllowedEnvironments` 之一（如 Simulation）。
Production 环境永远拒绝仿真与 HIL，这是设计红线。

## 6. 附：核心配置项速查

| 配置节 | 作用 | 默认 |
|---|---|---|
| `WcsOptions:PlcPolling` | PLC 轮询开关与间隔 | 开 / 100ms |
| `WcsOptions:Persistence` | 快照落库间隔 | 10s |
| `Storage:Telemetry:Provider` | 遥测归档（Disabled/SqlServer/InfluxDb） | Disabled |
| `AlarmRules` | 报警级别与防抖/抑制参数 | 内置默认 |
| `TransportResilience` | 自动备份周期与保留数 | 60min / 48 份 |
| `SimulationGovernance` | 仿真白名单环境与容量上限 | Simulation、SimulationLoadTest |
