# 仿真平台测试策略与完整回归规范

## 1. 统一交付循环

```text
功能开发
→ 阶段契约测试
→ 阶段专项 E2E
→ 当前完整历史回归
→ 文档和 Evidence 回填
→ 文档提交形成新 exact Head
→ 新 Head 再跑同等完整回归
→ Ready
→ Squash Merge
```

旧 Head 的成功不能替代 latest exact Head。

## 2. S0 专项

### WCS Simulation Governance Compile

- 清理 bin/obj；
- Restore `Wcs.Simulator.Tests`；
- Release 编译测试项目及 Host 依赖图；
- 运行全部 Governance 与 Controller 测试；
- 保存 Restore、Build、Test、TRX Artifact。

### WCS Simulation Governance Boundary

- Production Simulator 默认关闭；
- Simulation/SimulationLoadTest 双开关开启；
- Simulation 默认关闭 Anomaly、ML、Forecast；
- 环境白名单精确；
- Production 启动保护存在；
- 非批准环境 API 返回 404；
- `controlWritesAllowed=false`；
- Governance 不依赖 PLC、任务、交通和调度控制；
- 不包含写 PLC、取消任务、释放路权和派单操作。

## 3. 契约测试

核心覆盖：

1. 相同 Seed 的随机序列一致；
2. 不同 Seed 不同；
3. Production 永久拒绝；
4. 双开关缺一不可；
5. 只允许批准环境；
6. 配置白名单禁止 Production；
7. 合法 Package 幂等；
8. 同一 Version 修改内容拒绝；
9. 路径穿越拒绝；
10. Hash 不匹配拒绝；
11. Evidence 规范化 Hash 稳定；
12. Evidence Sequence 重复拒绝；
13. Production/Development API 返回 404；
14. Simulation 双开关 API 返回 200；
15. API 修改不可变版本返回 400。

## 6. 失败处理

- 修实现，不通过删除或放宽断言迁就错误；
- 不使用 `continue-on-error` 掩盖关键失败；
- 性能失败先核查 Runner，再复验 Artifact；
- 修复提交产生新 Head 后，旧结果失效；
- 长稳必须检查 RSS、GC、线程、句柄、队列和守恒量。

## 7. Evidence 最低内容

- Workflow、Run Number、Run ID；
- exact Head；
- 环境和配置；
- Restore/Build/Test/TRX；
- Artifact 与 Digest；
- 通过/失败数量；
- 性能、容量和写入计数；
- 已知限制。

## 8. 现场边界

仓库测试不能证明机械制动、硬件联锁、工业网络、真实 RUL 准确率、正式权限、HIL 和投产。这些必须在 S9 或项目验收中签署。
