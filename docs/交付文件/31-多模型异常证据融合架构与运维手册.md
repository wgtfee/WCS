# 多模型异常证据融合架构与运维手册

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 功能名称 | AnomalyEngine v3.3 — 多模型异常证据融合 |
| 适用分支 | `develop` |
| 核心引擎 | `AnomalyFusionEngine` |
| PLC 桥接 | `PlcAnomalyFusionBridgeService` |
| 周期桥接 | `TransportCycleFusionBridgeService` |
| 异步入口 | `AnomalyEvidenceChannel` |
| 默认状态 | 关闭，`AnomalyFusion:Enabled=false` |
| 运行性质 | 只读分析，不写 PLC、不停止设备、不改变调度决策 |

## 2. 建设目标

WCS 已具备规则/统计检测、Isolation Forest、同群 Median/MAD 和运输周期异常。各检测器分别输出结果时，运维人员仍需要人工判断多个异常是否指向同一设备、是否来自独立来源，以及异常是否足以升级为正式健康告警。

v3.3 建立统一证据模型：

```text
规则 / 统计 / Isolation Forest / 同群 / 周期
→ AnomalyEvidence
→ 有界异步 Channel
→ 同资产、同来源去重
→ 权重、置信度、严重度和来源多样性融合
→ Normal / Observe / Warning / Alarm
→ 只读 API
```

目标包括：

- 将不同模型输出标准化；
- 同一来源只采用贡献最大的活动证据，防止重复采样放大；
- 默认至少两个独立来源才能进入 Alarm；
- Warning、Alarm 和恢复均支持连续评估与滞回；
- Evidence、资产状态、历史快照和入口队列全部有界；
- 公开写入、读取、积压和丢弃指标；
- 保持检测与控制解耦。

## 3. 安全边界

1. Fusion 只接收已产生的异常证据，不参与 PLC 读写。
2. Fusion 不调用车辆停止、任务取消、路权释放或调度重排。
3. `Enabled=false` 时后台消费、PLC 桥接和周期桥接立即退出。
4. 单一来源默认不能独自升级为 Alarm。
5. 未知 EvidenceId 的恢复事件不会改变正式健康状态。
6. 通道满时采用有界丢弃并记录 `Dropped`，不会无限堆积生产者任务。
7. 所有 Evidence 都有 TTL；空闲 Normal 资产会自动淘汰。
8. LoadTest 注入 API 只在 `LoadTest` 环境存在，生产环境返回 404。
9. Fusion 结果是诊断和决策支持信息，不替代 PLC 联锁、安全回路和现场操作规程。

## 4. 标准证据模型

`AnomalyEvidence` 主要字段：

| 字段 | 说明 |
|---|---|
| EvidenceId | 上游生命周期唯一编号；恢复时必须保持一致 |
| Source | 标准来源编号 |
| AssetId | 被评估资产，例如 RGV、EMS 小车或输送设备 |
| RelatedEntityId | 规则、任务或请求编号 |
| Category | 异常类别 |
| State | `Active` 或 `Recovered` |
| ObservedAtUtc | 证据观察时间 |
| ExpiresAtUtc | 可选显式过期时间 |
| Score | 0～1 异常分数 |
| Confidence | 0～1 置信度；0 表示使用来源默认值 |
| Severity | Observe、Warning、Error、Critical |
| Reason | 可读原因 |
| ContextJson | 可选运行上下文 |

标准来源：

```text
RULE_THRESHOLD
RULE_RATE
RULE_DURATION
RULE_STATISTICAL
RULE_CONSISTENCY
ISOLATION_FOREST
PEER_MEDIAN_MAD
CYCLE_SEQUENCE
CYCLE_PHASE_DURATION
CYCLE_TOTAL_DURATION
```

## 5. PLC 异常桥接

PLC 异常仍由现有规则、统计、ML 或同群运行时生成，并经过正式生命周期：

```text
PlcAnomalyDetectedEvent / PlcAnomalyRecoveredEvent
→ EventBus
→ PlcAnomalyFusionBridgeService
→ AnomalyEvidenceChannel
→ AnomalyFusionEngine
```

映射原则：

| PlcAnomalyType | Fusion Source |
|---|---|
| Threshold | RULE_THRESHOLD |
| RateOfChange | RULE_RATE |
| Duration | RULE_DURATION |
| StatisticalBaseline | RULE_STATISTICAL |
| Consistency | RULE_CONSISTENCY |
| MachineLearning | ISOLATION_FOREST |
| ContextualPeerComparison | PEER_MEDIAN_MAD |

EvidenceId 使用：

```text
PLC|<AnomalyId>
```

激活与恢复事件使用同一 EvidenceId，因此 Fusion 可以精确关闭原证据。

## 6. 运输周期桥接

周期模型保持独立，Fusion 通过只读轮询桥接最近异常：

```text
TransportCycleAnalysisService
→ TransportCycleFusionBridgeService
→ AnomalyEvidenceChannel
→ AnomalyFusionEngine
```

映射：

| TransportCycleAnomalyKind | Fusion Source |
|---|---|
| InvalidSequence | CYCLE_SEQUENCE |
| PhaseDuration | CYCLE_PHASE_DURATION |
| TotalDuration | CYCLE_TOTAL_DURATION |

周期异常没有显式恢复事件，Bridge 为 Evidence 设置明确 TTL。Bridge 使用有界去重字典，TTL 到期后释放去重状态。来自明显未来的测试/回放时间不会延长生产 TTL，过期时间统一基于当前 UTC 上限计算。

## 7. 融合计算

### 7.1 同来源去重

同一资产可能收到同一模型的多条活动 Evidence。引擎按 `Source` 分组，每个来源只保留贡献最大的一条参与当前计算。

```text
Contribution = clamp(ScoreWithSeverityFloor × Confidence × SourceWeight, 0, 0.99)
```

严重度最低分：

| Severity | 最低分 |
|---|---:|
| Observe | 0.25 |
| Warning | 0.55 |
| Error | 0.75 |
| Critical | 0.90 |

### 7.2 多来源组合

独立来源贡献使用概率式组合：

```text
BaseScore = 1 - Π(1 - Contribution_i)
DiversityBonus = min(MaximumSourceDiversityBonus,
                     (IndependentSources - 1) × SourceDiversityBonus)
FinalScore = clamp(BaseScore + DiversityBonus, 0, 1)
```

该公式避免简单求和超过 1，同时让多个相互独立的证据比单一证据更可信。

### 7.3 状态门槛

默认值：

| 状态 | 条件 |
|---|---|
| Normal | 分数低于 Observe，或正式状态完成恢复 |
| Observe | Score ≥ 0.35 |
| Warning | Score ≥ 0.65，并满足连续 Warning 评估 |
| Alarm | Score ≥ 0.85、独立来源不少于 2，并满足连续 Alarm 评估 |

Alarm 默认不能由单一来源触发，即使该来源分数很高。

### 7.4 连续确认与恢复滞回

默认：

- Warning 连续评估：2；
- Alarm 连续评估：2；
- 恢复连续评估：3；
- RecoveryThreshold：0.25。

Warning/Alarm 状态只有在分数降到恢复门槛以下或全部活动证据清除后，才开始推进恢复计数。维护周期会自动推进恢复，不要求上游重复发送恢复事件。

## 8. 生命周期和内存治理

### 8.1 Evidence TTL

- 活动 Evidence 默认保留 300 秒；
- 已恢复 Evidence 默认保留 60 秒；
- 显式 `ExpiresAtUtc` 优先，但 Bridge 会防止明显未来时间造成无限保留。

### 8.2 资产淘汰

资产满足以下条件后才能淘汰：

```text
Evidence 数量 = 0
状态 = Normal
空闲时间 > InactiveStateRetentionSeconds
```

活动 Warning/Alarm 不会直接淘汰。

### 8.3 有界容量

| 集合 | 默认上限 |
|---|---:|
| Channel | 20,000 |
| 资产 | 20,000 |
| 单资产 Evidence | 100 |
| 状态迁移快照 | 5,000 |

容量满时拒绝新增并计入 Dropped，不允许无界扩容。

## 9. 配置

```json
{
  "AnomalyFusion": {
    "Enabled": false,
    "ChannelCapacity": 20000,
    "EvidenceRetentionSeconds": 300,
    "RecoveredEvidenceRetentionSeconds": 60,
    "InactiveStateRetentionSeconds": 600,
    "MaximumTrackedAssets": 20000,
    "MaximumEvidencePerAsset": 100,
    "MaximumSnapshots": 5000,
    "ObserveThreshold": 0.35,
    "WarningThreshold": 0.65,
    "AlarmThreshold": 0.85,
    "RecoveryThreshold": 0.25,
    "MinimumIndependentSourcesForAlarm": 2,
    "ConsecutiveWarningEvaluations": 2,
    "ConsecutiveAlarmEvaluations": 2,
    "ConsecutiveRecoveryEvaluations": 3,
    "SourceDiversityBonus": 0.05,
    "MaximumSourceDiversityBonus": 0.15,
    "Sources": []
  }
}
```

### 9.1 参数说明

| 参数 | 说明 | 生产建议 |
|---|---|---|
| Enabled | Fusion 总开关 | 默认 false，先在测试环境开启 |
| ChannelCapacity | 异步 Evidence 队列容量 | 根据峰值事件量和 Pending 指标整定 |
| EvidenceRetentionSeconds | 活动证据默认 TTL | 不应替代上游恢复事件 |
| RecoveredEvidenceRetentionSeconds | 恢复证据审计保留时间 | 典型 30～300 秒 |
| InactiveStateRetentionSeconds | 空闲 Normal 资产 TTL | 典型 300～3600 秒 |
| MaximumTrackedAssets | 最大资产状态数 | 高于正常在线设备数并保留余量 |
| MaximumEvidencePerAsset | 单资产最大 Evidence 数 | 防止异常风暴无限增长 |
| MaximumSnapshots | 状态转换历史上限 | 内存审计窗口，不是长期历史库 |
| ObserveThreshold | 观察门槛 | 结合现场误报分析 |
| WarningThreshold | Warning 门槛 | 高于 Observe |
| AlarmThreshold | Alarm 分数门槛 | 还需满足独立来源数 |
| RecoveryThreshold | 正式状态恢复门槛 | 必须低于 WarningThreshold |
| MinimumIndependentSourcesForAlarm | Alarm 最少独立来源 | 默认 2，不建议降为 1 |
| ConsecutiveWarningEvaluations | Warning 连续次数 | 抑制瞬时毛刺 |
| ConsecutiveAlarmEvaluations | Alarm 连续次数 | 不建议低于 Warning 次数 |
| ConsecutiveRecoveryEvaluations | 恢复连续次数 | 防止状态抖动 |
| SourceDiversityBonus | 每增加一个独立来源的奖励 | 应保持有限 |
| MaximumSourceDiversityBonus | 多样性总奖励上限 | 默认 0.15 |
| Sources | 来源权重覆盖 | 基础配置保持空数组 |

### 9.2 来源策略覆盖

现场确需调整来源权重时，应在环境配置中完整提供，例如：

```json
{
  "AnomalyFusion": {
    "Sources": [
      {
        "Source": "ISOLATION_FOREST",
        "Weight": 0.85,
        "DefaultConfidence": 0.75
      }
    ]
  }
}
```

修改权重必须经过离线回放、影子观察和审批。不要用提高权重替代模型准确性修复。

## 10. API

### 10.1 状态

```http
GET /api/anomaly/fusion/status
```

返回：

- Fusion 状态：TrackedAssets、ActiveEvidence、EvidenceAccepted、Recovered、Expired、Dropped、EvictedAssets、状态迁移数；
- Ingress 状态：Capacity、Written、Read、Pending、Dropped。

守恒关系：

```text
Pending = max(0, Written - Dropped - Read)
```

### 10.2 资产列表

```http
GET /api/anomaly/fusion/assets?minimumStatus=Warning&maxCount=200
```

`minimumStatus` 支持 Normal、Observe、Warning、Alarm。

### 10.3 单资产

```http
GET /api/anomaly/fusion/assets/{assetId}
```

不存在或已淘汰返回 404。

### 10.4 LoadTest 专用入口

```http
POST /api/anomaly/fusion/load/plc-lifecycle
```

仅用于自动化验证真实 EventBus Bridge，生产环境返回 404。

## 11. 监控与告警

必须持续监控：

- `Ingress.Pending`；
- `Ingress.Dropped`；
- `Fusion.EvidenceDropped`；
- `TrackedAssets`；
- `ActiveEvidence`；
- `EvidenceExpired`；
- `EvictedAssets`；
- Warning/Alarm/Recovery 转换数量；
- Host RSS、GC 和日志异常。

建议告警：

```text
Ingress.Dropped > 0
Pending 长时间接近 ChannelCapacity
TrackedAssets 长期只增不减
ActiveEvidence 在生产停机后仍不下降
EvidenceDropped 持续增长
```

## 12. 上线流程

```text
Enabled=false
→ 测试环境开启
→ 验证 PLC 和 Cycle Bridge
→ 观察 Written/Read/Pending/Dropped
→ 使用只读页面展示，不触发控制
→ 调整来源权重和门槛
→ 运行高基数、10 分钟和一小时 Soak
→ 审批配置版本
→ 小范围现场启用
→ 观察误报、漏报和资源趋势
→ 扩大范围
```

回退只需将 `AnomalyFusion:Enabled=false` 并重启 Host。原规则、ML、同群和周期模型可继续独立运行。

## 13. 故障排查

### 13.1 有 Evidence 写入但资产不存在

检查：

- AssetId、EvidenceId、Source 是否为空；
- MaximumTrackedAssets 是否达到上限；
- Channel Dropped 是否增长；
- Evidence 是否已过期；
- Bridge 是否已启动。

### 13.2 单来源进入 Alarm

默认不会发生。检查：

- MinimumIndependentSourcesForAlarm 是否被改为 1；
- 多条 Evidence 是否实际使用了不同 Source；
- 环境变量覆盖是否正确。

### 13.3 状态不能恢复

检查：

- PLC 恢复事件是否使用相同 AnomalyId；
- 活动 Evidence 是否来自其他来源；
- RecoveryThreshold 和 ConsecutiveRecoveryEvaluations；
- 维护后台服务是否运行；
- Cycle Evidence TTL 是否合理。

### 13.4 内存或资产数持续增长

检查：

- EvidenceRetentionSeconds；
- InactiveStateRetentionSeconds；
- 上游是否持续发送新的 EvidenceId；
- EvictedAssets 是否增长；
- TrackedAssets 和 ActiveEvidence 是否在负载结束后排空；
- 不要仅凭一次 RSS 峰值判定泄漏，应同时核对托管存活内存和内部状态。

## 14. 变更和审计要求

以下变更必须留痕并重新测试：

- 阈值和连续评估次数；
- 最少独立来源数；
- Source 权重和默认置信度；
- TTL 和容量；
- PLC/Cycle 来源映射；
- 自动控制或报警桥接范围。

任何将 Fusion 结果接入自动停止或调度决策的改动，都属于新的安全阶段，不在 v3.3 交付范围内。
