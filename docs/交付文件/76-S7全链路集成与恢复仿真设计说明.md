# S7 全链路集成与恢复仿真设计说明

## 1. 目标

Simulation & Verification S7 用于验证 S2～S6 虚拟能力在同一 S1 `SimulationStateStore` 中组成一条确定性运输任务链，并验证中断、Checkpoint、状态恢复和 Replay 后仍满足一致性与 exactly-once 约束。

S7 不是新的生产控制链。它只组合：

- S2 `VirtualPlcRuntime`
- S3 `VirtualRgvRuntime`
- S4 `VirtualTrafficRuntime`
- S5 `VirtualExternalRuntime`
- S6 `VirtualHealthRuntime`

## 2. 任务生命周期

S7 的 `VirtualIntegrationMission` 状态为：

```text
Defined -> Dispatched -> Moving -> Completed -> Acknowledged
```

典型数据流：

```text
Scenario DSL
  -> integration.mission.define
  -> Virtual PLC / RGV / Traffic / External / Health 资源定义
  -> integration.mission.dispatch
  -> PLC request flag + RGV load/route + traffic reservation
  -> integration.mission.advance
  -> RGV movement + passed reservation release
  -> destination + unload + completion flag
  -> integration.mission.ack
  -> S5 idempotent external acknowledgement
  -> S6 CensoredNoFailure outcome
  -> PLC ack flag
```

重复 `mission.ack` 必须复用同一 IdempotencyKey，不得新增第二条成功 External Request，也不得新增第二条 Health Outcome。

## 3. 一致性判定

`VirtualIntegrationRuntime.GetConsistency` 在 Mission 已 Acknowledged 时验证：

1. 车辆位于目标节点；
2. 车辆已卸载；
3. 当前车辆没有残留 Reservation / Waiting；
4. External Request 恰好一条且成功；
5. PLC request/completed/ack 三个仿真标志一致；
6. `CensoredNoFailure` Outcome 恰好一条；
7. 没有该车辆的活动 Deadlock。

全部满足才返回 `IsConsistent=true`。

## 4. Checkpoint 与恢复

S7 所有 Mission 与 S2～S6 子系统状态均进入共享 S1 `SimulationStateStore`，因此正式 `SimulationCheckpoint` 覆盖完整集成状态。

恢复验证包含两类：

- `StateJson`：使用 canonical JSON 恢复新的 `SimulationStateStore`，继续执行后最终 JSON/Hash 必须一致；
- `SimulationCheckpoint`：在 Timeline 中途创建 Checkpoint，新建 Session 继续执行，最终 `FinalStateHash`、`EvidenceHash` 和 Assertion 结果必须与不中断运行一致。

同时使用 `ReplayTwiceAsync` 验证相同 Scenario/Seed 在重放时状态与 Evidence 等价。

## 5. DSL

### Actions

- `integration.mission.define`
- `integration.mission.dispatch`
- `integration.mission.advance`
- `integration.mission.ack`

### Assertions

- `integration.mission.state`
- `integration.mission.consistent`
- `integration.external.exactly-once`

## 6. Host 只读检查

路由：

```text
GET /api/simulation/virtual-integration/runs/{runId}/status
GET /api/simulation/virtual-integration/runs/{runId}/missions
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}
GET /api/simulation/virtual-integration/runs/{runId}/missions/{missionId}/consistency
GET /api/simulation/virtual-integration/runs/{runId}/audit?take=100
```

Host 只允许读取活动 Run 的 Checkpoint 快照，不提供 Mission 调度、运动、Ack、PLC 写、路权释放、Fault 注入或生产控制入口。

## 8. 安全边界

S7 Runtime 明确禁止：

- 真实 `HttpClient`、SQL Provider、SqlSugar、Socket/TCP/UDP；
- 真实 PLC/S7/Snap7 客户端；
- `CommandBus`、`TaskScheduler`、`TaskOrchestrator`、`DeviceManager`；
- `UnifiedTransportDispatchEngine`、`TransportTrafficCoordinator`、生产 Reservation Manager；
- `IAssetFailureForecastService` 或真实 ONNX `InferenceSession`；
- `DateTime.Now/UtcNow`、`Task.Delay`、`Thread.Sleep`、`Random.Shared` 参与确定性 Runtime。

Production 和未批准环境继续通过 `SimulationBoundaryGuard` 返回 404。

## 9. 验收边界

S7 证明的是仓库级确定性集成恢复能力，不等价于：

- 真实进程/主机重启恢复；
- HIL；
- 实车、真实 PLC、真实 MES/SQL/网络联调；
- 机械安全、功能安全或正式投产验收。

现场恢复与安全控制仍必须独立验收。
