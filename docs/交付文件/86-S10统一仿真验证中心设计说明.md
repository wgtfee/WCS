# S10 统一仿真与验证中心设计说明

## 1. 阶段定位

S10 是 `Simulation & Verification v1.0` 的最终软件阶段，目标是把 S0～S9 已交付的治理、场景、虚拟设备、交通、外部故障、健康/RUL、集成恢复、容量长稳和 HIL 验收边界集中到一个统一只读页面。

S10 不新增调度控制算法，不建立“第十三阶段”，也不通过桌面页面执行真实 PLC/RGV 操作。统一页面是验证信息入口，不是生产控制台，也不是现场 HIL 执行器。

当前 S10 使用堆叠分支：

```text
feature/simulation-s9-real-hil-trial
  -> feature/simulation-s10-unified-console
```

原因是 S9 软件 Head 已冻结并通过软件门禁，但真实 HIL、协议、机械安全和 Site Acceptance 尚未取得现场证据，PR #42 仍必须保持 Draft。S10 依赖 S9 的只读 HIL 状态契约，因此先基于 S9 软件 Head 开发；S9 后续合入后，S10 PR 再改为面向 `develop`。

## 2. 核心原则

1. **只读**：S10 Host 仅提供 `GET /api/simulation/verification/overview`。
2. **Production fail-closed**：Production 无条件返回 404。
3. **环境分区**：
   - Simulation / SimulationLoadTest 仅显示 S0～S8 仿真检查能力；
   - HIL / TrialRun 仅显示 S9 HIL 检查能力；
   - S10 自身统一页面在任一受控环境可用。
4. **不伪造现场状态**：默认并持续返回：

```text
RealHilExecuted=false
ProtocolValidated=false
MechanicalSafetyAccepted=false
SiteAccepted=false
```

5. **没有远程控制入口**：`RemoteControlAllowed=false`。
6. **不替代既有阶段 API**：S10 只提供能力目录和安全边界；详细运行数据仍由 S0～S9 原有只读 API 负责。

## 3. Host 统一概览 API

```text
GET /api/simulation/verification/overview
```

访问判定：

```text
Environment != Production
AND (
  SimulationBoundaryGuard.Allowed
  OR HilEnvironmentBoundaryGuard.Allowed
)
```

返回主要字段：

- `Stage=S10`；
- `Environment`；
- `ReadOnly=true`；
- `RemoteControlAllowed=false`；
- `SimulationInspectionAvailable`；
- `HilInspectionAvailable`；
- 真实 HIL / Protocol / Mechanical / Site 四项状态；
- `RealHilEvidenceRequiredForCompletion=true`；
- S0～S10 的有序能力矩阵。

每个阶段包含：

- 阶段编号和名称；
- 能力摘要；
- 原有 API 前缀；
- 当前环境是否可用；
- 是否需要 RunId；
- 是否要求真实硬件；
- 只读与安全边界说明。

## 4. Desktop 页面

新增：

```text
src/Wcs.Desktop/Services/SimulationVerificationApiService.cs
src/Wcs.Desktop/ViewModels/SimulationVerificationViewModel.cs
src/Wcs.Desktop/Views/SimulationVerificationView.axaml
src/Wcs.Desktop/Views/SimulationVerificationView.axaml.cs
```

默认菜单新增：

```text
统一仿真验证中心 -> /SimulationVerification
```

页面区域：

1. 标题、状态和刷新；
2. 明确的安全边界横幅；
3. 环境、页面模式、Simulation/HIL 可用性、可用阶段数、真实 HIL 状态；
4. S0～S10 阶段能力矩阵；
5. 选中阶段的能力、API 前缀和安全说明。

页面不包含：

- 场景执行按钮；
- Fault 注入按钮；
- PLC 写入；
- RGV 移动；
- 路权/预约/死锁处置；
- HIL Arm/Begin/Abort/Recover；
- Protocol/Mechanical/Site Acceptance 写入。

S10 软件完成要求：

- 统一页面和 API 功能完成；
- Production/非批准环境 fail-closed；
- 页面与 API 均无控制写入口；
- 专项契约、Desktop 构建和累计 exact-head 回归全部成功；
- Evidence Artifact 与 Digest 核实；
- 文档 86～88 和总索引同步。

S10 软件完成不等于 S9 真实现场验收完成。最终项目现场完成仍依赖真实 self-hosted HIL、Protocol、Mechanical Safety 和 Site Acceptance 证据。
