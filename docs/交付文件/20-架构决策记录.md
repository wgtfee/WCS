# EMS/RGV 架构决策记录

## ADR-001 统一调度、分离执行

### 决策

EMS 和 RGV 在 WCS 层使用统一车辆、任务、路径、路权、执行和命令模型；厂商协议保留在 Driver/Adapter 层。

### 原因

- 复用调度、交通、恢复和监控能力；
- 避免每种设备复制一套业务引擎；
- 现场协议变化不影响核心调度。

### 后果

新增设备类型必须实现统一 Driver 和映射，不得把协议逻辑带入 DispatchEngine。

## ADR-002 单一事实源位于运行时内存

### 决策

实时车辆、执行和路权以内存服务为运行时权威，SQL 用于恢复和审计，PLC 用于真实反馈和对账。

### 原因

实时调度需要低延迟和明确并发控制；数据库轮询不能替代内存状态机。

### 后果

必须有持久化、版本、恢复和三方一致性巡检。

## ADR-003 先预留后下发

### 决策

车辆进入执行和 PLC Move 命令下发前，必须完成路径与交通资源预留。

### 原因

避免车辆已经运动后才发现资源冲突。

### 后果

车辆 CAS 失败时必须释放预留；AdmissionPolicy 不得绕过 ReservationManager。

## ADR-004 物理占用高于软件租约

### 决策

`OccupancyConfirmed=true` 时，TTL、取消、死锁解除和任务终态都不能直接释放资源。

### 原因

软件状态可能过期，但车辆仍真实占用区段。

### 后果

需要 PLC/传感器清场反馈和延迟释放后台任务。

## ADR-005 RequestId、CommandSequence 和 OperationId 分层幂等

### 决策

- RequestId：业务任务幂等；
- CommandId/Sequence：PLC 命令相关性；
- OperationId：危险操作一次性执行。

### 原因

不同层的重试和重复风险不同，不能使用同一个标识替代全部语义。

## ADR-006 PLC 无连续位置时使用可信节点

### 决策

位置由最后确认节点和已确认物理区段组成，不根据时间推算真实位置。

### 原因

时间推算无法处理停车、故障、打滑、人工干预和通信延迟。

### 后果

现场必须提供到站、读码、RFID、编码器或控制器回执之一。

## ADR-007 运动命令失败默认不自动重试

### 决策

Move、Load、Unload 失败或超时后进入人工确认；Stop 可在审批后补偿。

### 原因

重复运动可能造成设备冲突或货物状态错误。

### 后果

命令持久化和 PLC 当前序号对账是恢复前提。

## ADR-008 生产队列和统一派单分层

### 决策

生产队列负责任务优先级和站点拥堵；统一派单负责车辆、路径和路权。

### 原因

避免生产策略污染底层安全调度，也便于复用派单内核。

## ADR-009 交通扩展采用 AdmissionPolicy

### 决策

单轨、电梯、门禁和工艺禁行通过 `ITransportDispatchAdmissionPolicy` 扩展。

### 原因

减少修改统一派单主流程的风险。

## ADR-010 配置使用乐观锁

### 决策

运行配置、生产整定和点位映射使用 ExpectedVersion。

### 原因

防止多人或多实例覆盖最新配置。

### 后果

版本冲突必须重新读取和审批，不能强制覆盖。

## ADR-011 高风险操作双人审批

### 决策

PLC 写、命令补偿、恢复冲突、配置回滚等使用申请人和独立审批人。

### 原因

降低误操作和账号滥用风险，满足审计要求。

## ADR-012 查询接口必须无副作用

### 决策

为生产队列提供 `PeekQueue()` 纯快照，页面、API 和仿真不得通过查询刷新优先级或清理任务。

### 原因

查询导致状态变化会使监控行为影响调度结果，破坏可复现性。

## ADR-013 SQL 专用表与 Journal 并存

### 决策

高频、强约束活动状态使用专用表；趋势、报告、快照和仿真使用分类 Journal。

### 原因

兼顾查询约束和扩展速度。

### 后果

Journal 枚举值只能追加，载荷需保持兼容。

## ADR-014 可观测性不阻塞控制闭环

### 决策

Trace、Metrics、健康和报告失败只能降级记录，不能中断派单或 PLC 命令。

### 原因

监控系统不可用不应造成设备控制停摆。

## ADR-015 恢复默认不自动续跑

### 决策

启动后执行 SQL、内存、PLC 三方对账，不确定任务进入 Suspended/人工恢复。

### 原因

自动续跑可能重复命令或错误释放物理占用。

## ADR-016 逻辑备份不替代数据库备份

### 决策

逻辑备份用于配置、状态和诊断证据；SQL Server 原生备份用于数据库灾难恢复。

### 原因

逻辑 JSON 无法完整替代事务日志和数据库一致性恢复。

## ADR-017 恢复准备只导入配置快照

### 决策

从备份恢复时不自动写回活动任务、路权、位置、点位和命令。

### 原因

历史状态可能与现场物理状态不一致。

## ADR-018 仿真必须隔离且确定性

### 决策

仿真使用状态副本和固定 Seed，不调用生产派单、执行或 PLC 接口。

### 原因

确保安全、公平比较和结果可复算。

## ADR-019 生产 Host 上限制仿真规模

### 决策

通过 SafeTransportSimulationService 限制任务数、车辆数、时间桶、容量网格、总估算量和并发。

### 原因

防止合法但超大请求耗尽 CPU 和内存。

## ADR-020 当前采用单活调度

### 决策

主备能力完全验证前，生产只允许一个实例写同一 EMS/RGV 控制器。

### 原因

双活会造成重复派单、重复命令和路权分裂。

### 后果

蓝绿发布也必须 Drain 并关闭非活动实例后台写能力。

## ADR-021 控制层不使用生成式 AI

### 决策

车辆选择、安全准入、路权、命令和恢复均使用确定性规则和状态机。

### 原因

工业控制需要可验证、可解释、离线可运行和稳定响应。

### 后果

AI 可用于非控制型知识查询或离线分析，但不得直接下发设备命令。

## ADR 维护规则

1. 新增重大架构选择时追加 ADR，不覆盖历史原因。
2. 决策被替代时标记 Superseded，并引用新 ADR。
3. ADR 变化必须同步总体设计、详细设计、测试和运维文档。
4. 涉及物理安全的 ADR 必须有自动化测试和现场验收项。
