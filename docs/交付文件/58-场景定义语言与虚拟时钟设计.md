# 场景定义语言与虚拟时钟设计

## 1. 定位

本文定义 WCS Simulation & Verification v1.0 的 S1 场景引擎。S1 建立在 S0 的 Manifest、版本、Seed、SHA-256、环境白名单和 Evidence 治理之上，不创建第二套设备模拟器，也不接入真实 PLC、任务、路权、车辆选择或派单控制。

## 2. 数据流

```text
S0 已登记 ScenarioId + Version + Seed + ContentSha256
→ 提交相同内容的严格 JSON 场景文档
→ 校验内容 SHA 与治理版本一致
→ 解析 DSL schema v1
→ 构建确定性 Timeline
→ Virtual Clock 推进
→ Action / Assertion Handler
→ State Store / Evidence / Assertion Outcome
→ Checkpoint / Replay Comparison
```

## 3. 场景 DSL v1

根对象字段：

- `SchemaVersion`：当前固定为 1；
- `ScenarioId`、`Version`、`Seed`：必须与 S0 已登记 Manifest 完全一致；
- `StartTimeUtc`：固定虚拟起点，不使用当前系统时间；
- `DurationMilliseconds`：1 毫秒至 365 天；
- `StopOnAssertionFailure`：断言失败是否立即终止；
- `Actions`：动作数组；
- `Assertions`：断言数组。

JSON 使用严格解析：区分字段大小写、禁止注释、禁止尾逗号、拒绝未知字段。

## 4. Timeline 排序

所有 Action 与 Assertion 合并为统一 Timeline，排序规则固定为：

```text
AtMilliseconds
→ ItemType（Action 在 Assertion 前）
→ Order
→ Id（Ordinal）
```

相同场景版本、相同 Seed 和相同输入不得因线程调度、机器速度或 SpeedFactor 改变执行顺序。

## 5. 内置动作

| Kind | 说明 | 控制边界 |
|---|---|---|
| `state.set` | 设置隔离状态值 | 仅内存状态 |
| `state.increment` | Int64 计数器增量 | 仅内存状态 |
| `event.emit` | 生成仿真 Evidence | 不发布生产 EventBus 控制事件 |

S2 以后新增 PLC、车辆、区段等 Handler 时，仍必须经过统一 Handler 注册表和 S0/S1 边界，不得在 DSL 内直接调用生产写接口。

## 6. 内置断言

- `state.equals`；
- `state.exists`；
- `state.notExists`。

断言输出 AssertionId、Expected、Actual、Message 和虚拟时间。断言失败可按场景配置立即失败，也可继续收集后续结果。

## 7. 虚拟时钟

`DeterministicSimulationClock` 支持：

- Pause；
- Resume；
- 单步推进；
- 向前推进至指定 Offset；
- SpeedFactor；
- 跳至场景结束时间。

SpeedFactor 只影响展示和未来运行策略，不改变 Timeline、状态或 Evidence。S1 核心禁止 `Task.Delay`、`DateTime.Now/UtcNow` 作为场景时间源和 `Random.Shared`。

## 8. 状态边界

默认：

| 参数 | Simulation | SimulationLoadTest | 硬上限 |
|---|---:|---:|---:|
| MaximumTimelineItems | 100,000 | 500,000 | 1,000,000 |
| MaximumStateEntries | 10,000 | 50,000 | 1,000,000 |
| MaximumStateValueCharacters | 4,096 | 4,096 | 1,048,576 |
| MaximumCheckpointBytes | 16 MB | 64 MB | 256 MB |
| MaximumSpeedFactor | 1,000 | 10,000 | 100,000 |
| MaximumRuns | 1,000 | 5,000 | 100,000 |

所有集合有界。达到容量后拒绝新内容，不静默丢弃。

## 9. Checkpoint

Checkpoint 包含：

- ScenarioId、Version、ManifestHash、Seed；
- 当前虚拟 Offset；
- 下一 Timeline Index；
- 确定性随机状态；
- Canonical State JSON；
- Evidence；
- Assertion Outcomes；
- CheckpointHash。

恢复时重新计算 SHA-256，并校验场景身份。内容被修改、跨版本使用或 Seed 不一致均拒绝。

## 10. Replay

同一场景分别以 SpeedFactor=1 和 SpeedFactor=100 执行，比较：

- EvidenceHash；
- FinalStateHash；
- Assertion Outcomes。

三者全部一致才判定 `Equivalent=true`。

## 11. Host API

```text
GET  /api/simulation/scenarios/runs
GET  /api/simulation/scenarios/runs/{runId}
POST /api/simulation/scenarios/runs
POST /api/simulation/scenarios/runs/{runId}/step
POST /api/simulation/scenarios/runs/{runId}/advance
POST /api/simulation/scenarios/runs/{runId}/run
POST /api/simulation/scenarios/runs/{runId}/pause
POST /api/simulation/scenarios/runs/{runId}/resume
POST /api/simulation/scenarios/runs/{runId}/speed
POST /api/simulation/scenarios/runs/{runId}/cancel
GET  /api/simulation/scenarios/runs/{runId}/checkpoint
POST /api/simulation/scenarios/replay
```

API 只在 S0 双开关开启且 Environment 为 Simulation 或 SimulationLoadTest 时可见，其他环境统一 404。

## 12. 当前限制

S1 不包含虚拟 PLC 点位/DB 块、RGV 运动、区段占用、交通冲突、MES/SQL 故障、异常退化数据和 HIL。这些分别属于 S2～S9。
