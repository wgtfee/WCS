# 故障概率与剩余寿命预测测试交付报告

## 1. 范围

本报告覆盖 AnomalyEngine v3.9 的历史数据门槛、固定特征契约、已审批模型 Manifest、本地 ONNX Runtime、故障概率和 RUL 区间、SQL 幂等、Outcome Journal、回测指标、模型切换、Host 重启恢复、坏模型隔离及完整回归。

## 2. 测试原则

- CI 现场生成微型 ONNX，不把模型文件提交到仓库；
- 不使用远程下载、云端推理或 GPU；
- 不使用健康分线性外推替代模型；
- 数据不足必须无预测；
- 不跳过 SHA、训练证据、特征顺序、维度、输出数学约束、native 链接、吞吐或内存检查；
- Forecast 专项不得改变 v1～v3.8 的既有断言；
- 最终验收只认 latest exact head 的完整矩阵。

## 3. Core 契约测试

`AssetFailureForecastTests` 覆盖：

1. 历史点不足时不构建特征；
2. 历史跨度不足时不构建特征；
3. 14 维特征名称和顺序确定；
4. 退化斜率、Delta、样本数和跨度计算确定；
5. TrainingAssetCount 门槛；
6. FailureEventCount 门槛；
7. CensoredRecordCount 门槛；
8. AUC、Brier 和区间覆盖门槛；
9. ManifestHash 确定；
10. ForecastId 确定；
11. 24/72/168 小时概率必须单调；
12. RUL Lower/Median/Upper 必须有序且有界。

### 4.2 Forecast Runtime

工作流：`WCS Asset Failure Forecast Runtime`

CI 模型：

```text
Input : features float32 [1,14]
Output: forecast float32 [1,6]
Values: 0.10, 0.30, 0.60, 40, 72, 120
```

门槛：

- ONNX Checker；
- 本地文件和 SHA-256；
- 训练资产、真实故障、删失样本与验证指标；
- CPU native Runtime；
- 六个输出精确；
- 20,000 次推理；
- 吞吐 > 1,000 次/秒；
- RSS 增长 ≤ 256 MB；
- 错误 Hash 拒绝；
- 错误 Shape 拒绝；
- 错误 FeatureOrder 拒绝；
- 无真实故障证据的模型拒绝；
- Store/Runtime 重建后输出一致；
- Linux x64 native 依赖无 `not found`；
- 控制写入为 0。

开发期成功证据：

### 4.3 Forecast Host + SQL

工作流：`WCS Asset Failure Forecast`

精确门槛：

- 本地 v1、v2 两个已审批模型；
- Host 启动加载 v1；
- 3 点历史返回 `InsufficientData`，Forecast=0；
- 48 点、47 小时历史允许预测；
- v1 输出 P24=0.10、P72=0.30、P168=0.60、RUL=40/72/120；
- 同窗口重复评估 ForecastId 相同，SQL 只插入 1 行；
- 同 Outcome 重复提交只插入 1 行；
- v1 SQL 精确 Model=1、Forecast=1、Outcome=1；
- ObservedFailure 在 72 小时发生时，RUL MAE=0、IntervalCoverage=1、24h Brier≈0.01；
- 激活 v2 后输出 P24=0.20、P72=0.40、P168=0.70、RUL=20/48/96；
- v2 SQL 精确 Model=2、Forecast=2；
- Host 重启保持 v2；
- 坏 Hash 时 Host 健康、Forecast 状态 Failed 且不加载模型；
- 恢复正确 active.json 后 v2 再次加载；
- 最终 SQL 精确 Model=2、Forecast=2、Outcome=1、PlcWrite=0；
- Forecast Core/Infrastructure/Controller 不依赖 PLC、任务或交通控制命名空间；
- Host 无 OOM、AccessViolation 或 native 崩溃。

开发期首个 Host 运行已通过所有业务断言，只因最终证据脚本引用不存在的控制审计表而失败。后续版本改为真实 `Wcs_PlcWriteLog=0` 与源码依赖门禁，不降低 Forecast 业务门槛。
