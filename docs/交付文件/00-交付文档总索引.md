## 7. 文档与治理规则

1. 代码、配置、数据库、API、阈值、模型、场景、数据集、Manifest 或控制边界变化必须同步文档。
2. 真实点位、拓扑、资产、维修规则、MES 地址、SQL ConnectionString、密钥、模型、许可证和未脱敏数据不写入通用仓库。
3. 同一图、规则、模型或场景 Version 不得对应不同 Hash、FeatureSchema、Seed 或审批元数据。
4. 已签署验收记录不得覆盖，必须新增版本。
5. LoadTest、MlLoadTest、ForecastLoadTest、Simulation 和 SimulationLoadTest 接口不得在 Production 开放。
6. Governance、复核、反馈、模型激活、Outcome 和场景审批写操作必须保存 Actor、原因和时间。
7. 健康、根因、维修、Forecast 或仿真结果不得直接接入自动控制；联动必须独立安全立项。
8. 每阶段首轮全绿后必须回填 Artifact/Digest，并对文档 Evidence Head 再跑同等完整矩阵。
9. Full Regression 必须校验 exact Head、固定 child 数量、所有 child `completed/success`、`allSuccess=true` 和 PR Head 未漂移。
10. 仿真死锁处置仅允许修改仿真会话状态，不得映射为生产任务取消、车辆动作、路线修改或现场路权释放。
11. S5 外部故障、重试、Circuit 与 Idempotency 仅为 Simulation State；不得保存真实凭据、发起真实 HTTP/SQL/Socket 请求或替代现场联调。
12. S6 Forecast Oracle 仅允许作为仿真期望值；不得伪装成批准模型 Forecast、写入生产 Forecast SQL、触发维修/停机或替代真实模型验证。
13. S7 Integration Mission 与恢复状态仅为 Simulation State；不得映射生产任务、车辆、路权、PLC 写或真实 External Ack。
14. S7 Checkpoint/StateJson 恢复只证明仓库级 deterministic recovery，不替代真实进程/主机重启、HIL 和现场恢复验收。
15. S8 8h/24h 只代表 virtual-time endurance；不得描述为真实 8/24 小时 HIL。
16. S8 `ReadyToEnterS9` 只表示 software-side prerequisites 满足；`RealHilExecuted`、`MechanicalSafetyAccepted`、`SiteAccepted` 在 S8 必须保持 false。
17. S8 Capacity preflight 必须在创建 S2～S7 虚拟资源之前完成；超限必须 fail-closed，禁止半初始化资源。
