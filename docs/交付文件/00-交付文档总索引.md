## 8. 文档与治理规则

1. 代码、配置、数据库、API、阈值、模型、场景、数据集、Manifest 或控制边界变化必须同步文档。
2. 真实点位、拓扑、资产、维修规则、MES 地址、SQL ConnectionString、密钥、模型、许可证和未脱敏数据不写入通用仓库。
3. 同一图、规则、模型或场景 Version 不得对应不同 Hash、FeatureSchema、Seed 或审批元数据。
4. 已签署验收记录不得覆盖，必须新增版本。
5. LoadTest、MlLoadTest、ForecastLoadTest、Simulation、SimulationLoadTest、HIL 与 TrialRun 接口不得在 Production 开放。
6. Governance、复核、反馈、模型激活、Outcome、场景审批和 HIL Acceptance 写操作必须保存 Actor、原因和时间。
7. 健康、根因、维修、Forecast 或仿真结果不得直接接入自动控制；联动必须独立安全立项。
8. Full Regression 必须校验 exact Head、固定 child 数量、所有 child `completed/success`、`allSuccess=true` 和 PR Head 未漂移。
9. S8 8h/24h 只代表 virtual-time endurance；不得描述为真实 8/24 小时 HIL。
10. S8 `ReadyToEnterS9` 只表示 software-side prerequisites；RealHilExecuted/MechanicalSafetyAccepted/SiteAccepted 在 S8 必须 false。
11. S9 GitHub hosted CI 不得连接真实设备，也不得产生 RealHilExecuted=true。
12. S9 Real HIL 必须使用 manual `[self-hosted,wcs-hil]` Gate、批准 Bench、维护窗口、双人安全审批和 exact Software Head。
13. S9 每个 Trial Step 必须具有 `RealHardwareObserved=true` 的真实证据和 SHA-256。
14. S9 Abort 后必须进入安全 Recovery；Recovered 为终态，重试必须新建 Session 并引用 `RecoveryFromSessionId`。
15. S9 `ProtocolValidated`、`MechanicalSafetyAccepted`、`SiteAccepted` 不允许由 Simulation、Mock、hosted CI 或默认配置自动置 true。
16. 真实 HIL Evidence Gate 未成功前，PR #42 必须保持 Draft，不得合并为 S9 Completed。
