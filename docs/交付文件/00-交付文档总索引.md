## 8. 文档与治理规则

1. 代码、配置、数据库、API、阈值、模型、特征、数据集、场景、策略或控制边界变化必须同步文档。
2. 真实点位、拓扑、资产、维修规则、MES 地址、SQL ConnectionString、密钥、模型、许可证和未脱敏数据不写入通用仓库。
3. 相同 Version 不得对应不同 Hash、FeatureSchema、Dataset、Seed、Policy 或审批元数据。
4. 已签署验收、Evidence 和 Audit Journal 不得覆盖，只能追加版本或 Journal。
5. Production 默认 fail-closed；IndustrialIntelligence 未经明确批准最高 L0。
6. P0 允许的最高软件自动化等级为 L1；L2/L3 必须在后续独立阶段重新治理和验收。
7. L4 安全关键控制永久禁止 AI 直接执行。
8. AI/SQL/Model/Feature/Decision/Optimization 故障不得阻塞 PLC Polling、TaskScheduler、TaskOrchestrator、DeviceManager 和交通控制。
9. P0 Host 只允许只读 Status/Capabilities，不得出现 POST/PUT/PATCH/DELETE 控制入口。
10. P0 `Wcs.IndustrialIntelligence` 不得依赖 PLC、CommandBus、TaskScheduler、TaskOrchestrator、DeviceManager、Dispatch、Traffic 或 RouteReservation mutation path。
11. 所有队列、窗口、模型、查询、批次、缓存和保留期必须有界。
12. Full Regression 必须校验 exact Head、固定 child 数量、所有 child `completed/success`、`allSuccess=true` 和 PR Head 未漂移。
13. Simulation、Mock、手写 JSON、hosted CI 和虚拟 8h/24h 不得描述为真实 HIL 或现场安全验收。
14. 后续模型必须先 Validate、Candidate、Shadow，再进入 Champion/Challenger；必须保留 Fallback/Quarantine/Rollback。
15. Dataset 必须 Point-in-Time 正确并保存 DatasetHash、FeatureSchemaHash 和标签版本。
16. Decision Proposal 必须记录 FeatureSnapshot、ModelVersion、硬约束结果和 Evidence。
17. 自动化等级提升必须有独立风险分析、KillSwitch、Rate/Budget Limit、CircuitBreaker、回滚和真实现场验收。
