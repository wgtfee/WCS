## 3. 核心断言

1. 未知 JSON 字段、注释、尾逗号和大小写错误被拒绝；
2. ScenarioId、Version、Seed 必须与 S0 Manifest 一致；
3. Timeline 按时间、类型、Order、Id 稳定排序；
4. 同时刻 Action 在 Assertion 前执行；
5. Pause 后不自动推进；
6. Step 仅执行一个 Timeline Item；
7. Advance 只向前推进；
8. SpeedFactor 不改变结果；
9. 相同 Seed 的随机序列一致；
10. Checkpoint 保存随机状态并可连续恢复；
11. Checkpoint 篡改、跨版本和错误 ManifestHash 被拒绝；
12. 10,000 Timeline Item 无丢失、无重复；
13. State、Timeline、Checkpoint 和 RunRegistry 容量有界；
14. 已登记内容 SHA 与执行内容不一致时拒绝；
15. Production、Development 和双开关缺失时 API 返回 404；
16. 取消后 Run 状态为 Cancelled，不能继续执行；
17. Replay 的 EvidenceHash、FinalStateHash 和 Assertions 全部一致；
18. S1 不包含 PLC 写、任务取消、路权释放、车辆选择和派单依赖。

## 4. Host API 测试链路

```text
S0 Validate/Register
→ S1 Create Run（Paused）
→ Step
→ Checkpoint
→ Resume
→ Run To Completion
→ FinalStateHash / EvidenceHash
→ Replay Twice
→ Equivalent=true
```

同时测试：未登记版本 404、错误 Base64 400、内容 SHA 不一致 400、未知 Run 404、终态重复操作 409。

- 编译或契约失败必须修实现；
- 不删除测试、不降低容量和安全门槛；
- 不使用 `continue-on-error`；
- Runner/SQL/网络波动必须读取 Job Logs 和 Artifact 后判断；
- 新提交产生新 Head 后，旧 Head 结果全部失效；
- 文档 Evidence 提交后必须再跑第二轮 29 项。
